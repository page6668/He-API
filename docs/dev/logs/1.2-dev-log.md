## 1. Implementation Summary

Story 1.2 delivers the project's first CI/CD baseline on GitHub Actions: PR gating
(`lint` / `test` / `build-images` PR validation, 6 required status checks) and a
`workflow_run`-chained `deploy-staging` GitOps entry that runs in a graceful-skip
configuration until Story 1.3 / 1.4 wire real ACR + ArgoCD.

All Architect Round-1/2/3 fixes (C1, M1, M2, M3, M-new-1, m1, m2, m3, m-new-1,
m-new-2, L-new-1) landed verbatim in the YAML. The one tracked Low (L-new-2) —
T6 line referencing the removed `HAS_HELM_VALUES` variable name — is corrected
in the AC2 traceability + this log; no story-body edit was needed because the
runtime verification described in T6 is deferred to a real PR/merge run.

### Highlights

- **6 PR status checks** baked into branch-protection plan: `lint-ts`, `lint-go`,
  `unit-ts`, `unit-go`, `integration`, `build-image-pr`.
- **M-new-1 regression guard implemented**: `id: probe_helm` step lives after
  `actions/checkout` + `actions/download-artifact` + `Resolve image SHA`; no
  `hashFiles(` in any job-env mapping.
- **C1 GitOps loop break**: `update-helm-values` pushes with default
  `${{ secrets.GITHUB_TOKEN }}` + job-level `permissions: contents: write`. No
  custom PAT introduced.
- **workflow_run chaining** with `actions/upload-artifact@v4` (build-images) →
  `actions/download-artifact@v4` (deploy-staging, `run-id: workflow_run.id`).
- **Concurrency** declared on both workflows; PR-only cancel-in-progress on
  `build-images`, serial-on-main on `deploy-staging`.
- **golangci-lint scope** = `./apps/...` (matches `go.work` `use ./apps/api-gateway`).
- **CGO split**: `unit-go` job sets `CGO_ENABLED=1` (for `-race`); Dockerfile
  builder stage sets `ENV CGO_ENABLED=0` (distroless static binary).
- **Vitest installed in `packages/shared-types`** with a runtime-import
  placeholder (`import * as types ... expect(types).toBeDefined()`) that does
  NOT depend on any specific type export.

### Tracked low items addressed inline

- **L-new-2 (story T6 line 337 references removed `HAS_HELM_VALUES`)**: see
  AC traceability below — every deploy-staging E2E evidence row uses the new
  step-output gating expression (`steps.probe_helm.outputs.exists == 'false'`)
  instead of the stale env-name. The story body itself is left as historical
  record; QA test 1.2-UNIT-018 covers the regression statically.

> **Note on the `pnpm test` env passthrough**: vitest forks workers that
> mkdir under `$TMPDIR`. Turbo 2 defaults to *strict* env mode and strips
> non-declared vars before invoking child processes; that breaks vitest under
> a sandboxed temp dir (vitest then falls back to `/tmp` which the sandbox
> denies). Adding `globalPassThroughEnv: ["TMPDIR"]` to `turbo.json` fixes
> this without weakening turbo's caching guarantees. GitHub-hosted runners
> never hit this because `/tmp` is writable there — but the fix is correct
> in general and lets contributors reproduce CI exactly on Mac sandboxed
> environments.

### M-new-1 regression guard (most important static check)

`1.2-UNIT-018` asserts at vitest runtime:

1. `update-helm-values.steps[*]` contains `id: probe_helm` AFTER an
   `actions/checkout` step (`steps.findIndex(checkout) < steps.findIndex(probe_helm)`).
2. At least one step gates on `steps.probe_helm.outputs.exists == 'true'`.
3. **No job-level `env:` key is named `HAS_HELM_VALUES`**, AND
4. **No job-level `env:` value contains `hashFiles(`** (the original M-new-1
   footgun expression).

This test fails fast if any future PR re-introduces the timing bug Architect

## 5. T6 End-to-End Verification — deferral plan

The story's T6 task lists six runtime checks (draft-PR run, lint-red injection,
test-red injection, merge-driven workflow_run chain, cache hit, C1 regression).
These require a real GitHub Actions environment and a draft PR / merge — they
cannot run locally in this sandbox. The verification plan:

1. **Open the Story 1.2 PR** → 3 PR-triggered workflows fire (`lint`, `test`,
   `build-images`/build-image-pr) producing all 6 status checks. Append PR URL
   + screenshot of the 6 green checks here.
2. **Lint-red injection** — temp commit adding an unused Go var; verify
   `lint-go` turns red; revert. Append Run URL.
3. **Test-red injection** — temp commit with `t.Fatal("intentional")`; verify
   `unit-go` red; revert. Append Run URL.
4. **Merge** the PR → expect 2 workflow runs:
   1. `build-images` (main): `HAS_ACR='false'` path → push skipped + fallback
      summary line; `image-sha.txt` artifact uploaded; job exits 0.
   2. `deploy-staging` (workflow_run): triggers ~1 min after build-images success;
      `steps.probe_helm.outputs.exists == 'false'` path → helm-update skipped;
      `HAS_ARGOCD == 'false'` → argocd sync skipped. Job exits 0. Step summary
      contains image SHA + every gating reason.
5. **Second commit on a follow-up PR** within an hour → expect pnpm + Go build
   + buildx-gha cache hits; PR-check duration ≤ 60 s.
6. **C1 regression note (Story 1.3 follow-up)** — once Story 1.3 lands
   `values-staging.yaml`, verify the *first* real helm-values push produces no
   second deploy-staging run within 5 minutes (the GitHub Actions
   `GITHUB_TOKEN`-authored-commit suppression invariant).

> Until those evidence URLs are pasted, AC1/AC2 "runtime aspect" status is
> *pending PR open* — the static contract is fully green right now.
