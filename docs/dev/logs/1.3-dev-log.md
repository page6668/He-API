## 1. Implementation Summary

Delivers four reusable Terraform modules (`vpc` / `ack` / `acr` / `oss-state`),
two env compositions (`staging` real-apply / `prod` code-only with
`prevent_destroy`), a one-shot `bootstrap-state-backend.sh` for the OSS +
TableStore + KMS state-backend "chicken-and-egg", a minimal `api-gateway` Helm
chart that closes Story 1.2's `HAS_HELM_VALUES` probe-fallback branch, a
`kustomize`-rooted set of K8s base manifests covering 6 namespaces / RBAC /
NetworkPolicy / ResourceQuota, and a `infra-lint.yml` GitHub Actions workflow
adding 4 PR required checks (`terraform-validate (staging)`,
`terraform-validate (prod)`, `helm-lint`, `k8s-manifest-validate`).

All Architect Round-1 + Round-2 rulings are encoded:

- **Q1 (values-staging.yaml whitelist)**: only `image / service / networkPolicy /
  serviceAccount` keys; `ingress` / `autoscaling` / `resources` /
  `env`/`envFrom` are statically forbidden by 1.3-UNIT-202..206.
- **Q2 (state backend)**: OSS + TableStore (Aliyun-native), declared in
  `infra/terraform/backend.tf` with `encrypt = true` and KMS reference at
  the bucket level.
- **Q3 (Path A2)**: `var.api_server_public_access_enabled` (bool, default
  `true`) + `var.api_server_public_access_allowed_cidrs` (list(string),
  default `[]`) with `lifecycle.precondition` enforcing
  `length(allowed_cidrs) > 0` when enabled — `terraform plan` rejects the
  "公网 enable 但无 CIDR 白名单" configuration mistake.
- **Q4 + H-3 (cluster retention)**: `terraform destroy` recipe in README
  explicitly excludes ACR EE Basic / OSS state bucket / KMS key / TableStore
  lock-table from the resource cleanup; staging cluster retained until
  Story 1.4.
- **H-1 (ACR EE Basic)**: `alicloud_cr_ee_instance` (`instance_type = "Basic"`,
  `payment_type = "Subscription"`, `period = 1`, `renewal_status =
  "AutoRenewal"`); endpoint expression =
  `${alicloud_cr_ee_instance.this.name}-registry.${var.region}.cr.aliyuncs.com`.
- **M-1 (argocd ns + managed-by)**: 6 namespaces in
  `infra/k8s-base/namespace.yaml`; the 4 deferred ones (`monitoring` /
  `cert-manager` / `ingress-nginx` / `argocd`) carry
  `annotations.managed-by: story-1.4`.
- **M-2 (kustomization)**: `kustomization.yaml` references all 4 manifests
  (`namespace.yaml` / `rbac.yaml` / `network-policy.yaml` /
  `resource-quota.yaml`) — 1.3-UNIT-086 covers regression.
- **M-3 (tflint pin)**: repo-root `.tflint.hcl` pins `plugin "alicloud"
  version = "0.20.0"` with explicit `source = "github.com/terraform-linters/
  tflint-ruleset-alicloud"`.
- **M-4 (prod CIDR)**: `envs/prod/main.tf` uses `10.30.{1,2,3}.0/24` vSwitch
  CIDRs — `terraform.tfvars.example` carries them.
- **M-5 (Pod Security Restricted)**: Deployment template has all 6
  Restricted-profile fields (`runAsNonRoot:true` / `runAsUser:65532` /
  `readOnlyRootFilesystem:true` / `allowPrivilegeEscalation:false` /
  `capabilities.drop:[ALL]` / `seccompProfile.type:RuntimeDefault`).
- **L-2 (cost ¥800)**: README cost-estimate row + ¥1500 escalation gate.
- **L-3 (10 required checks)**: README "Branch protection" lists all 10
  literal check names — 6 from Story 1.2 + 4 from this Story.
- **L-4 (tfvars placeholders)**: both env `terraform.tfvars.example` files
  carry `api_server_public_access_allowed_cidrs = [...]` placeholders with
  GHA-runner / operator-workstation / office-NAT examples and the weekly
  refresh comment pointing at `api.github.com/meta`.
- **L-5 (deploy-staging double-trigger gate)**: documented in the
  Operator Hand-off section as a hard gate — second `deploy-staging` run
  within 5 minutes of the first merge → escalate to Architect Round 3
  before this Story can transition to Done.
