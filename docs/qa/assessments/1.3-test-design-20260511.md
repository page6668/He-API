### Test-Level Interpretation for IaC Stories

Story 1.3 delivers infrastructure-as-code (Terraform HCL + Helm chart + K8s manifests + a one-shot bash bootstrap + a CI workflow). There is **no business runtime code** in this story (Story 1.5 first introduces Go business logic). The test-level pyramid therefore inverts in the same way it did for Story 1.2:

| Level | Coverage Strategy |
|-------|-------------------|
| Unit | Vitest tests parsing `infra/terraform/**/*.tf`, `infra/helm/api-gateway/**/*.{yaml,tpl}`, `infra/k8s-base/*.yaml`, `scripts/infra/bootstrap-state-backend.sh`, `.github/workflows/infra-lint.yml`, `.tflint.hcl`, `.gitignore`, `README.md`. Each scenario asserts file structure / required keys / Architect Round 1 ruling encoding / regression guards (Q1-Q4, H-1, M-1…M-5, L-3, L-4). Runnable locally via `pnpm test`. HCL is treated as text+regex (matches the deliverable_bindings convention already used by SM/Architect). |
| Integration | PR-driven scenarios on `infra-lint.yml` (4 new required checks) + Story 1.2 GitOps closure regression (probe_helm sees `values-staging.yaml` → real `yq` write → no double-trigger of `deploy-staging`). Evidence = PR Run links in `docs/dev/logs/1.3-dev-log.md` T11. Not auto-runnable. |
| E2E | Single-shot Dev `terraform apply` on staging (per Architect Q4 ruling: real apply, retain cluster for Story 1.4) + `kubectl` / `helm` validation matrix + exposure-surface scan from non-whitelisted IP. Evidence = command output + screenshots in dev-log T11/T12. Not auto-runnable; cluster lifecycle tracked via `retention_status` field in dev-log. |

> **Skeleton file**: `packages/shared-types/__tests__/1.3-aliyun-vpc-k8s-cluster-terraform.test.ts` (co-located with Story 1.2 skeleton; relocate to dedicated `tests/infra` workspace in Story 1.5+ when business code lands).

> **Risk profile**: Comprehensive tier triggers `[test-design, risk-profile]` per `core-config.yaml.qa.testDesignThresholds.comprehensive.tasks`. A separate `*risk-profile 1.3` invocation produces `docs/qa/assessments/1.3-risk-{YYYYMMDD}.md`. This test-design document maps each Architect Round 1 issue (Q1-Q4 / H-1 / M-1…M-5 / L-3 / L-4 / L-5) to its regression guard scenarios in the Risk Coverage section below; risk-profile may add scenarios on top.
