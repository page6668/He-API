# Test Design: 5.3 — 限流（QPS / RPM / TPM）

2026-05-26 | Turing (QA) | Level: **Comprehensive** | Security-focus: **TRUE** | Chaos: **REQUIRED** (locked by SM Decision 8B + Epic-5 epic-level `test_design_level=comprehensive`) | Risk-profile: **NOT GENERATED IN THIS PASS** — the Story's §AC1/2/3 + Decision 8B reasoning (items a–i) already enumerate the threat surface (atomicity / cross-axis short-circuit / TPM post-deduction race / Retry-After RFC 7231 / fail-open posture / cross-pod statelessness / slog discipline / chaos / hot-path benchmark) explicitly and authoritatively; QA opts to embed those concerns DIRECTLY as `5.3-UNIT/INT/CHAOS/SEC` scenarios in this design rather than spawn a parallel `5.3-risk-*.md` artefact (precedent: Story 5.1 + Story 3.2 + Story 2.5 all opted for explicit-scenario embedding when the threat surface was already authoritatively enumerated upstream).

> **Scope:** Story 5.3 commits the FIRST in-gateway 3-axis rate-limit middleware on He-API (`apps/api-gateway/internal/middleware/ratelimit/`), the FIRST atomic Lua script in api-gateway (`check_and_incr.lua` — single-round-trip 3-axis CHECK+INCR+EXPIRE with NX TTL semantics), the FIRST post-deduction token-accounting pattern (TPM deducted AFTER upstream returns `usage.total_tokens` on both non-streaming and streaming paths, with Q10-ratified edge cases for stream-error / client-disconnect / missing-tail-usage), a NEW envelope code `429_rate_limit_rpm` (Architect Q5 ratified — completes the QPS/RPM/TPM triplet), realisation of pre-declared Redis keys `ratelimit:key:{api_key_id}:{qps,rpm,tpm}` (architecture `data-models.md §4.3`), fail-OPEN posture on Redis unavailability with 5ms timeout (Q6 ratified divergence from Story-2.3 OQ3 fail-CLOSED — different threat model), and Helm-templated free-tier defaults sourced from env vars `RATELIMIT_FREE_TIER_{QPS,RPM,TPM}_MAX`. The test surface spans **middleware unit** (testify + miniredis/v2 + httptest), **handler-integration** (testcontainers Redis 7.2-alpine + httptest gateway), **streaming-integration** (Story-4.1 adapter-chunker contract), **cross-pod statelessness** (2 gateway httptest instances sharing one Redis), **fail-open chaos** (Toxiproxy + Redis RST + OOM + LOADING), **security cross-cutting** (slog discipline + per-key isolation + defensive 500), and **hot-path benchmark** (miniredis). All 3 ACs + 26 BRs (BR-1.x 8 + BR-2.x 8 + BR-3.x 10) + 9 cross-cutting (BR-X.1..X.9) covered by ≥ 1 scenario each.

### Story-level Scenario-ID convention

- `5.3-UNIT-{NNN}` — Go unit test (testify + table-driven). In-process composition only. Mocks: `miniredis/v2` for in-memory Redis Lua execution; `httptest` for HTTP handler chain; `slogtest` for slog capture. Deterministic time via `clockwork.NewFakeClock` only where TTL precision is asserted.
- `5.3-INT-{NNN}` — Integration test (`apps/api-gateway/tests/ratelimit_integration_test.go`). testcontainers-go Redis pinned to `redis:7.2-alpine` per architecture `tech-stack.md §2.1`. Real Redis EVALSHA path; real net/http chain.
- `5.3-CHAOS-{NNN}` — Build-tag `chaos` (`go test -tags chaos`). Toxiproxy for slow-loris / RST; Redis OOM via `maxmemory` directive; Redis LOADING via `DEBUG SLEEP` proxy.
- `5.3-SEC-{NNN}` — Security test (`apps/api-gateway/tests/ratelimit_security_test.go`). Regex-assertion over captured slog stream + Prometheus snapshot.
- `5.3-BENCH-{NNN}` — `BenchmarkCheck` in `ratelimit_bench_test.go`. Soft-gate via `t.Log` per Story-4.7 BR-1.10 precedent (informational; not CI-blocking until Epic-9 k6 baseline lands).
- `5.3-DOC-{NNN}` — Documentation registry / architecture-doc verification (CI-style guard in QA, NOT a Go test).

### Test-design level reasoning (Decision 8B verbatim)

Three rules converge:
- `complexity_indicators >= 3 → Comprehensive` (Story has 5/8 — api_changes + new_patterns + security + performance + core_docs)
- `security_sensitive == true → Comprehensive + security_focus` (rate-limit IS the abuse/DoS defence layer)
- Epic-5 epic-level `test_design_level: comprehensive` inheritance

Hence test_levels = `[unit, integration, e2e, security, chaos]`, priority = `critical`. **E2E note:** Decision 8B lists `e2e`, but rate-limit semantics are testable at the integration tier (no UI surface in Story 5.3 — Story 5.5 Console UI is the E2E owner). QA opts to substitute E2E with deeper INT + CHAOS coverage, matching Dev Notes line 820 "No E2E: rate-limit semantics are testable at the integration tier; Playwright E2E is reserved for Story 5.5 Console UI."
