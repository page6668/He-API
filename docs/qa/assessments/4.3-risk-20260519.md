**Top 4 Risks (by score):**

1. **TECH-001 (R1)** — Upstream-failure-mode coverage incomplete for Moonshot-specific shapes (429 throttle body, 400 context-length-exceeded body via `invalid_request_error`, native 401 `invalid_api_key`); BR-1.4 + BR-4.4 + BR-4.5 mapping drift could leak unhandled errors as `500_internal_error` or misclassified `upstream_4xx_generic`. Score: **16** (P=4 × I=4) — mitigated by sextuple-layer test defence (INT-003 + INT-004 + INT-006 + UNIT-007 body-aware classifier + CHAOS-001..006 + 2 NEW Kimi-specific CHAOS-007/008).
2. **TECH-008 (R8 N=3-strengthened)** — Multi-model-id-per-service dispatch leaks state across THREE model ids: a `moonshot-v1-8k` request returns `moonshot-v1-32k` or `moonshot-v1-128k` response (model-id swap in `translate.go` body, adapter response mapping, or concurrent goroutine state-sharing). Score: **15** (P=3 × I=5 — silent data corruption with downstream billing implications + N=3 has more permutations than Story-4.2 N=2) — mitigated by triple-layer (UNIT-002/003/003b translate forward × 3, INT-002 upstream-receive × 3, INT-013 parallel-three-stream non-cross-contamination, CONTRACT-001..006 SDK-observed response.model × 3 × 2 paths).
3. **TECH-009 (R9 N=3-strengthened)** — `NewRegistry` endpoint-dedup refactor (Story-4.2 M2 ~7 LoC) MUST scale from N=2 to N=3 without regression. If the dedup `byEndpoint` map fails at N=3, three pool-share gets dropped to three separate connection pools (Story-4.1 deepseek-v3 and Story-4.2 qwen-max/qwen-plus must continue working unchanged). Score: **12** (P=3 × I=4 — Story-4.1/4.2 regression breaks two ratified vendor surfaces) — mitigated by UNIT-011 strengthened to `assert.Same(h_8k, h_32k); assert.Same(h_32k, h_128k)` chain per OQ-4.3-5 + UNIT-012 (deepseek-v3 distinct handle, Story-4.1 regression guard) + UNIT-013 (qwen-max/qwen-plus distinct from kimi; M2 invariant preserved) + INT-016 (end-to-end cross-vendor dispatch verified).
4. **TECH-010 (R10 NEW)** — Large-prompt PII discipline regression at the 128k variant. The 128k context budget encourages long-document workloads (50K+ token prompts); slog discipline regression here would leak 100K+ character user content into logs at HIGH ops-cost and direct PII exposure on long-document QA prompts. Score: **15** (P=3 × I=5 — direct compliance + ops-cost surface). Mitigated by UNIT-014 (BR-1.9 short-prompt) + UNIT-016 (NEW Kimi-specific: 100K-char prompt fixture — slog substring check) + BLIND-FLOW-002 (cancel-on-long-prompt preserves discipline) + BLIND-RESOURCE-003 implicit (slog record size bounded).

**Overall Assessment:**

- **Zero Critical** risks. All 12 risks have explicit P0 or P1 test gates designed in `4.3-test-design-20260519.md`.
- The 4 High risks (TECH-001 + TECH-008 + TECH-009 + TECH-010) drive the Comprehensive test-design budget — together they account for **31 of the 42 P0 scenarios** (chaos suite + three-model triple-coverage + M2 N=3 endpoint-dedup regression guard + 100K-char PII fixture).

- All 4 High risks must have GREEN P0 test coverage before Dev marks `Status = Review` (QA-aligned gate criteria).

**Recommendation: Conditional Proceed** — Dev MAY begin implementation after acknowledging the 5 Immediate Action items in §Risk Mitigation Roadmap.
