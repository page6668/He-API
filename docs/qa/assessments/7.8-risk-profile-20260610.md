## Detailed Risk Analysis

### PRIV-001: Tier privilege-escalation (client-asserted plan trusted)

**Category:** Security / Revenue-integrity · **Probability:** 3 · **Impact:** 5 · **Score:** 15 (High)

**Description.** The entitlement ceiling is what the user *paid for*. If the gateway ever trusted a client-supplied plan/limit (an `X-Plan: enterprise` header, a body hint, a forged claim), a Free user would obtain Pro/Enterprise rate-limit/quota — the direct revenue/abuse-integrity defect this story exists to prevent. This is the **dominant risk** of 7.8, the hot-path analogue of the 7.1 wrong-charge.

**Mitigation:**
- **Prevention:** the entitlement is resolved **SERVER-SIDE** from `subscriptions` (status='active') keyed by the **authenticated** user_id (`BearerUserIDFromContext`); a client-asserted plan/limit is structurally never read (BR-E-1). The plan→limits map is version-controlled code (`packages/plan-catalogue/`), not runtime-tamperable. The snapshot is keyed by user_id (no cross-user read) and written only by billing-svc.
- **Detection:** **P0** — a request carrying a plan hint with a Free subscription is throttled at free limits; the resolver ignores the hint.
- **Response:** the catalogue + server-resolution are the single trust boundary; no client path can raise the ceiling.
- **Owner:** Dev

**Test Requirements (P0):** UNIT-016/017 (server-side context-user resolution; client-asserted plan structurally ignored) — **GREEN**; full-HTTP lane INT-035 (integration-env).
**Residual:** **Low** — proven non-vacuously at the component boundary; the only unproven slice is the full-HTTP wrapper (env-deferred, QA-7.8-004).
**References:** [BR-E-1; AC3 Example "privilege-escalation blocked"; SM threat_model #1; Architect Q-ENTITLEMENT-ENFORCE]

### PRIV-002: Fail-open-HIGH on cache miss / resolution uncertainty

**Category:** Security / Revenue-integrity · **Probability:** 3 · **Impact:** 5 · **Score:** 15 (High)

**Description.** The gateway enforces a *cached* entitlement snapshot on the hot path. Fail-open is the "convenient" default (don't throttle if unsure) — but for an entitlement ceiling it is catastrophic: **every** cache miss/uncertainty would grant the higher (Enterprise/unlimited) ceiling to whoever missed, a systemic revenue leak and the fail-direction mistake an unguarded implementation drifts into. Inherent probability is elevated precisely because fail-open is the tempting direction.

**Mitigation:**
- **Prevention:** **fail-safe-LOW** is mandatory and non-negotiable (Architect-ratified) — a cache miss, a resolution failure, or any uncertainty enforces the **FREE** ceiling (the lowest), never fail-open-high (BR-E-2). A miss async-refreshes the snapshot from billing-svc but enforces free meanwhile.
- **Detection:** **P0** — fail-safe-LOW asserted across the full set of uncertainty cases (miss, malformed snapshot, billing-svc unavailable, TTL expiry with no refresh).
- **Response:** the 60s TTL self-heals; the sentinel is the fast path.
- **Owner:** Dev

**Test Requirements (P0):** UNIT-018/019/021 (`entitlement_test.go` — fail-safe-LOW across 5 uncertainty cases) — **GREEN**.
**Residual:** **Low** — the 5-case fail-safe-LOW suite is proven; this is the strongest-covered invariant in the story.
**References:** [BR-E-2; AC3 fail-safe-low; Architect Q-ENTITLEMENT-ENFORCE "fail-safe-LOW … non-negotiable"]

### CACHE-001: Stale-cache downgrade leak

**Category:** Security / Revenue-integrity · **Probability:** 3 · **Impact:** 4 · **Score:** 12 (Medium)

**Description.** A downgrade / cancel / provider-webhook `past_due` must promptly drop the user's ceiling. If the cached snapshot is not invalidated, a downgraded/cancelled user keeps the higher tier until TTL — a revenue leak (Pro limits without Pro billing). Downgrades/cancels are routine, so probability is real.

**Mitigation:**
- **Prevention:** billing-svc is the **sole writer** and invalidates/refreshes `entitlement:user:{id}` on **every** `subscriptions` transition (including the 7.3 cancel/past_due webhook) + a cross-pod invalidation sentinel (5.1 `auth:apikey:revoked` precedent) + a bounded TTL ≤ 60s self-heal (BR-E-3). A cancelled subscription degrades to **free**, never to unlimited (BR-S-8 / Q-PLAN-DEFAULT).
- **Detection:** **P0** — a cancel webhook invalidates the snapshot → the gateway converges to free (never keeps the higher tier); an upgrade refreshes to the higher tier within the window (both directions).
- **Owner:** Dev

**Test Requirements (P0):** `credit_test.go` INT-019 (cancel webhook invalidates the snapshot, never keeps the higher tier) + INT-013 (refresh-to-pro) — **GREEN**; full convergence-window E2E-003/004 (integration-env).
**Residual:** **Low-Medium** — invalidate/refresh proven at the credit boundary; the cross-pod sentinel propagation timing is an integration-env assertion.
**References:** [BR-E-3; SM data_sync_analysis item 2 + threat_model #4; Architect TTL≤60s + sentinel knob]

### BETA-002: Beta-flag unavailable-direction wrong

**Category:** Technical · **Probability:** 3 · **Impact:** 4 · **Score:** 12 (Medium)

**Description.** The beta-flag read has two failure modes that fail in *opposite* safe directions, and conflating them is harmful: a **booting** pod with no Redis AND no PG signal that defaults beta **ON** would trap every user in the sandbox on a cold-infra fault (DoS-by-config); a **running** pod that loses Redis but had beta ON and silently flips OFF would remove the containment cap mid-Beta (uncontrolled spend).

**Mitigation:**
- **Prevention (Architect-ratified split):** a booting pod with no signal defaults beta **OFF** (do not trap users on a cold fault); a running pod that loses Redis holds its **last-known** flag value until PG/Unleash reconciles (BR-B-2, Q-BETA-GATE unavailable-direction).
- **Detection:** unit tests on **both** directions, distinctly.
- **Owner:** Dev

**Test Requirements (P0/P1):** UNIT-028 (booting-no-signal → OFF) + UNIT-029 (running-loses-Redis → last-known) + BLIND-ERROR-004 (`betamode_test.go`, cold-start-reader call tracking) — **GREEN**.
**Residual:** **Low** — both fail-directions proven with call-tracking.
**References:** [BR-B-2; AC2 Error Handling "Redis unavailable"; Architect Q-BETA-GATE unavailable-direction]

### BETA-001: Non-admin beta-mode flip (global blast radius)

**Category:** Security · **Probability:** 2 · **Impact:** 5 · **Score:** 10 (Medium)

**Description.** `beta_mode` is a single global control: ON traps everyone in the sandbox (DoS-by-config), OFF removes the beta ceiling (uncontrolled spend). A non-admin flip is a platform-wide incident.

**Mitigation:**
- **Prevention:** the flip **WRITE surface is OUT of He-API** entirely (Q-ADMIN-BETA scoped) — the **Unleash console (its own RBAC)** is the operator SoT; He-API's `feature_flags` PG row + `flag:beta_mode` Redis are cold-start + runtime **READ mirrors** only. There is **no** He-API write endpoint and **no** `admin-forbidden` code (both dropped from 7.8). A normal bearer key has no route to flip the flag.
- **Detection:** **P0** — assert the **absence** of any He-API `beta_mode` write route (route-absence is the assertion, not a 403).
- **Owner:** Dev/Ops (Unleash RBAC config is ops-owned)

**Test Requirements (P0):** INT-027 asserts He-API route absence for `beta_mode` write — **GREEN (route-absence)**; Unleash RBAC is operator-config (out of code).
**Residual:** **Low (in-code)** — no write surface exists to attack; **residual sits in ops** (Unleash console RBAC must be correctly configured before Beta cutover).
**References:** [BR-B-4; Architect Q-ADMIN-BETA "SCOPED — Unleash console SoT; DROP the admin endpoint + admin-forbidden code"; SM threat_model #2]

### XUSER-001: Cross-user subscription mutation

**Category:** Security · **Probability:** 2 · **Impact:** 5 · **Score:** 10 (Medium)

**Description.** If PUT/DELETE `/v1/billing/subscription` accepted a target-user parameter, user A could change user B's plan (or cancel it) — a cross-tenant integrity break.

**Mitigation:**
- **Prevention:** the singleton endpoints operate ONLY on the **authenticated** user's own subscription (user_id server-resolved via `BearerUserIDFromContext`); there is **no** path/body target-user parameter (BR-S-7). The singular `/subscription` *is* "the caller's one subscription" by design (Medium-2 singleton).
- **Detection:** **P0** — no target-user parameter exists; the handler resolves the caller only.
- **Owner:** Dev

**Test Requirements (P0):** server-side context-user resolution shares the PRIV-001 proof (no target param in the handler signature); full-HTTP lane INT-036 (integration-env).
**Residual:** **Low** — structurally impossible (no target param); full-HTTP re-assertion is env-deferred.
**References:** [BR-S-7; AC1 ownership invariant; SM threat_model #3]

### PERF-001: Hot-path latency regression

**Category:** Technical · **Probability:** 2 · **Impact:** 4 · **Score:** 8 (Medium)

**Description.** Entitlement resolution sits on `POST /v1/chat/completions`. A synchronous PG or billing-svc call on that path would regress the gateway latency budget for every request (performance indicator, Decision 8B — the contrast with 7.7 which sat off the hot path).

**Mitigation:**
- **Prevention:** the resolution is a **single cached Redis read composed in-process** (`Resolver.CeilingsForUser` on the 5.3 `ResolveCeilingsFunc` seam); **NO** synchronous PG/billing call on the request path (BR-E-6). 7.8 supplies only the limit *values* the existing 5.3 Lua limiter reads — no new throttle envelope, no new key shape.
- **Detection:** hot-path benchmark soft-gate (4.7 `models_bench_test.go` precedent).
- **Owner:** Dev

**Test Requirements (P1):** INT-016/023 (cached-read only, no PG call on resolve) — **GREEN**; hot-path benchmark E2E-006 (integration-env soft-gate).
**Residual:** **Low** — the no-sync-call structure is verified; the absolute latency number is an env-deferred soft-gate.
**References:** [BR-E-6; Decision 8B performance indicator; Architect Q-ENTITLEMENT-ENFORCE "NO synchronous PG/billing call on the chat hot path"]

### CONF-001: Optimistic plan mutation → billing↔entitlement mismatch

**Category:** Technical / Revenue-integrity · **Probability:** 2 · **Impact:** 3 · **Score:** 6 (Medium)

**Description.** If billing-svc flipped `subscriptions.plan` *before* the provider confirmed the billing change, a failed provider charge would leave a user entitled to a tier they were never billed for (entitled-but-unbilled), or vice-versa.

**Mitigation:** the plan transition is **CONFIRMED on the 7.3 provider webhook** (mirrors "credit only on confirmed webhook" — BR-S-3); billing-svc does not optimistically mutate `subscriptions.plan` before the provider confirms. The entitlement *may* apply optimistically on an upgrade once the provider call returns success (Architect knob), but the durable plan flip is webhook-gated. **Detection (P0):** webhook plan flip on confirmed active (INT-013); no flip on a non-confirmed path. **Owner:** Dev.

**Test Requirements:** INT-013 (`credit.applySubscription` flips plan on confirmed webhook, RETURNING user_id) — **GREEN**.
**References:** [BR-S-3; Architect Q-UPGRADE-DOWNGRADE]

**Category:** Security / Revenue-integrity · **Probability:** 2 · **Impact:** 3 · **Score:** 6 (Medium)

### MONEY-001: Money precision loss

### BETA-003: Beta propagation lag

**Category:** Technical · **Probability:** 2 · **Impact:** 2 · **Score:** 4 (Low)

**Mitigation:** the propagation window is bounded by the gateway's Redis-read cadence + Unleash push latency — an explicit, bounded knob (BR-B-6), not unbounded; PG is the cold-start SoT, Redis the runtime read, Unleash the live push. **Detection (integration-env):** flip → every-pod-effective within the window. **Owner:** Dev/Ops.

**Test Requirements:** propagation INT-024..030 (integration-env, QA-7.8-004).

### BUS-001: Downgrade-deferred-to-period-end UX confusion
