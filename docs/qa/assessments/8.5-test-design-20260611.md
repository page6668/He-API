# Test Design: 8.5 — 治理日志（拦截记录）+ 备案材料模板

2026-06-11 | Turing (QA) | Level: **Comprehensive** (security-sensitive, complexity 6)

> Spine (Architect handoff, Wright 2026-06-11): the **four HARD compliance/regression gates** are the
> backbone of this design — every other scenario hangs off them.
> 1. **NO-REGRESSION** — 8.2/8.3/8.4 byte-identical on the response path with the persisting Recorder wired.
> 2. **FIRE-AND-FORGET (+ graceful drain)** — a faulting / full-buffer Recorder never blocks/alters the
>    400 / redact / stream-terminate; ctx-cancel flushes in-flight events then exits (OQ-8.5-1 ruling).
> 3. **GDPR-EXEMPTION** — delete user → `content_safety_logs` rows survive; NO `REFERENCES users` FK.
> 4. **REDACTION-SAFETY** — `excerpt_redacted` and the 备案 PDF leak neither raw user content nor the
>    literal 敏感词 (only canonical `matched_rule` ids + masked windows).

## Overview

Total: **44** | Unit: 31 (70%) · Integration: 5 (11%) · Migration: 3 (7%) · Manifest: 1 · Build: 1 · Bench: 1
Priority: **P0: 26** · P1: 15 · P2: 3
Blind-spot scenarios: **15** (BOUNDARY 6 · ERROR 4 · CONCURRENCY 2 · RESOURCE 2 · DATA 1 · FLOW 0 — backend, no UI flow)

**Toolchain note (binding constraint):** local env cannot run docker/atlas/buf (memory: `project_toolchain_env_limits`).
Persist + retention DELETE are exercised with **pgxmock**; the gateway path with **httptest**. Migration
reversibility (MIG-002) and the no-FK schema assertion (MIG-001) are verified by round-trip **where the
toolchain allows**; else they are a documented Dev follow-up (BR-1.1 / BR-4.4). No new CI lane (BR-4.2) —
everything lands in the existing `./apps/api-gateway/... -race` lane.

**Skeleton-as-tables (deliberate, Go-specific):** the task's Output-2 executable skeleton is a TS/JS
artifact. A Go skeleton referencing the not-yet-created `safetylog` types would fail to compile and break
`go build ./...` / the test lane — contradicting BR-4.2. So the executable scenarios are delivered as the
white-box tables below + the finalized **Test Specs** already embedded in the story Tasks (T1–T4). Dev
implements tests next to the code per Go convention; QA verifies one test per scenario id at review.

## P0 TRANCHE (execute first — fail fast on the HARD gates)

### AC1 · persisting Recorder + table + 脱敏 excerpt (P0)

| ID | Lvl | Test | Why P0 |
|----|-----|------|--------|
| 8.5-UNIT-001 | U | Input block (strict key, high 入参 term) → **exactly 1** row {direction:`input`, action:`blocked`, matched_rule=canonical, excerpt 脱敏} | compliance: persist-correctness, one acted-on block = one row |
| 8.5-UNIT-002 | U | Output redact (default key, A/B 2 choices both medium) → **2** rows {direction:`output`} (one per redacted choice, `chat_completions_safety_output.go`) | per-choice fan-out is the easiest place to drop/double-write |
| 8.5-UNIT-003 | U | Stream terminate (high term split across deltas) → **1** row {direction:`output`} | stream path is a separate emit site |
| 8.5-UNIT-004 | U | Sub-threshold (loose key, only `low` term, not acted on) → **0** rows | BR-1.6: only acted-on blocks log; no Bloom-near-miss noise |
| 8.5-UNIT-005 | U | Row field projection: matched_rule (canonical id ≤100 runes), user_id / api_key_id / he_request_id from event, created_at=NOW(), strictness from `SafetyEvent.Strictness` (OQ-8.5-7 col) | pure projection correctness; defence vs field-mapping drift |
| 8.5-UNIT-006 | U | **REDACTION-SAFETY (HARD, property)**: hits with surrounding email/phone/long-digit/@handle → excerpt has matched span = `■`×rune-count, PII masked, ≤64 runes, **literal term NEVER stored**, NO raw user text | HARD gate #4 (no-leak + 不出境); BR-1.4, Architect OQ-8.5-2 |
| 8.5-INT-001 | I | Gateway httptest + pgxmock: input block end-to-end → 1 row; response envelope byte-identical to 8.2 | wires Recorder through the real handler |
| 8.5-BLIND-ERROR-001 | U | **FIRE-AND-FORGET (HARD)**: Recorder whose INSERT errors → block envelope byte-identical + on-time; WARN `safety_log: persist failed`; event dropped | HARD gate #2; the gravest defect is a persist that alters the block |
| 8.5-BLIND-ERROR-002 | U | **FIRE-AND-FORGET (HARD)**: saturate the async buffer → event dropped + `safety_log_dropped_total++`; block proceeds unchanged | HARD gate #2 (saturation path) |
| 8.5-BLIND-RESOURCE-001 | U | **GRACEFUL DRAIN (HARD, OQ-8.5-1)**: ctx cancel → worker flushes in-flight events then exits within bounded timeout; no goroutine leak; no silent loss on normal redeploy | HARD gate #2; Architect made graceful-drain an explicit HARD assertion |

> Blind-spot refs: ERROR-001/ERROR-005 (network/resource-exhaustion → drop), RESOURCE-002/004 (worker exit, no leak).

### AC2 · 6-month retention + GDPR exemption (P0)

| ID | Lvl | Test | Why P0 |
|----|-----|------|--------|
| 8.5-UNIT-010 | U | Sweep deletes `< NOW()-INTERVAL '6 months'` — rows at 7mo + 5mo → 7mo DELETED, 5mo REMAINS (strict `<`) | §9.3 retention floor; correctness of the cutoff |
| 8.5-UNIT-011 | U | Idempotent — re-run within window deletes **0** rows | BR-2.5; safe re-run / `Forbid` posture |

| 8.5-INT-003 | I | **GDPR-EXEMPTION (HARD)**: create user + logs → `DELETE FROM users WHERE id=<u>` → content_safety_logs rows for `<u>` **REMAIN** | HARD gate #3; §9.3 合规优先于个人删除 |
| 8.5-MIG-001 | M | **NO-FK (HARD)**: inspect schema after 0014 → `content_safety_logs.user_id` has **NO** `REFERENCES he_api.users(id)` (contrast `data_export_requests` CASCADE) | HARD gate #3 mechanism; blocks a future "tidy the FK" cascade-reintroduction |
| 8.5-BLIND-BOUNDARY-004 | U | Row exactly at cutoff (`created_at == NOW()-6mo`) → **NOT** deleted (strict `<`, half-open) | BOUNDARY-002/004; off-by-one on the compliance floor |
| 8.5-BLIND-ERROR-003 | U | DB unreachable in cron → exit 1, no partial effect | ERROR-002; cron must fail loud (backoffLimit:0 → human-verified) |
| 8.5-BLIND-DATA-001 | I | Cascade-reintroduction guard — same as INT-003 asserted as a regression lock: any future FK that cascades fails this test | DATA-003 (inverse); the load-bearing 备案-retention invariant |

## Risk Coverage

No standalone risk-profile doc; the story's Security & Compliance Notes name the **three gravest defects** —
each is pinned to a HARD gate and a P0 scenario:

| Gravest defect (story §Security) | HARD gate | Pinned P0 scenarios |
|----------------------------------|-----------|---------------------|
| (a) Recorder failure that BLOCKS/ALTERS the user-facing block | Fire-and-forget | 8.5-BLIND-ERROR-001/002, UNIT-031, RESOURCE-001/032 |
| (b) Cascade that PURGES safety logs on user deletion | GDPR-exemption | 8.5-INT-003, MIG-001, BLIND-DATA-001 |
| (c) Leak of raw content / literal 敏感词 into excerpt or PDF | Redaction-safety | 8.5-UNIT-006, UNIT-021 |
| + silent regression of 8.2/8.3/8.4 response path | No-regression | 8.5-UNIT-030 |
