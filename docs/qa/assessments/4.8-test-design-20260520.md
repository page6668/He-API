### Why "Comprehensive" (not Standard or Simple)

Decision 8B routes to **Comprehensive** via two converging triggers:

1. **Epic-level directive (primary)** — `docs/prd/epic-4-model-adapters.yaml` line 9 declares `test_design_level: comprehensive` at the epic root. Story 4.8 is precisely the test-coverage closure for Epic 4 — applying anything less here would defeat the directive's purpose.
2. **Story-level natural fit (secondary)** — the AC2 protocol-completeness matrix is a 20-cell verification grid (10 model ids × stream={false, true}); the 26-cell per-vendor body-conversion fanout (4.1-CONTRACT-001..006 + 4.2-001..006 + 4.3-001..006 + 4.4-001..002 + 4.5-001..004 + 4.6-001..002); plus 14 fake-upstream / workflow / live-lane scenarios; plus the 20-strong meta-test block (T0.3). Comprehensive coverage is the natural floor.

Comprehensive level → all four test tiers exercised (unit + integration + contract + e2e); blind-spot overlay mandatory; ~30 scenario floor easily cleared.

### Why this surface needs Comprehensive

Story 4.8 lands **three precedent-setting test surfaces** that cascade across Epic-4 closure + Epic-5+ inheritance:

1. **Shared protocol-invariants library** (`apps/api-gateway/tests/_protocol_invariants.py`) — the FIRST `_`-prefixed pytest-shared helper module in the gateway test root. Establishes the file naming + module layout + stdlib-only discipline (BR-2.11) that future Stories adding vendors (4.9+) + future Stories adding endpoints (Epic-5 `/v1/files` + Epic-7 fine-tuning) inherit verbatim. A typo in the regex constants here (`CHATCMPL_ID_RE` / `REQUEST_ID_RE`) silently corrupts every downstream contract test.
2. **Adapter-fake CI lane pattern** — the FIRST CI-only Go binaries in the repo (`apps/adapters/{vendor}/cmd/fake-upstream/main.go` × 6). Establishes the co-located test-binary directory placement (OQ-4.8-3); the `httptest.NewTLSServer`-shaped fake-upstream wire shape; the deterministic-fixture-response invariant (BR-1.10); the 12-background-process workflow lifecycle (BR-1.3). Future Stories 4.9+ adding vendors inherit this template wholesale.
3. **20-cell cross-vendor protocol-completeness matrix** — the FIRST parametrised matrix test in the gateway test root. Establishes the `MATRIX_MODELS × MATRIX_STREAM = N×M` single-source-of-truth constant discipline (BR-2.8); the `$GITHUB_STEP_SUMMARY` cell-result markdown table (BR-2.7); the `he-router-*` virtual-model exclusion with explicit skip-with-reason audit trail (BR-2.9). Future Story-4.9-vendor#7 just appends `"kuaichi-v1"` to `MATRIX_MODELS` and the matrix auto-grows from 20 → 22 cells.

Drift at any of these three surfaces silently propagates across Stories 4.1-4.6 (whose `_contract_test.py` bodies now consume the shared library + run on the new CI lane) AND across Stories 4.9+ (whose authors will inherit the pattern). Over-investing in tests now is cheap insurance.

- **Fast feedback**: Unit tier runs in ≤ 30s locally; integration ≤ 90s in CI; full suite ≤ 12 min wall-clock (BR-1.9)
