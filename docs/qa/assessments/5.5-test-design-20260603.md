# Test Design: 5.5 — Console Keys Page (CRUD + Config UI)

2026-06-03 | Turing (QA) | Level: **Comprehensive** (Epic-5 inheritance + security_sensitive + multi-AC)

> **Architect ruling applied (Wright, 2026-06-03, AwaitingArchReview → AwaitingTestDesign):**
> **Q-E5 OVERRULED** — `cap_tripped` is **de-scoped from the server wire shape**. `<CapBudgetBar>`
> **heuristic-computes** the tripped state client-side as `current_month_cost_usd >= monthly_cost_cap_usd`.
> Consequences for this test design:
> 1. `ApiKeyEntrySchema` MUST NOT require a `cap_tripped` field (it is removed, not `.optional()`).
> 2. The tripped badge is a pure client-side derivation — there is a **known coverage gap**
>    (the Story-5.4 cron-reset edge case: `current=0` while the Redis sticky-trip sentinel is still set →
>    heuristic renders *green/no-badge*). This gap is **by-design per the Q-E5 overrule** and is
>    documented as `GAP-CAP-001` below — it is NOT a Dev defect.
> The 4 Architect "Major" issues (factual-reference corrections — filenames / schema names / list
> envelope shape / i18n namespace) are MANDATORY Dev-time corrections, not test blockers.

**Shift-left rationale:** the highest-value logic of this story — locale-aware money parsing,
IP/CIDR validation, NFC name validation, type-name-match comparison, and the cap-tripped heuristic —
is **pure and isolated** and is pushed to the Unit level (fast, deterministic). React component
wiring (RHF + next-intl + shadcn-ui) is verified at the Integration level with Testing Library.
Only true cross-page journeys, plaintext-discipline, IDOR, and a11y land at E2E.

**Test runners:**
- Unit + Integration → **Vitest** + `@testing-library/react` → `apps/console/__tests__/5.5-console-keys-page-crud-config-ui.test.tsx` (skeleton generated by this task) + per-component files under `apps/console/__tests__/components/business/` per story T1–T4.
- E2E + Security + A11y + Visual → **Playwright** → `apps/console/e2e/5.5-keys-page.spec.ts` + `apps/console/e2e/5.5-keys-page-a11y.spec.ts`.
