# Test Design: 6.4 — A/B 模式（X-He-AB-Models）

2026-06-03 | Turing (QA) | Level: **Comprehensive** (Epic-6 inheritance + Decision 8B) | Status: Complete

> All Q-A…Q-K Architect rulings are **LOCKED** (Round 1, 2026-06-03). Test design targets the
> SM defaults as ratified. High-1 (`sync.WaitGroup`, NOT errgroup) and High-2 (keypolicy
> middleware gates `body.model` upstream; handler additively checks both legs) are folded in.

## Overview

**Total: 58** | Unit: 47 (81%) | Integration: 9 (16%) | Contract: 2 (3%)
**Priority:** P0: 33, P1: 21, P2: 4
**Blind Spot Scenarios: 16** (BOUNDARY 5, CONCURRENCY 4, ERROR 4, DATA 2, RESOURCE 1)

**Test levels** (per Decision 8B): `unit` (logic — parse / merge / classify / billing math),
`integration` (gateway↔routing-svc↔adapter dispatch + scope/middleware), `contract`
(proto wire round-trip on the 3 preshaped fields + OpenAI-SDK Pydantic round-trip).

**Coverage target:** ≥80% on `dispatchAB` + `mergeABResponses` + `dispatchAdapterOnce` +
`ParseABModels` + the routing-svc A/B decision branch (Tasks T6.2).

**Shift-left bias:** the headline new logic (parse exactly-2, merge re-index, usage sum,
error classification, billing math) is pure → tested at UNIT. Only the parallel-dispatch
concurrency proof, scope/middleware interaction, dual-billing end-to-end, and the OpenAI-SDK
round-trip need INT/CONTRACT.

- BOUNDARY ≥1 per input field — ✅ `X-He-AB-Models` header (5 BOUNDARY scenarios).
- ERROR ≥1 per external dependency — ✅ upstream adapter legs (ERROR-001/002/003 + AC3 leg-failure suite).
- CONCURRENCY for security/parallel ops — ✅ the parallel dual-dispatch (4 CONCURRENCY scenarios; the headline new pattern).
- DATA for the dual-billing/usage-sum cross-cut — ✅ DATA-001/010.
- RESOURCE for stream cleanup on the non-writing primitive — ✅ RESOURCE-001.
- FLOW intentionally omitted — A/B is a server-side fan-out, not a multi-step user journey (no UI flow surface).
