### Story-level Scenario-ID convention

- `2.5-UNIT-{NNN}` — auth-svc / api-gateway / console unit (Go testify + Vitest)
- `2.5-INT-{NNN}` — auth-svc + Postgres / Kafka / Redis integration (Go testcontainers-go) **OR** api-gateway ↔ auth-svc full-stack handler integration
- `2.5-E2E-{NNN}` — Playwright browser flow (console + api-gateway + auth-svc + Kafka audit)
- `2.5-BLIND-{CATEGORY}-{NNN}` — blind-spot scenario tagged `[BLIND-SPOT]` per `blind-spot-categories.yaml`. Categories applied: **BOUNDARY, ERROR, FLOW, CONCURRENCY, DATA, RESOURCE** (full-stack applicability per the framework's `applicability.fullstack` row)

Dev MUST embed `// Scenario: {scenario_id}` (Go + TS) in each test function — QA `*review 2.5` greps these comments for AC traceability per Story 2.2 / 2.3 / 2.4 precedent.

### Project-type detection

Full-stack: Go gRPC `auth-svc` + Go HTTP `api-gateway` (stdlib `net/http` ServeMux per m-5 ruling) + Next.js `console` (Server Components + Server Actions). High-priority blind-spot categories per `blind-spot-categories.yaml` `applicability.fullstack`: **all 6**. `security_sensitive=false`, so CONCURRENCY / DATA / RESOURCE are NOT auto-elevated to P0 (contrast Story 2.4) — only the etag-protection race (CONCURRENCY-001) and the DB-vs-audit transactional contract (DATA-001) are P0 by the AC business rules themselves (BR-2.7, BR-2.13).

### Architect Q1-Q4 ruling impact on test design

- **Q1** (GET /v1/me whole-user APPROVE): test scope unchanged; surface tested includes `email + totp_enabled + oauth_provider` read-only fields per AC1.
- **Q2** (etag = `UnixMicro()` end-to-end + Go-side compare in FOR UPDATE txn): scenarios `2.5-UNIT-004`, `2.5-UNIT-032`, `2.5-INT-005`, `2.5-INT-006` test the microsecond round-trip. Story-Tasks ID-references to `UnixNano` must be read as `UnixMicro` per Architect m-1 ruling.
- **Q3** (`SetLocaleCookie` helper in `apps/api-gateway/internal/handlers/cookies.go`): scenarios `2.5-UNIT-042` + `2.5-INT-010` test the cookie attribute mirror against `apps/console/lib/i18n.ts → buildLocaleCookieOptions`.
- **Q4** (`aal>=1` APPROVE, no step-up): scenario `2.5-UNIT-007` asserts route wiring uses `verifier.RequireJWT(...)` only, NOT `RequireAAL(2, ...)`.

## Risk Coverage

`security_sensitive=false` per SM Decision 8B + Architect Round 1 confirmation; risk-profile artifact is NOT required for Story 2.5 (contrast Story 2.4 where security_sensitive=true mandated `*risk-profile`). The following implicit risks are addressed by the test scenarios above:

| Risk | Mitigated by |
|------|--------------|
| IDOR (client-supplied user_id reaching auth-svc) | UNIT-007 + INT-004 (gateway middleware extracts user_id from JWT `sub` only) |
| Display-name homoglyph attack | UNIT-021 + UNIT-022 (NFC + class allowlist) |
| Lost-update on simultaneous tab edit | UNIT-030 + INT-006 + E2E-003 + BLIND-CONCURRENCY-001/002 (etag FOR UPDATE Go-side compare) |
| Profile-edit abuse (rate-limit bypass) | UNIT-036 + INT-012 + E2E-005 (10/hour Redis counter) |
| PII leak in audit log | UNIT-034 + INT-016 (redactPresence — display_name never literal) |
| Locale-cookie attribute drift vs `<LocaleSwitch>` | UNIT-046 + UNIT-055 + INT-010 (Q3 helper parity table-driven test) |
| Cache-mishandling of PII page | UNIT-008 (Cache-Control: no-store) |
| i18n key drift across 10 locales | UNIT-056 + UNIT-057 (CI gates) |
| RTL layout regression | E2E-007 + E2E-015 (visual regression) |
| Long-text locale overflow (German) | E2E-016 (visual regression) |
