# Test Design: 9.7 — TTS API（兼容 OpenAI Audio Speech）+ Doubao

2026-06-15 | Turing (QA) | Level: **Comprehensive** (security_sensitive=true)

> Designed against the **Architect-ratified contract** (`## Architect Review Results`, Wright, score 9.5/10) — the 7 OQ rulings + 3 low-issue resolutions are binding. Key amendments folded into the scenarios below: **`ComputeCost` REFACTORS to a `CostInput` struct** (not a 6th positional param) — token/ASR/per-call golden vectors MUST stay byte-identical; **per-1k-chars** granularity, char count = **runes** (`len([]rune(input))`); **EXACT pre-flight** `balance ≥ char_count×price` gate (stronger than ASR); **Volcano HTTP `query` one-shot, base64-in-JSON `data` field, auth `Authorization: Bearer;{token}` (semicolon)**; **`doubao-tts` no-alias**, capability flag `Speech`, voice set adapter-owned; **mp3/wav/opus only** (opus→`audio/ogg`); **`maxSynthesizedAudioBytes = 20 MiB`**, `maxSpeechBodyBytes = 64 KiB`, `maxSpeechInputChars = 4096`; **`SynthesizeResponse.character_count` DROPPED** (gateway bills from its own rune count — Low-1).

The P0 weight is higher than 9.6 (41 vs 26): three NON-NEGOTIABLE gate suites are front-and-centre — (a) PII no-leak over `input` text + synthesized audio, (b) money one-SoT incl. the **`CostInput` refactor zero-drift proof** (a money-path refactor is a new risk 9.6 did not carry), (c) capability-fence regression over ALL ids — plus the **first binary-response-integrity** lane. E2E is deliberately thin (1): per the toolchain limits ([[project_toolchain_env_limits]]) the wire/billing/adapter paths are exercised via in-process `httptest` + fake-upstream + proto round-trip at the integration level; a single OpenAI-SDK contract lane (E2E-001) pins the public shape. Shift-left favoured throughout.
