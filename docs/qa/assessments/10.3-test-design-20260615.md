# Test Design: 10.3 — TypeScript SDK（`@he-api/sdk`, drop-in OpenAI）

2026-06-15 | Turing (QA) | Level: **Comprehensive** (Epic-10 directive)

## Overview

Total: **40** | Unit: 14 (35%) | Integration: 24 (60%) | E2E: 1 (3%, live-gated) | Doc-gate: 1 (2%)
Priority: **P0: 16**, P1: 18, P2: 6
Blind Spot Scenarios: **8**

**Story shape (drives every scenario):** `@he-api/sdk` is a *pure-consumer* library — `Client extends OpenAI` (openai-node subclass, R-OQ-1), overriding only the constructor to inject He defaults. There is **no backend/proto/DB surface**. "Interface identity" is therefore tested as **inheritance fidelity** (the inherited surfaces still behave OpenAI-shaped after the He default-injection), not as a re-implemented HTTP client. All hermetic tests **inject a mock `fetch`** into the openai-node client (R-OQ-5) — **no real gateway**. The single live E2E is gated on `HE_API_TEST_GATEWAY_URL` (skip-if-unset).

**Drop-in oracle (REUSE):** `apps/api-gateway/tests/_protocol_invariants.py` shape assertions (`assert_chat_completion_shape`, `assert_chat_completion_chunk_shape`, `assert_embedding_shape`, `assert_error_envelope_shape`, `assert_model_entry_shape`, `REQUEST_ID_RE = ^req_[0-9a-f]{12}$`). The TS hermetic mocks must emit fixtures that satisfy these shapes so the wrapper is proven shape-faithful in the same terms as the gateway's own contract suite.

## Risk Coverage

No separate risk-profile was run (Comprehensive level, but `security_sensitive=false`, pure consumer). Implicit risk mapping:
- **Upstream-breakage risk** (openai-node major bump silently changing parse shapes) → `10.3-UNIT-003` pin-drift guard + every INT shape assertion.
- **Credential cross-wiring risk** (sending an OpenAI key to the He gateway, or vice-versa) → `10.3-UNIT-012`, `BLIND-BOUNDARY-001/002`.
- **False-billing risk** (treating `X-He-Cost-Usd` as authoritative) → `10.3-INT-023` (OQ5 guard).
- **Publish-footgun risk** (shipping `private:true`/`0.0.0` or leaking src) → `10.3-UNIT-002`, `10.3-INT-002`.

## Execution Order

1. **P0 Unit** — UNIT-001/002/003/010/011/012 (fail fast on packaging + resolution + pin)
2. **P0 Integration** — INT-001/002/003 (build/pack/types) then INT-010..016 (drop-in core + error passthrough)
3. **P1** — UNIT-004/005/006/013; INT-020..025; all 7 P1 [BLIND-SPOT]; E2E-001 (only if gateway URL set)
4. **P2** — UNIT-014; INT-030/031/032; DOC-001; RESOURCE-001
