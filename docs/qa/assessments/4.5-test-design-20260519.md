### Why "Comprehensive"

Decision 8B locks **Comprehensive** because:

- Rule 1 (Simple) fails: `complexity_indicators = 3 > 0`.
- Rule 2 (Standard) fails: `complexity_indicators = 3 > 2`.
- Rule 3 (Comprehensive) matches: `3 ≥ 3` → unit + integration + e2e mandated; risk profile required.
- Rule 4 (via `security_sensitive`) NOT triggered: `security_sensitive = false`.

Story 4.5 is the **architecturally most-novel** Epic-4 adapter to-date: it is the **first non-identity transform** in any Epic-4 translate.go (the `model` field bidirectional rewrite per BR-1.11). This introduces a NEW failure surface — endpoint-id misconfiguration (BR-1.12 fail-fast) — that does not exist in Stories 4.1-4.4. Comprehensive adds the **chaos suite** (Toxiproxy 7 REUSE Story-4.1..4.4 + NEW CHAOS-008 endpoint-id-not-configured per BR-1.12/BR-4.6), **contract suite** (`openai==1.40.*` skeleton — FOUR scenarios across 2 model ids × 2 paths), and an **opt-in e2e live suite** (`HE_API_DOUBAO_LIVE=1` per T4.2 — FOUR live scenarios) with an explicit round-trip assertion `response.model == request.model` (NOT the Volcengine endpoint id) per BR-1.11.
