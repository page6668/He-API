# Test Design: 2.7 — 账号注销与数据删除（30 天宽限期）

2026-06-16 | Turing (QA) | Level: **Comprehensive** (security_sensitive=true) | Round 1

## Overview

Total: **78** | Unit: 33 (42%) | Integration: 31 (40%) | E2E: 5 (6%) | Security: 9 (12%)
Priority: **P0: 47**, P1: 22, P2: 9
Blind Spot Scenarios: **18** (BOUNDARY 3 · ERROR 5 · FLOW 4 · CONCURRENCY 3 · DATA 2 · RESOURCE 1)

**Story type**: fullstack (Go auth-svc + api-gateway · TS console) → all 6 blind-spot categories in scope.

**Binding inputs from Architect Review Round 1 (Wright, 8.0/10, ratified)** — the design tests the *ratified* behavior, not the pre-review story text:
- **OQ-1 (RATIFIED)**: signin *authenticates* a `pending_deletion` user → yields a **recovery-only session** (console/business API blocked via `403_account_pending_deletion`; signin / recovery-page / cancel endpoints NOT blocked). → covered by AC4 + SEC scenarios.
- **OQ-2 (RATIFIED)**: cancel requires only a valid JWT (no fresh re-auth) — deliberate asymmetry vs delete. → 2.7-UNIT-020.
- **OQ-3 (RATIFIED-WITH-OVERRIDE)**: RETAIN-linked `recharge_orders`/`subscriptions`/`invoices`; **OVERRIDE for `payment_methods`** — sweeper MUST Stripe-detach the live off-session token then delete the row. → 2.7-INT-021 / 2.7-INT-022.
- **M-1**: `content_safety_logs` is **UNTOUCHED** (compliance §9.3, no users FK) — `security.md §8.3`'s literal "Delete content_safety_logs" is a doc bug; design asserts UNTOUCHED. → 2.7-INT-023.
- **M-3**: audit taxonomy is **37 → 40** (not 34 → 37 — Story 5.1 added 3 api_key events). → 2.7-UNIT-033.
- **m-4**: rate-limit code SHOULD be `429_rate_limit_account_delete` (registry convention). → 2.7-UNIT-039.

> **Single most error-prone area (Architect-flagged + design-prioritized)**: the sweeper **soft-deletes** (anonymizes) the `users` row, so `ON DELETE CASCADE` **does NOT fire** — PII-bearing children MUST be **explicitly** deleted. This is guarded by 2.7-INT-020 + the T8.2 reality matrix and is weighted P0.

## Toolchain Note (project memory)

`buf` / `atlas` / `docker` may not run locally (LC_UUID dyld abort / no daemon). Per project convention: hand-edit generated proto stubs **additively** + verify via round-trip; backend tests via **pgxmock + httptest** (Story 2.6 harness reuse); migration verified by SQL round-trip rather than live `atlas migrate apply`. AC5 INT-017/018/019 are therefore verified structurally (file + SQL inspection + drift-gate reasoning) where the live toolchain is unavailable — flagged so Dev/QA-review do not mistake a structural check for a live apply.
