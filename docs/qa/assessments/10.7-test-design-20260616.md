# Test Design: 10.7 — 上线检查表 + 监控告警 + 客服接入

2026-06-16 | Turing (QA) | Level: **Comprehensive** (security_sensitive=true · complexity 5/8)

> Designed against the **Architect-ratified contracts** (`## Architect Review Results`, Wright, score 9.5/10, 2026-06-16). All 6 OQ rulings + 2 low-issue resolutions are **binding** — every scenario below hangs off them:
> 1. **OQ-2 ZERO-PII HARD CONTRACT (highest-risk gate)** — the Intercom boot payload NEVER carries email/name/user_id/IP-identity/prompt/key/content; the **only** permitted identifier is the non-PII `he_request_id` handle (§11.5). The Identity-Verification HMAC seam is **BUILD-but-DORMANT** (secret server-only, disabled by default). PRC-region users are **region-gated** away from Intercom to an in-region channel (飞书/email); Intercom serves the international authed face only. ⚠️ PII-bearing widening is **PO-gated** — out of this story's auto-scope.
> 2. **OQ-1 Alertmanager** — inline `alertmanager.config` route tree in `kube-prometheus-stack` values (lintable, gold-gated, NOT a CRD); receiver secrets via **ExternalSecret→Vault `kv/data/he-api/alerting/*`** mounted by `alertmanagerSpec.secrets`, referenced via `routing_key_file`/`api_url_file`; **P0 dual-channel** = `severity=critical → PagerDuty + 飞书 mirror` (`continue:true`); explicit **non-blackhole catch-all** mandatory; `verify-alertmanager-routes.sh` gold-gate asserts `critical→pagerduty` + catch-all.
> 3. **OQ-5 RULE IN** — build `infra/helm/api-gateway/templates/prometheusrule.yaml` with the 4 §11.3 RED rules; `DataExportSuspect` (境外 egress>0, crit·pagerduty) is the **§9.1 runtime sentinel that backstops the OQ-2 egress contract**.
> 4. **OQ-4 SDK first-release** — build the OIDC trusted-publishing pipeline; **CI runs dry-run ONLY** (`twine check`/`npm pack`/tag-validation), **never a real publish**. Real publish is **PO-gated** (name ownership + OIDC creds), outside auto-scope.
> 5. **OQ-3** — `docs/runbooks/go-live-checklist.md` doc-primary + lightweight `scripts/ci/` verifier (machine-checkable items only); synthetic-page drill = **runbook manual operator step**.
> 6. **OQ-6** — console **authed face only**; marketing/anonymous deferred → no consent-gate this story.
> 7. **L-1** — `*_file` secret-ref needs Alertmanager ≥ 0.26; confirm pinned image else fallback (templated Secret + envsubst). **L-2** — `he_request_id` validates against the EXACT shared regex `^req_[a-f0-9]{12}$` (reuse §11.5, don't re-declare).

The P0 weight (20) is dominated by **three non-negotiable security/compliance gate-suites** that define this launch-readiness story: (a) **ZERO-PII to Intercom** (OQ-2 — the highest-risk compliance gate; a single leaked attribute = a PIPL §9.1 data-egress incident), (b) **secret no-leak everywhere** (`INTERCOM_SECRET` / PagerDuty routing key / 飞书 / Slack webhooks never in bundle/git), and (c) **alert-route integrity** (`critical→pagerduty` gold-gate + dual-channel + non-blackhole catch-all — route drift = silent P0 loss = launch-grade incident). Plus the **irreversible-action guard** (SDK release dry-run only) and the **`DataExportSuspect` runtime egress sentinel** that backstops OQ-2.

**Toolchain note (binding constraint, [[project_toolchain_env_limits]]):** the local env cannot run `helm`/`buf`/`atlas`/`docker`. So Helm-render + PrometheusRule-syntax + Alertmanager-config (the `L` lane) are verified by **YAML parse + structural assertions where the toolchain allows**, else by the existing **`helm-lint-observability` matrix in `.github/workflows/infra-lint.yml`** (CI) + documented Dev follow-up. The `verify-alertmanager-routes.sh` gold-gate is a **bash/bats** test (runs locally). The console HMAC seam + zero-PII boot payload are genuinely **node-`crypto`/jsdom unit-testable** locally. The synthetic-page drill (E2E-001) is an **operator manual step** by ruling (OQ-3) — not a CI lane.

**Skeleton-as-tables (deliberate, multi-runtime):** the task's Output-2 executable skeleton is a TS/JS artifact, but 10.7 spans **YAML (Helm) + bash (gold-gate) + GitHub Actions (release) + Markdown (runbook) + a TS island (console)**. A TS skeleton referencing not-yet-created console components would fail `next build`/`lint` and break the console lane (same compile-safety reason 8.5/9.7 delivered tables). So the executable scenarios are delivered as the **white-box tables below** + a compact **Test Specs** backfill in the story Tasks. Dev implements one test per scenario id next to the code (console: `*.test.ts`; infra: bats + CI lint; workflow: dry-run); QA verifies one-per-id at `*review`.

## ▶ P0 Tranche (execute first — 20 scenarios · fail fast on the HARD gates)

P0 = **OQ-2 zero-PII / region-gate / dormant-HMAC**, **secret no-leak**, **alert-route integrity (critical→pagerduty gold-gate + dual-channel + non-blackhole)**, **PagerDuty/Slack payload no-PII**, the **`DataExportSuspect` egress sentinel**, the **SDK irreversible-publish guard**, and the **no-new-gateway-surface** regression fence.

### AC2 — Intercom 客服 · ZERO-PII + region-gate + dormant HMAC (HIGHEST RISK)

| ID | Lvl | Scenario | Why P0 |
|----|-----|----------|--------|
| 10.7-UNIT-010 | U | **ZERO-PII boot payload (HARD, property test)**: for ANY user/session input, the serialized Intercom `boot`/`update` object contains **no** email / name / user_id / IP-identity / prompt / key / user content; the ONLY identifier is `he_request_id` (or none) | OQ-2 hard contract · §9.1 数据不出境 — one leaked attr = egress incident (BR-10.7.7) |
| 10.7-UNIT-011 | U | **`INTERCOM_SECRET` server-only**: secret is read ONLY inside the BFF route/server-action module; a bundle scan asserts it NEVER appears in any client chunk or `NEXT_PUBLIC_*` | OQ-2 · BR-10.7.8 — secret in bundle = security incident |
| 10.7-UNIT-012 | U | **HMAC seam DORMANT by default**: in zero-PII mode (default) Identity Verification is disabled — boot sends no `user_hash`, the BFF hash path is not invoked; activates only via explicit approved config flag | OQ-2 dormant — capability built, not active (BR-10.7.8) |
| 10.7-UNIT-013 | U | **PRC region-gate**: a PRC-region request → Intercom does **not** boot (no widget, no snippet egress); user routed to in-region channel (飞书/email) | OQ-2 region-gate — even anon session egresses IP/cookies (PIPL) (BR-10.7.7) |
| 10.7-UNIT-014 | U | **HMAC correctness (built-but-dormant)**: when enabled, `user_hash = HMAC-SHA256(INTERCOM_SECRET, user_id)` over the **immutable** id (user_id, NOT email); golden vector byte-stable; secret never returned to client | OQ-2 · BR-10.7.8 — anti-impersonation correctness for the future approved path |
| 10.7-INT-010 | I | BFF `/api/intercom-hash` route (or `_actions/intercom.ts`): secret read server-side, response is `{user_hash}` only (no secret echo); route is unreachable/404 while the identity-bearing path is unapproved | OQ-2 · BR-10.7.8 — server seam isolation |
