# Test Design: 9.1b — 用量趋势图（`<UsageChart>` + `/v1/me/usage/series`）

2026-06-15 | Turing | Level: **Standard** | Story status at design: AwaitingTestDesign

## Overview

Total: **33** | Unit: 20 (61%) | Int: 12 (36%) | E2E: 1 (3%)
Priority: **P0: 1**, P1: 25, P2: 7
Blind Spot Scenarios: **10** (BOUNDARY 4 · ERROR 2 · FLOW 2 · DATA 1 · RESOURCE 1)

**Design intent.** 9.1b is a strict, pre-specified subset of 9.1 (fast-follow). It adds exactly ONE endpoint (`GET /v1/me/usage/series`), ONE component (`<UsageChart>`, the first Recharts realization), ONE Server Action, ONE Zod schema — no new tables/migration/Kafka/PG DDL. Testing therefore concentrates on (a) the **P0 IDOR fence** on the new endpoint — the highest-stakes rule (BR-CH-SERIES-3), (b) **aggregation correctness** (hourly_agg day-rollup ties to raw rows), and (c) **chart resilience** (empty/error/a11y/RTL) so the new chart never degrades the shipped 9.1 `<UsageStatCards>` band.

> **Cost-SoT note (carried from 9.1 H-1-R).** SM default = primary series is `requests` (ClickHouse volume store); **no `cost_usd` series in 9.1b**. The `cost_usd` field is shape-parity only. If Architect rules Q-SERIES-COST IN, scenarios `9.1b-INT-009` / `9.1b-UNIT-015` (greyed below) activate and MUST read PG `usage_ledger` per bucket — never `request_logs.cost_usd` (always 0). They are authored but marked CONDITIONAL.

## Scenarios by AC

### AC1: `GET /v1/me/usage/series` (JWT-cookie, per-user isolation)

| ID | Lvl | Pri | Test | Why |
|----|-----|-----|------|-----|
| 9.1b-INT-005 | I | **P0** | **IDOR fence**: user A's token returns ONLY A's buckets; every query carries `WHERE user_id=$JWT.sub`; B's rows never leak across any `group_by` | BR-CH-SERIES-3 — highest-stakes rule; extends 9.1 `TestIDORFence` to `/series` |
| 9.1b-INT-001 | I | P1 | `group_by=day` → one bucket per calendar day (hourly_agg→day), `key=null`; response `{range,group_by,series:[{bucket,key,requests,total_tokens,cost_usd}]}` | AC1 core shape + day rollup |
| 9.1b-INT-002 | I | P1 | `group_by=model` → buckets keyed by model (one logical line per model) | AC1 core By Model |
| 9.1b-INT-003 | I | P1 | `group_by=status` → buckets keyed by status class (2xx vs 4xx/5xx) reading `request_logs` | AC1 core By Status (reads raw, not agg) |
| 9.1b-INT-004 | I | P1 | day bucketing honours `users.timezone` (Q-TZ parity with `/summary`); boundary day rows land in the correct local-day bucket | tz-correct bucketing; reuses 9.1 period helper |

## Blind Spot Scenarios [BLIND-SPOT]

| ID | Category | Pri | Scenario | Ref |
|----|----------|-----|----------|-----|
| 9.1b-BLIND-BOUNDARY-001 | BOUNDARY | P1 | No usage history → `series:[]` empty array, HTTP 200 (NOT an error) | BOUNDARY-001 |
| 9.1b-BLIND-BOUNDARY-002 | BOUNDARY | P1 | `range=91d` (just beyond the 90d cap) → `400_invalid_request` | BOUNDARY-004 |
| 9.1b-BLIND-BOUNDARY-003 | BOUNDARY | P2 | `range=0d` / empty `range` value → `400` or documented default | BOUNDARY-002 |
| 9.1b-BLIND-BOUNDARY-004 | BOUNDARY | P1 | Empty history in chart → EmptyState "No usage in the last 30 days"; no NaN-axis / no broken Recharts render | BOUNDARY-001 |
| 9.1b-BLIND-ERROR-001 | ERROR | P1 | CH query fails mid-request → `503` envelope AND the read-only CH pool connection is returned (no leak) | ERROR-002 + RESOURCE-001 |
| 9.1b-BLIND-ERROR-002 | ERROR | P1 | `/series` 5xx → inline chart-card retry; the shipped 9.1 `<UsageStatCards>` band STAYS rendered (degradation isolation) | ERROR-002 + BR-CH-4 |
| 9.1b-BLIND-FLOW-001 | FLOW | P1 | Keyboard-only toggle operable (Tab to group, Arrow/Enter to switch); focus visible | FLOW (a11y nav) |
| 9.1b-BLIND-FLOW-002 | FLOW | P2 | Rapid toggle (By Model→Status→Day in quick succession) → only the latest `group_by` series renders (no stale-response race) | FLOW-002 / CONCURRENCY-004 stale data |
| 9.1b-BLIND-DATA-001 | DATA | P1 | By Model rollup: each model's daily bucket sum ties exactly to its raw `request_logs` rows | DATA-002 |
| 9.1b-BLIND-RESOURCE-001 | RESOURCE | P2 | CH pool connection returned to the pool after a query error; reuses 9.1's pool (no second CH path opened) | RESOURCE-001 + BR-CH-SERIES-1 |

**Minimum-coverage check**
- BOUNDARY per input field: `group_by` (UNIT-002), `range` (UNIT-003, BLIND-BOUNDARY-002/003), history-volume (BLIND-BOUNDARY-001/004) ✓
- ERROR per external dependency: ClickHouse (INT-006, BLIND-ERROR-001), `/series` HTTP (BLIND-ERROR-002) ✓
- FLOW per multi-step process: toggle interaction (BLIND-FLOW-001/002) ✓

## Risk Coverage

No formal risk-profile exists (Standard level, no `*risk-profile` run — Architect ruled review NOT_REQUIRED). Implicit risks mapped:

| Risk | Mitigated by |
|------|--------------|
| Cross-user data leak (IDOR) — highest stakes | `9.1b-INT-005` (P0), `9.1b-E2E-001` |
| Wrong aggregation (trend misleads users) | `9.1b-INT-007`, `9.1b-BLIND-DATA-001` |
| Cost-SoT regression (showing non-authoritative cost) | SM default no-cost-series; conditional `9.1b-INT-009` reads `usage_ledger` only |
| New chart breaks the shipped dashboard | `9.1b-BLIND-ERROR-002` (degradation isolation) |
| Inaccessible chart (WCAG fail) | `9.1b-UNIT-012/013`, `9.1b-BLIND-FLOW-001` |
