# Story 2.3 — OWASP ASVS L2 Compliance Checklist

**Story:** 2.3 OAuth — Google / GitHub
**Standard:** OWASP ASVS v4.0.3 — Level 2 (Standard)
**Date:** 2026-05-13
**Author:** Linus (Dev) — QA review round 1, QA-2.3-M5
**Reviewer:** Turing (QA) — re-review on `*review 2.3`

## Scope

Story 2.3 is flagged `security_sensitive=true` in SM Decision 8B (test-design level Comprehensive). The risk profile (`docs/qa/assessments/2.3-risk-20260513.md` §"Compliance Mapping") lists 6 ASVS L2 controls that map directly to AC4 + the OAuth identity-federation surface. This checklist signs each off with explicit pass/fail evidence per item.

Items follow ASVS chapter notation: `V<chapter>.<section>.<requirement>`.

## V2 — Authentication Verification Requirements

### V2.5 — Credential Recovery Verification Requirements

| Req | Description | Status | Evidence |
|-----|-------------|--------|----------|
| V2.5.1 | System-generated initial passwords or activation codes SHOULD be securely randomly generated, SHOULD be at least 6 characters long, and MAY contain letters and numbers, and expire after a short period of time. | **PASS** | OAuth flow issues no initial passwords. New OAuth users have `password_hash=NULL` (Story 2.3 AC3 Branch C: `apps/auth-svc/internal/repository/users.go::UpsertOAuthUser`). Verified by `repository.users_test.go::TestUpsertOAuthUser_NullPasswordHash` (`apps/auth-svc/internal/repository/users_test.go`). |
| V2.5.4 | Shared or default accounts are not present (e.g. "root", "admin", or "sa"). | **PASS** | No shared/default OAuth-linked accounts created by the system. Branch C INSERT path requires a provider-verified email; no system-bootstrap path exists. |
| V2.5.7 | Password reset and verification flows do not reveal whether the email is registered. | **PASS** | OAuth callback applies anti-enumeration (Story 2.2 m-5 ruling reused): `ErrAuthenticationFailed` masks the `pending_deletion` + `suspended-after-link` branches per `apps/auth-svc/internal/oauth/linking.go::handleBranchA` and `::handleBranchB`. Identical 401 response for "email not found" and "account in non-active state". |

### V2.7 — Out of Band Verifier Requirements

| Req | Description | Status | Evidence |
|-----|-------------|--------|----------|
| V2.7.1 | Clear text out of band (NIST "restricted") authenticators, such as SMS or PSTN, are not offered for account recovery. | **PASS** | OAuth identity assertion delivered over TLS via the provider authorize→callback round-trip; no SMS/PSTN. ID-token signature verified against the published JWKS (`apps/auth-svc/internal/oauth/google.go::verifyIDToken`). |
| V2.7.2 | Out of band verifier expires out of band authentication requests, codes, or tokens after 10 minutes. | **PASS** | OAuth state TTL is 600s (10 min) — `apps/auth-svc/internal/handlers/server.go::oauthStateTTL` + `apps/auth-svc/internal/oauth/state.go::TestConsumeState_Expired`. PKCE verifier shares the same TTL window (stored alongside state). |
| V2.7.6 | The verifier does not store an unencrypted version of the authenticator at rest. | **PASS** | Provider client secrets stored in K8s Secret `he-api-auth-jwt-keys` (out of band of the application config); ID-token and access-token from the provider are never persisted — they're exchanged for our own JWT and the originals are discarded after the callback request returns. |

## V3 — Session Management Requirements

### V3.2 — Session Binding Requirements

| Req | Description | Status | Evidence |
|-----|-------------|--------|----------|
| V3.2.1 | The application generates a new session token on user authentication. | **PASS** | New `he_access` + `he_refresh` cookies issued on every successful OAuth callback (`apps/auth-svc/internal/handlers/server.go::CompleteOAuth` lines 1500-1515). Refresh family ID rotates per session per BR-3.9. |
| V3.2.2 | Session tokens possess at least 64 bits of entropy. | **PASS** | JWT JTI is `uuid.NewRandom()` (122 bits of entropy per RFC 4122 §4.4). OAuth state ID is `crypto/rand` 32 bytes hex-encoded (256 bits) per `apps/auth-svc/internal/oauth/state.go::NewState`. |
| V3.2.3 | The application only stores session tokens in the browser using secure methods such as appropriately secured cookies (see section V3.4) or HTML 5 session storage. | **PASS** | `he_access` + `he_refresh` set with `HttpOnly; Secure; SameSite=Lax` per `apps/api-gateway/internal/handlers/cookies.go::SetAccessCookie` / `SetRefreshCookie`. `he_oauth_state` follows the same pattern (`apps/api-gateway/internal/handlers/oauth.go::setOAuthStateCookie`). |

### V3.5 — Token-based Session Management

| Req | Description | Status | Evidence |
|-----|-------------|--------|----------|
| V3.5.1 | The application allows users to revoke OAuth tokens that form trust relationships with linked applications. | **DEFERRED** | Account-unlinking flow lands in Story 2.5 (resource management); tracked in Epic 2 backlog. Not in scope for Story 2.3 (BR-2.5 explicitly defers). |
| V3.5.2 | The application uses session tokens rather than static API secrets and keys, except with legacy implementations. | **PASS** | No static API keys involved in OAuth flow. Provider client_id/client_secret stored in K8s Secret; rotated independently of user sessions. |
| V3.5.5 | If the JWT scheme is used, "alg=none" or algorithm confusion attacks MUST be prevented. | **PASS** | `apps/auth-svc/internal/jwt/jwt.go::Verifier.Verify` keyfunc rejects any `alg` other than RS256 with `ErrInvalidAlgorithm`. Test `jwt_test.go::TestVerify_RejectsHS256_AlgConfusion` pins this (2.2-UNIT-115). Story 2.3 reuses the same Verifier for the new OAuth access tokens. |

## V5 — Validation, Sanitization and Encoding Verification Requirements

### V5.1 — Input Validation

| Req | Description | Status | Evidence |
|-----|-------------|--------|----------|
| V5.1.5 | The application has defenses against HTTP parameter pollution attacks, particularly if the application framework makes no distinction about the source of request parameters (GET, POST, cookies, headers, or environment variables). | **PASS** | `return_to` allow-list validation runs against `r.URL.Query().Get("return_to")` (singular extraction; Go's net/http `Get()` returns the first value only, eliminating ambiguity). `apps/api-gateway/internal/handlers/oauth.go::Initiate` + `Callback` both validate against `IsAllowedReturnTo`. Test `oauth_redirect_test.go::TestIsAllowedReturnTo` (2.3-UNIT-050..059) covers production/staging/dev matrix + relative path edge cases. |

## V8 — Data Protection Verification Requirements

### V8.3 — Sensitive Private Data

| Req | Description | Status | Evidence |
|-----|-------------|--------|----------|
| V8.3.4 | Verify that all sensitive data is identified and classified into protection levels. | **PASS** | OAuth audit payloads carry hashed PII only (BR-3.9 / BR-4.5): `email_hash` (SHA-256 of normalised email), `subject_hash` (SHA-256 of provider subject), `ip_hash` (SHA-256 of IPv4 /24 or IPv6 /64 prefix), `ua_hash` (SHA-256 of full UA string). Verified via `apps/auth-svc/internal/handlers/server.go` (post QA review round 1 — all 12 OAuth event emissions populate EmailHash + Metadata.subject_hash) + `apps/auth-svc/internal/oauth/state.go::HashClientIP / HashUserAgent / HashSubject`. |

## V11 — Business Logic Verification Requirements

### V11.1 — Business Logic Security

| Req | Description | Status | Evidence |
|-----|-------------|--------|----------|
| V11.1.1 | The application will only process business logic flows for the same user in sequential step order and without skipping steps. | **PASS** | OAuth state ID is single-use: `apps/auth-svc/internal/oauth/state.go::ConsumeState` uses Redis `GETDEL` (atomic), guaranteeing each state value can only be redeemed once. Replay → `ErrStateNotFound` → 400 oauth_state_invalid. Verified by `apps/auth-svc/internal/oauth/state_test.go::TestConsumeState_SingleUse`. |
| V11.1.2 | The application will only process business logic flows with all steps being processed in realistic human time, i.e. transactions are not submitted too quickly. | **PASS** | Ratelimit applied on both initiate (`auth.oauth.initiate.{ip}`) and callback (`auth.oauth.callback.{ip}`) paths per BR-4.4 — 30 req/60s/IP. Enforced by `apps/api-gateway/internal/middleware/oauth_ratelimit.go::OAuthRateLimit` + Redis token bucket. Test `oauth_ratelimit_test.go::TestRateLimit_BlocksAfterBurst` covers the 31st-request 429 boundary. |
| V11.1.5 | The application has business logic limits or validation to protect against likely business risks or threats, identified using threat modeling or similar methodologies. | **PASS** | All 23 risks from `docs/qa/assessments/2.3-risk-20260513.md` mapped to either implemented mitigations (P0 risks) or documented deferrals (Story 2.5 unlinking, Story 2.4 2FA). SEC-001 / SEC-002 / SEC-006 (the 3 High risks) all have mitigation tests at the appropriate level (this story's test design covers them via the SEC-A0x scenarios). |
