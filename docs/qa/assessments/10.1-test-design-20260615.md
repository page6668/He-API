# Test Design: 10.1 — 控制台 10 种语言翻译落地

2026-06-15 | Turing (QA) | Level: **Comprehensive**

> Scope contract (Architect-ratified, Wright 2026-06-15): mechanism (T1 wiring + T3 RTL + tests) is the critical path; T2's 1720 translations may batch in follow-up PRs gated only by `check-i18n-keys` parity + ar-native-review (launch gate). **AC2 "correct" = layout/direction correctness** (RTL mirror, LTR islands, icon flip) — explicitly decoupled from ar prose linguistic quality (that → Epic-10 launch gate 10.7/10.8). This design tests **mechanism, not translation fluency**.

## Overview

Total: **29** | Unit: 11 (38%) | Integration: 7 (24%) | E2E: 11 (38%)
Priority: **P0: 9**, P1: 14, P2: 6
Blind Spot Scenarios: **6** (BOUNDARY 4, ERROR 1, FLOW... see §Blind Spot — 4 BOUNDARY-class / 1 ERROR / 2 FLOW counted across levels)

Story type = **Frontend UI** → high-priority blind-spot categories: BOUNDARY, FLOW, ERROR (CONCURRENCY/DATA medium — story is pure-frontend, no DB/proto/cross-service, so DATA/RESOURCE/CONCURRENCY largely N/A).

## Risk Coverage

No formal risk-profile artifact for 10.1 (SM complexity 2/8, `security_sensitive=false`). Implicit top risks and their mitigating scenarios:

| Risk | Mitigated by |
| --- | --- |
| Linchpin wiring still partial → bare keys in prod (the gap this story exists to close) | 10.1-UNIT-001/002, **10.1-INT-001** |
| Re-miss: a future namespace silently un-wired again | 10.1-INT-002 (namespaces.ts SoT) |
| Placeholder/key drift slips past CI | 10.1-UNIT-003/004/005, BLIND-BOUNDARY-002 |
| RTL layout breaks (physical classes) | 10.1-UNIT-008, 10.1-E2E-004 |
| Numbers/IDs garbled in ar | 10.1-E2E-005, BLIND-BOUNDARY-003 |
| 250KB first-load budget blown by all-ns load | 10.1-INT-004 |
| Pre-existing HEAD failures wrongly attributed (memory: auth-surface-prebroken-head) | Per-file verification; baseline recorded in T0.2/T0.3 — not a scenario, an execution discipline |

> Fail-fast: if any P0 fails, halt — the linchpin (INT-001) or RTL core (E2E-004) is the story's reason to exist.

## Coverage Validation

- Every AC has ≥1 test: AC1 ✓ (16 scenarios), AC2 ✓ (11 scenarios), cross-AC ✓ (INT-006).
- No duplicate coverage: wiring tested once at unit (config purity) + once at integration (real SSR path) = defense-in-depth on the linchpin, justified.
- Critical paths multi-level: linchpin (unit+int), RTL (unit audit + e2e visual).
- Blind spots: BOUNDARY on locale-route + ICU + ar-LTR inputs; ERROR on namespace-load failure; FLOW on switch-replay/toggle. CONCURRENCY/DATA/RESOURCE intentionally minimal — pure-frontend story, no shared mutable state / DB / connections.
