**Test levels** (Decision 8B): `unit, integration, contract`. No browser/E2E-UI — this story is **backend-only** (Q-FE: the Console toggle is a deferred story). "E2E" here = a service-level cron→read flow over a scratch PG / testcontainers, not a UI journey.

**Mocking posture** (Dev Notes / [[project_toolchain_env_limits]]): `pgxmock` (plain `pgxpool`, no otelpgx) for the gateway PG read + the cron INSERT; an `httptest.Server` as the fake FX upstream for the `FxProvider` (timeout / non-2xx / malformed / zero-rate injection); `FX_MANUAL_USD_CNY` for the deterministic dev/CI rate. `buf`/`atlas`/`docker` abort locally → the `0009` migration round-trip runs on a scratch PG in CI; the CronJob manifest + `verify-cron-schedule.sh` are asserted by static fixture parse, not a live cluster.

### Money-display correctness lanes (Decision 8B, all covered)

This story holds money-**display** correctness to the same rigour as a money invariant even though it is read-only: a wrong / silently-stale / float-drifted rate is a money defect.

| Lane | Where |
|------|-------|
| (a) conversion accuracy — golden vector, HALF-UP 2dp, 8dp rate precision | AC1: UNIT-001, UNIT-006 |
| (b) rounding boundary — HALF-UP at `.xx5` → up (never half-even / down) | AC1: UNIT-002, BLIND-BOUNDARY-003 |
| (c) **Decimal-not-float** (M-1 cascade) — float-slip vector byte-exact under `shopspring/decimal` | AC1: UNIT-005 |
| (d) zero / large / negative-bound balance | AC1: UNIT-003, UNIT-004, UNIT-009 |
| (e) **SoT-preservation (CRITICAL)** — RMB reads never mutate `balances.*` / `usage_ledger`; 7.1 reconciliation byte-identical | X-AC: INT-018, BLIND-DATA-001 |
| (f) **stale-serve** — provider down ⇒ no insert, last row served, never a zero/null rate | AC2: INT-021…024, BLIND-ERROR-002…004 |
| (g) money discipline — every money + rate field a string-decimal, never a JSON number | AC1: INT-007, INT-012, UNIT-005 |
| (h) back-compat — USD-default endpoints byte-compatible with the 7.1 contract | AC1: INT-001, INT-008, CONTRACT-001 |
| (i) cron determinism — `0 0 * * *` UTC, append-only, idempotent at day granularity, latest-row read | AC2: INT-026, INT-028 |
| (j) provider isolation — provider NEVER on the read hot path | AC1: UNIT-012; AC2: BLIND-RESOURCE-001 |

### Architect-ruling assertions folded in (all 12 Q-* RATIFIED; H-1/H-2/M-1/M-2 are load-bearing)

- **Q-SOT (display-only, single USD SoT)** → `7.2-INT-018` is the gating CRITICAL test (chat→deduct→reconcile with RMB reads interleaved → byte-identical), reinforced by `7.2-BLIND-DATA-001`.
- **H-1 (dedicated cron binary, NOT a server subcommand)** → `7.2-INT-030` asserts the CronJob targets `apps/billing-svc/cmd/fx-refresh` (own `main` + Dockerfile + Helm image), no HTTP server stack in the cron pod (5.4 precedent parity).
- **H-2 (cron hardening + CI gate + image)** → `7.2-INT-028` asserts the hardening fields (`concurrencyPolicy: Forbid`, `startingDeadlineSeconds: 200`, `backoffLimit: 0`, history limits `3`, `timeZone: Etc/UTC`); `7.2-INT-029` asserts `scripts/ci/verify-cron-schedule.sh` locks the new `0 0 * * *` literal.
- **M-1 (`400_unsupported_currency` runtime mirror)** → `7.2-UNIT-013` asserts the code is registered in `apps/api-gateway/internal/openaierr.CodeMetadata` as `invalid_request_error` (Story-3.6 single-canonical-writer rule), not only in the §5.1.2 spec table.
- **M-2 (mixed-currency `by_model` payload)** → `7.2-INT-010` asserts the documented MVP cut: `total_cost_display` converted to RMB top-line while `by_model[].cost_usd` stays USD on `?currency=rmb`.
- **Q-FXSRC ADD (bounded fetch)** → `7.2-UNIT-018` asserts the provider call carries a hard `context` deadline — stale-serve correctness depends on a bounded fetch.
- **L-1 (explicit active-rate read)** → all latest-rate reads are spelled `ORDER BY fetched_at DESC LIMIT 1` per `(base,quote)` (mirrors `model_pricing` latest-`effective_at`), never a `MAX()` subquery — asserted in UNIT-010 / INT-020.

## Risk Coverage

No standalone `7.2-risk-profile` doc (test-design subsumes it under Comprehensive). The dominant risk per Story Metadata is a **money-correctness fork** (RMB mis-modelled as a second SoT) + **money-display defects** (wrong / silently-stale / float-drifted rate), mapped:

| Risk | Mitigating scenarios |
|------|----------------------|
| SoT fracture — RMB becomes a 2nd accounting truth | **INT-018 (CRITICAL)**, BLIND-DATA-001 |
| Wrong-rate display (float drift / bad rounding) | UNIT-001/002/005/006, BLIND-BOUNDARY-003 |
| Silently-stale rate (provider down, user unaware) | INT-021…024, INT-017 (`fx_degraded`), `fx_as_of` exposure (INT-002), BLIND-ERROR-002…004 |
| Zero/null rate persisted or served | INT-024, UNIT-020 |
| Back-compat break for existing 7.1 clients | INT-001/008, CONTRACT-001, UNIT-007 |
| Cron schedule drift on a money cron | INT-028/029 (H-2) |
| Provider latency leaks onto the read hot path | UNIT-012, BLIND-RESOURCE-001 |
| New secret leaked in logs | UNIT-019 |
