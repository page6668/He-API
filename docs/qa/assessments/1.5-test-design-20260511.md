### Test-Level Interpretation for Service-Template Stories

Story 1.5 delivers a **scaffolding toolchain + template files + first dogfood consumer + CI matrix refactor**. Unlike 1.4 (mostly config), the bulk of 1.5 is generative: `.tmpl` source files consumed by a Bash tool to produce 7 atomically-installed targets in a fresh service. The pyramid therefore tilts toward Unit (static text/regex on template source + generated dogfood artefacts), with Integration on the cross-workspace toolchain (`go build` / `golangci-lint` / `buf lint` / `buf generate` drift / `helm lint` / `kubeconform`) and E2E on the 5-minute SLA + staging observability evidence.

| Level | Coverage Strategy |
|-------|-------------------|
| Unit | Vitest scenarios parsing the Bash scaffolder (`scripts/scaffold-svc.sh`), each `.tmpl` under `scripts/scaffold-svc/templates/`, the Buf toolchain (`packages/proto/buf.yaml` / `buf.gen.yaml` / `.gitignore`), the observability shared package (`packages/go-observability/{go.mod,tracer.go,logger.go,http.go,*_test.go}`), the dogfood service tree (`apps/sample-grpc-app/*` + `infra/helm/sample-grpc-app/*` + `packages/proto/he/sample/v1/sample.proto` + `packages/proto/gen/go/he/sample/v1/*.pb.go`), and the CI/workspace registration changes (`.github/workflows/build-images.yml` matrix, `.github/workflows/infra-lint.yml` `helm-lint-services` job, `go.work`, `README.md`). Assertions encode every Architect Round 1 ruling (Q1–Q8) and minor cleanup (m-1…m-5) as a literal file:regex check, matching the `deliverable_bindings` convention already established by SM/Architect for 1.4. Runnable locally via `pnpm test`. |
| Integration | (a) PR-driven scenarios on `.github/workflows/test.yml` + `.github/workflows/infra-lint.yml`: cross-workspace `go build` / `go test` / `go vet` / `golangci-lint run ./...`, `buf lint`, `buf generate && git diff --exit-code packages/proto/gen/` (Q4 drift), `helm lint` per matrix entry, `kubeconform -strict` per rendered chart, `bash -n scripts/scaffold-svc.sh` syntax check. (b) Self-test (T8/T9): scaffold a `_throwaway` service in CI and run full toolchain against it. (c) Idempotency + negative argument flows: re-scaffold same name fails non-zero, invalid `--name` / `--domain` regex rejected, missing args print usage. Evidence = GitHub Actions PR run links + `docs/dev/logs/1.5-dev-log.md` §Integration. |
| E2E | Single-shot Dev execution against the staging ACK cluster retained from 1.3/1.4 (Q4 ruling, retention_status carried over). Not auto-runnable. |

> **Architectural note (template-files-as-deliverables)**: Story 1.5's primary artefacts are `.tmpl` files **plus** their first concrete render (the dogfood `apps/sample-grpc-app/` tree generated by running `scripts/scaffold-svc.sh --name sample-grpc-app --domain sample`). Wherever scenarios overlap (e.g., "Dockerfile.tmpl uses `gcr.io/distroless/static-debian12`" vs "`apps/sample-grpc-app/Dockerfile` uses same"), both are asserted: the `.tmpl` for design intent, the rendered file for proof-of-execution. This dual assertion is the cheapest possible drift guard for the 14 Epic 2-10 services that will inherit from 1.5.
