### Test-Level Interpretation for Frontend-Foundation Stories

Story 2.1 delivers a **frontend application skeleton** (Next.js 14 App Router + next-intl 3.x + 10-locale messages + LocaleSwitch + codegen pipeline + CI gates). Unlike 1.6 (infrastructure-as-code with managed-DB runtime in cloud), 2.1's primary artefacts are **TypeScript/React source files that ship a runnable Next.js app**. The pyramid therefore lands roughly 66/13/12/9 (Unit/Int/E2E/Blind-Spot):

| Level | Coverage Strategy |
|-------|-------------------|
| Unit | Vitest (`jsdom`) scenarios cover (a) the `i18n/config.ts` static contract (`locales` tuple length 10 + alphabetic order + `defaultLocale='en'` + `fallbackMap` 4 entries + `isLocale` type guard + `Locale` literal union); (b) `lib/i18n.ts` pure helpers (`isRtlLocale` over 10 MVP + 4 RTL placeholders, `resolveLocale` over 5 negotiation paths, `buildLocaleCookieOptions` over 3 envs); (c) `messages/{locale}/common.json` × 10 locale × 19 keys structural integrity + ICU plural branch counts (en `=0/=1/other`, zh-CN `other`, ar `zero/one/two/few/many/other`); (d) `LocaleSwitch.tsx` component rendering + ARIA + keyboard navigation + Server Action mock invocation; (e) `app/[locale]/page.tsx` Demo render smoke + `not-found.tsx` 404 render; (f) Server Action `setLocale` validation + cookie option set per env; (g) `scripts/gen-i18n-keys.ts` codegen output regex; (h) `scripts/check-i18n-keys.ts` algorithm — happy + 4 failure modes. Static skeleton-file scenarios assert deliverable existence + regex on raw source text (low cost, fastest feedback, regression-stable). Runnable locally via `pnpm --filter @he-api/console test`. |
| Integration | (a) next-intl SSR contract: spin up Next.js test runtime (`next dev` in test mode or `next build` + `next start`), `fetch` four representative locale paths (`/en/`, `/zh-CN/`, `/ja/`, `/ar/`), assert `200 OK` + `<html lang="...">` + `<html dir="...">` + i18n-rendered `<h1>` text matches `messages/{locale}/common.json` `demo.title`. (b) Middleware behavior: simulate `Accept-Language` header + cookie + un-prefixed paths (`/about`), assert `302 Location: /{negotiated_locale}/about` + `Set-Cookie` semantics per Q4 ruling. (c) CI integration: invoke `scripts/gen-i18n-keys.ts` against fixture `messages/`, assert generated `.ts` output matches expected union literal; invoke `scripts/check-i18n-keys.ts` against (i) clean fixture (exit 0), (ii) missing-key fixture (exit 1 + diff output), (iii) ICU plural mismatch fixture (exit 1 + branch error). (d) `size-limit` budget gate: build console once, then assert `size-limit` exit 0 under threshold (250 KB gzip) and exit 1 above threshold (synthetic over-budget test). Evidence = vitest output + `docs/dev/logs/2.1-dev-log.md` §Integration. |
| E2E | Playwright on 3 projects (chromium + firefox + webkit) × 3 locale (en, zh-CN, ar) × LocaleSwitch flow + 5 negotiation scenarios + cookie persistence + RTL visual snapshots. Each scenario captures: (a) navigate to start URL, (b) interact (click LocaleSwitch / set headers / set cookie), (c) follow 302 redirect, (d) assert URL segment changed + cookie attribute matrix (`Domain`, `Max-Age`, `SameSite`, `Secure`) per env, (e) reload context with stored cookie, (f) verify cookie-first path takes precedence. Visual snapshots compare `ar` vs `en` to verify `dir="rtl"` + Tailwind logical properties mirror layout. Evidence = Playwright HTML report + `docs/qa/evidence/2.1-playwright-report/` artifact + RTL screenshot diffs. |
| Blind-Spot | 12 scenarios spanning BOUNDARY (empty/oversize cookie, invalid locale URL segment, q-value edge cases, ICU plural zero/large numbers), ERROR (Server Action network failure, missing messages module, cookie-disabled browser, hydration mismatch), FLOW (LocaleSwitch double-click, browser back during locale switch, direct URL to undefined locale), CONCURRENCY (concurrent locale switches in two tabs sharing cookie), DATA (cookie value pointing to retired locale fallback chain), RESOURCE (size-limit guard against runaway bundle growth). Each maps to a specific blind-spot check-point ID. |

> **Risk profile**: Comprehensive tier triggers `[test-design]` per `core-config.yaml.qa.testDesignThresholds.comprehensive.tasks` (note: 2.1 is NOT security_sensitive, so `risk-profile` is optional — Architect Round 1 Score 8.5, Critical=0, High=2 already resolved → no formal `*risk-profile 2.1` invocation needed in this Story). This test-design document doubles as the de-facto risk register: every Architect Round 1 Q-ruling (Q1–Q5) maps to ≥1 regression-guard scenario, both High-severity Round-1 issues (M-1: `packages/eslint-config` not-yet-delivered → use `next/core-web-vitals` directly; M-2: drop `console/unit-tests` + `console/lint` jobs → only `console/e2e-tests` + `console/i18n-keys-completeness`) map to explicit assertions, and Medium m-1 (`source-tree.md` namespace-split append) maps to a deliverable-binding-style check.

> **Architectural note (frontend skeleton stamps Epic 2-10)**: Story 2.1's `[locale]` segment route + `LocaleSwitch` + `messages/` namespace structure + `packages/i18n-keys/` codegen + cookie scheme + RTL strategy will be inherited by **25+ downstream Stories** (Epic 2 auth/profile/GDPR UI + Epic 3 console business pages + Epic 7 billing + Epic 10 docs). Any drift in this Story propagates broadly. The test matrix therefore prioritizes (a) **structural invariants** (locale tuple + key completeness + cookie spec + RTL helper) over implementation details, and (b) **CI gates** (codegen drift + key check + bundle budget) as the long-term regression guards. Future-Story regressions in any 2.1-foundation file should fail an existing 2.1 test.

## Notes

- All Unit scenarios are runnable locally with `pnpm --filter @he-api/console test`. They assert source-text properties (regex on raw files) where the file does not yet exist at test-design time — Dev is expected to make them pass during T1–T4. Integration scenarios require a running Next.js test runtime; E2E scenarios require Playwright browsers installed.
- "Generated" assertions (`packages/i18n-keys/src/common.ts`) target files produced by the codegen step. The test harness must run `pnpm --filter @he-api/i18n-keys build` before asserting (or ship a fixture file under `__tests__/fixtures/`).
- Cookie attribute matrix in 2.1-E2E-011 is dev-environment focused (`Domain=undefined`); production attribute verification is captured in Architect Recommendation #2 and rechecked at staging deploy time, not during local CI E2E.
- Bundle-budget glob pattern in `size-limit.json` (BR-4.9) is a placeholder; Dev MUST run `next build` once and adjust the glob to match Next.js 14.2's actual emitted chunk filename pattern (per Architect Recommendation #3). 2.1-UNIT-191 asserts a reasonable glob shape but allows flexibility.
