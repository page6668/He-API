# Test Design: 9.2 — 实时调用日志（最近 1000 条）

2026-06-11 | Turing | Level: **Standard** | Scope: AC1 (read endpoint) + AC2 (console viewer)

## Overview

Total: **38** | Unit: 24 (63%) | Int: 10 (26%) | E2E: 4 (11%)
Priority: **P0: 10, P1: 23, P2: 5**
Blind-Spot Scenarios: **11** (BOUNDARY 5, ERROR 3, DATA 2, FLOW 1)

**Highest-stakes invariant**: per-user **IDOR isolation** (BR-RD-1) — the headline risk per Dev Notes. SM Decision 8B elevated **IDOR full-path, PII-exclusion, and pagination-bound abuse** to **P0** within the Standard design. IDOR is designed at THREE levels (UNIT + INT + E2E) by intent — the documented exception to the duplicate-coverage guard, consistent with 9.1.

**Faithful-subset note**: this story reuses 9.1's shipped `request_logs` MergeTree, `analyticsquery` store/auth, `openaierr` envelopes, and the JWT-cookie `/v1/me/usage/*` family. No new store, migration, Kafka topic, or cost-source decision (per-request 消费 is intentionally absent — BR-RD-9 / H-1-R).

## Blind Spot Scenarios [BLIND-SPOT]

| ID | Category | Pri | Scenario | Ref |
|----|----------|-----|----------|-----|
| 9.2-UNIT-001 | DATA | P0 | IDOR fence: `WHERE user_id=?` always; `user_id` param rejected | DATA / BR-RD-1 |
| 9.2-INT-001 | DATA | P0 | Cross-user isolation: A never sees B's rows | DATA-002 |
| 9.2-UNIT-004 | BOUNDARY | P0 | `offset+limit` just-beyond the 1000 cap → 400 | BOUNDARY-004 |
| 9.2-UNIT-012 | BOUNDARY | P1 | `api_key_id` wrong type (non-UUID) → 400 | BOUNDARY-005 |
| 9.2-UNIT-013 | BOUNDARY | P1 | `start/end` missing → no bound; `end≤start` → 400 | BOUNDARY-001/004 |
| 9.2-UNIT-014 | BOUNDARY | P1 | Unknown/extra query param → 400 | BOUNDARY-004 |
| 9.2-UNIT-019 | BOUNDARY | P1 | Empty result (`total_count=0`) → EmptyState | BOUNDARY-001 |
| 9.2-INT-006 | ERROR | P1 | ClickHouse unreachable → 503; rows/conn released on error path | ERROR-002 / RESOURCE-001 |
| 9.2-UNIT-020 | ERROR | P1 | 503 inline retry / 401 redirect (session expiry) | ERROR-002 / FLOW-004 |
| 9.2-UNIT-021 | ERROR | P1 | Malformed payload (Zod fail) → generic error, no crash | ERROR-003 |
| 9.2-UNIT-023 | FLOW | P1 | Filter change resets offset; Next disabled at `has_more=false`; URL reflects state | FLOW-005 |

**CONCURRENCY — deliberately out of scope (documented, not a gap)**: `/logs` is a read-only endpoint over an append-only MergeTree; there is no write contention, lock, or check-then-act. The one race-adjacent property — new rows arriving shift the "最近 1000 条" window between pages — is benign eventual-consistency, not a correctness defect, and is governed by the deterministic `ts DESC, he_request_id DESC` ordering (9.2-INT-004). No CONCURRENCY test is warranted.

**RESOURCE** is covered as an assertion inside 9.2-INT-006 (connection/rows released on the error path) rather than as a standalone scenario — the endpoint reuses 9.1's pooled `OpenStore` and opens no new resource.

## Risk Coverage

No formal `risk-profile` artifact exists for 9.2 (Standard level; security_sensitive=true but the SM ruling routed it to elevated-P0-within-Standard, not Comprehensive+risk-profile). The dominant risks the suite addresses:

| Risk | Severity | Mitigated by |
|------|----------|--------------|
| Cross-user log leak (IDOR) | CRITICAL | 9.2-UNIT-001/002 (P0), 9.2-INT-001/002 (P0), 9.2-E2E-001 (P0) |
| Cross-user leak via `api_key_id` filter | CRITICAL | 9.2-INT-002 (P0) |
| PII leak (client_ip/UA/country/error_message/cost) | HIGH | 9.2-UNIT-003 (P0), 9.2-INT-003 (P0) |
| Deep-pagination resource abuse (unbounded offset) | MEDIUM | 9.2-UNIT-004 (P0), 9.2-UNIT-005 (P0) |
| Non-deterministic pages under equal-ts rows | MEDIUM | 9.2-INT-004 (P1) |
| ClickHouse outage cascades to a 500/crash | MEDIUM | 9.2-INT-006 (P1 → 503), 9.2-UNIT-020 (P1) |
| Cost wrongly surfaced (non-authoritative) | MEDIUM | 9.2-UNIT-018 (P1 — no cost column) |
| Malformed payload crashes console | LOW | 9.2-UNIT-021 (P1 Zod safety-net) |
