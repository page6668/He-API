### Why "Comprehensive" (not Simple or Standard)

Decision 8B locks **Comprehensive** because:

- Rule 1 (Simple) fails: `complexity_indicators = 4 > 0`.
- Rule 2 (Standard) fails: `complexity_indicators = 4 > 2`.
- Rule 3 (Comprehensive) matches: `complexity_indicators = 4 ≥ 3` → unit + integration + e2e mandated.
- Rule 4 (Comprehensive via `security_sensitive`) NOT triggered: Story 4.1's security surface is entirely inherited; `security_sensitive = false` per Story metadata.

Comprehensive level adds a **chaos suite** (Toxiproxy fault matrix per T4.3 — six upstream-failure modes the BR-1.4 mapping table must absorb) AND a **contract suite** (OpenAI Python SDK end-to-end per T4.4 — six scenarios that prove the SDK's strict Pydantic shape conformance survives both stream=False and stream=True paths) AND an **opt-in e2e live suite** (T4.5 — eight scenarios gated by `HE_API_DEEPSEEK_LIVE=1` so CI does not consume vendor quota on every PR). Risk profile is **required** per `qa.testDesignThresholds.comprehensive` and is produced as a separate document (`docs/qa/risk-4.1-deepseek-adapter.md`) cross-referencing R1–R7 enumerated below.
