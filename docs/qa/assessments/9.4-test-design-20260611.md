# Test Design: 9.4 — 全链路 trace（OpenTelemetry）

2026-06-11 | Turing (QA) | Level: **Comprehensive** (security_sensitive=true)

> Designed against the **ratified** Architect T0 contract (Wright, 2026-06-11, score 9.5/10). Binding rulings folded into every scenario:
> - **Q-PROP**: composite `tracecontext`+`baggage`; our code injects NO baggage values (rely on `trace_id` continuity).
> - **Q-SAMPLE**: `ParentBased(TraceIDRatioBased)`; non-prod ratio = 1.0, **prod = 0.1**; unparseable arg → 1.0 + warn; errors-always-sampled is NOT head-sampling (→ collector).
> - **Q-KAFKA**: **span LINK (not child) for ALL 4 topics** (billing, analytics request_logs, auth audit, 9.3 usage-log-export).
> - **Q-STORE**: KEEP Jaeger; no Tempo migration.
> - **Q-PII**: allow-list = registered `he.*` (§11.5) + `http.*`/`rpc.*`/`db.system` semconv ONLY; **NO SDK-side scrub** — two layers (code discipline + collector redaction).
> - **Q-COLLECTOR**: redaction keep-list processor (drops non-allow-list) + `tail_sampling` **ERROR/non-OK = 100%** retained.
> - **Q-SPANCOV**: ONLY mandatory new manual span = adapter→vendor upstream-model client span; DB/Redis/CH deferred.
> - **M1 (Medium)**: Loki→Jaeger `trace_id` derivedField ALREADY EXISTS — the genuine T3.1 delta is the *reverse* Jaeger `tracesToLogsV2` → Loki; MUST NOT duplicate the forward link.

**Local runnability** ([[project_toolchain_env_limits]]): all UNIT scenarios are fully runnable in-process (OTel SDK + `tracetest`/in-memory exporter + `propagation` carriers). All INT scenarios require docker/collector/Jaeger/Kafka → **CI/staging only**, compile-clean under the integration build tag. E2E is a documented manual stub (9.1-H-B / 9.2 / 9.3 precedent).

**Security focus (security_sensitive=true)**: the PII allow-list is the highest-risk surface. BOTH layers are asserted independently — (1) code never *sets* a disallowed attribute (9.4-UNIT-008 spans, 9.4-UNIT-015 Kafka headers); (2) collector drops `prompt`/`authorization`/email/IP (9.4-INT-005). These are P0 and lead the execution order after the continuity P0s.

| ID | Category | Pri | Lvl | Scenario | Ref |
|----|----------|-----|-----|----------|-----|
| 9.4-BLIND-BOUNDARY-001 | BOUNDARY | P1 | U | Malformed/absent incoming `traceparent` (not `00-<32hex>-<16hex>-<2hex>`) → otelhttp starts a NEW root span, no crash; the request becomes the trace root (correct for the true entry edge) | BOUNDARY-001/005 |
| 9.4-BLIND-BOUNDARY-002 | BOUNDARY | P2 | U | `OTEL_TRACES_SAMPLER_ARG` at limits `0` (drop all) and `1` (keep all), and just-beyond (`>1`, negative) → clamped/fallback to 1.0 + warn, never panic | BOUNDARY-002/003/004 |
| 9.4-BLIND-BOUNDARY-003 | BOUNDARY | P2 | U | Oversized baggage header (W3C > 8KB) → propagator drops baggage, `trace_id` still propagates (no continuity loss) | BOUNDARY-004 |

| 9.4-BLIND-ERROR-001 | ERROR | P1 | I | OTLP collector unreachable → spans buffered then dropped by the batcher; propagation + slog `trace_id` UNAFFECTED; zero request impact | ERROR-002 |

| 9.4-BLIND-DATA-001 | DATA | P1 | I | Collector scrub MISCONFIG over-drops (allow-list ⊊ §11.5) → a legit `he.*` attribute is dropped → caught by the allow-list⊇§11.5 assertion (ties to 9.4-INT-008) | DATA-002 |

**Blind-spot coverage check**:
- BOUNDARY per input field: incoming `traceparent` (001), sampler arg (002), baggage size (003), derivedField regex (004). ✅
- ERROR per external dependency: collector (E-001), Kafka header (E-002), producer write (E-003). ✅
- FLOW/CONCURRENCY for the async multi-step: redelivery (CONCURRENCY-001) covers the at-least-once flow. ✅
- DATA for the config/store path: scrub allow-list completeness (DATA-001). ✅
- RESOURCE for the new client: connection pooling (RESOURCE-001). ✅
