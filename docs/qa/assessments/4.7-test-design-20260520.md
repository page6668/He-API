### Why "Comprehensive" (not Standard or Simple)

Decision 8B locks **Comprehensive** because:
- Rule 1 (Simple) fails: `complexity_indicators = 3 > 0`.
- Rule 2 (Standard) fails: `complexity_indicators = 3 > 2`.
- Rule 3 (Comprehensive) matches cleanly: `complexity_indicators ≥ 3` (api_changes + new_patterns + core_docs).
- Independently, Epic-4 declares `test_design_level: comprehensive` at the epic root — epic-level directive overrides Story-level boundary case.

Comprehensive level → all four test tiers exercised (unit + integration + contract + e2e); blind-spot overlay is mandatory; ~30 scenario floor honored (this design lands 39).

### Why this surface needs Comprehensive

Three precedent-setting surfaces converge in Story 4.7:

1. **NEW unauthenticated endpoint** (`/public/models`) — the FIRST public endpoint on the gateway pre-Story-5.x rate-limit Stories. Establishes the public-endpoint pattern that Epic-9 observability + Epic-10 marketing endpoints (`/public/benchmark`, `/public/compliance`) will inherit. Wire-shape + CORS + anti-credential discipline get cemented here.
2. **NEW Next.js route group** (`(marketing)`) — the FIRST sibling of `(auth)` + `(console)` in `apps/console/app/[locale]/`. Epic-10's six marketing routes (`/pricing`, `/benchmark`, `/compliance`, `/blog`, `/about`, `/legal`) inherit this layout + auth-bypass pattern.
3. **He-API extension on OpenAI ModelEntry** (`capabilities`) — establishes the field-placement convention (extension fields appended LAST after OpenAI-canonical fields) for future He-API extensions on OpenAI-compatible surfaces. Story 4.8 contract tests will cascade this convention to per-vendor capability assertions.

Drift at any of these three surfaces cascades across multiple downstream stories — over-investing in tests now is cheap insurance.
