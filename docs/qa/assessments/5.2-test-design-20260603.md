### Story-level Scenario-ID convention

- `5.2-UNIT-{NNN}` — Go unit test (testify + table-driven). In-process only. Mocks: `pgxmock`/testcontainers-go PG for repository, `miniredis/v2` for Redis, `httptest` for gRPC stubs. Pure functions (`keypolicy/checks.go`, `clientip.go`) are mock-free.
- `5.2-INT-{NNN}` — Go integration test. Requires real Postgres 16 (testcontainers-go) AND/OR Redis 7.2 (testcontainers-go) AND/OR miniKafka (KRaft). Located in `apps/api-gateway/internal/handlers/me_keys_update_test.go` (gateway↔auth-svc loop).
- `5.2-E2E-{NNN}` — Real-binary pytest in `apps/api-gateway/tests/openai_sdk_keys_policy_e2e_test.py` (pytest 8.* + httpx 0.27.* — Story-3.3/5.1 toolchain REUSED); spawns gateway + auth-svc + testcontainers PG/Redis/Kafka; budget ≤ 60s wall-clock.
- `5.2-SECURITY-{NNN}` — Security-focused cross-cutting (Decision 8B `security_focus=true`). Level annotated per scenario (UNIT log-scan or INTEGRATION matrix).
- `5.2-CACHE-{NNN}` — Cache-coherence spanning Story-3.2 positive cache + Story-5.1 revoke sentinel + Story-5.2 config-updated sentinel; INTEGRATION (real Redis `EXISTS`/MULTI roundtrip).
- `5.2-CHAOS-{NNN}` — Resilience with `toxiproxy` Redis chaos; build-tag `chaos` (NOT in default CI; nightly gated per Story-4.x/5.1 precedent).
- `5.2-REG-{NNN}` — Regression guard for Story-3.2/5.1 suites against the additive `bearer_auth.go` change.
- `5.2-BLIND-{CATEGORY}-{NNN}` — blind-spot scenarios tagged `[BLIND-SPOT]`. Categories per `blind-spot-categories.yaml`.

Dev MUST embed `// Scenario: {scenario_id}` Go comments atop each Go test function (and `# Scenario: {scenario_id}` for pytest) — `*review 5.2` greps these for AC traceability per Story 2.x/3.x/4.x/5.1 precedent.
