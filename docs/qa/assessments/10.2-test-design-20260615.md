# Test Design: 10.2 — Python SDK（`he-api`, drop-in OpenAI 替代）

2026-06-15 | Turing (QA) | Level: **Comprehensive** (Epic-10 directive)

## Overview

Total: **41** | Unit: 12 (29%) | Integration: 26 (63%) | E2E: 1 (2%, live-gated) | Doc-gate: 2 (5%)
Priority: **P0: 17**, P1: 18, P2: 6
Blind Spot Scenarios: **8**

**Story shape (drives every scenario):** `he-api` is a *pure-consumer* library — `he_api.Client` subclasses `openai.OpenAI` and `he_api.AsyncClient` subclasses `openai.AsyncOpenAI` (R-OQ-1), each **overriding only `__init__`** to inject He defaults (default `base_url`, `HE_API_KEY` read). There is **no backend/proto/DB surface** (cumulative-context PASS). "Interface identity" is therefore tested as **inheritance fidelity** (the inherited `.chat`/`.embeddings`/`.models`/`.audio`, SSE streaming, pydantic response models, retries, `.with_raw_response` still behave OpenAI-shaped after the He default-injection), **not** as a re-implemented HTTP client. All hermetic tests **mock the httpx transport via `respx`** (R-OQ-5) — **no real gateway**. The single live E2E is gated on `HE_API_TEST_GATEWAY_URL` (skip-if-unset).

**Two Python-specific surfaces 10.3 (TS) did not have:**
1. **Async client parity** — Python needs an explicit `AsyncClient` (subclass of `openai.AsyncOpenAI`); JS was promise-native, so the TS mirror had no async-specific scenario. Covered by `10.2-INT-017` + `10.2-BLIND-CONCURRENCY-001`.
2. **Build/distribution rigor** — `python -m build` → clean-venv `pip install` → `import he_api` → `twine check`, plus the **version single-source** invariant `he_api.__version__ == importlib.metadata.version("he-api")` (BR-10.2.4). Covered by `10.2-UNIT-002`, `10.2-INT-001/002/003`.

**Drop-in oracle (REUSE):** `apps/api-gateway/tests/_protocol_invariants.py` shape assertions (`assert_chat_completion_shape`, `assert_chat_completion_chunk_shape`, `assert_embedding_shape`, `assert_error_envelope_shape`, `assert_model_entry_shape`, `REQUEST_ID_RE = ^req_[0-9a-f]{12}$`). The `respx` hermetic mocks must emit fixtures that satisfy these shapes so the wrapper is proven shape-faithful in the **same terms** as the gateway's own contract suite (the 20 `openai_sdk_*_test.py` files driving the gateway via the official SDK). The live E2E (`10.2-E2E-001`) reuses these assertions verbatim against a real gateway.

## Risk Coverage

No separate risk-profile was run (Comprehensive level, but `security_sensitive=false`, pure consumer). Implicit risk mapping:
- **Upstream-breakage risk** (openai major bump silently changing parse shapes) → `10.2-UNIT-003` pin-drift guard + every INT shape assertion.
- **Credential cross-wiring risk** (sending an OpenAI key to the He gateway, or vice-versa) → `10.2-UNIT-012`, `BLIND-BOUNDARY-001/002`.
- **False-billing risk** (treating `X-He-Cost-Usd` as authoritative) → `10.2-INT-023` (OQ5 guard).
- **Publish-footgun risk** (broken metadata / version drift / un-installable wheel) → `10.2-UNIT-002`, `10.2-INT-001/002/003`.
- **Async-divergence risk** (async client behaving differently from sync) → `10.2-INT-017`, `BLIND-CONCURRENCY-001`.

## Execution Order

1. **P0 Unit** — UNIT-001/002/003/010/011/012 (fail fast on packaging metadata + version SoT + pin + default/precedence resolution)
2. **P0 Integration** — INT-001/002/003 (build/install/twine/name-split) then INT-010..017 (drop-in core, error passthrough, async parity)
3. **P1** — UNIT-004/005/006/013; INT-020..025; all 7 P1 [BLIND-SPOT]; E2E-001 (only if gateway URL set)
4. **P2** — INT-030/031/032; DOC-001/002; RESOURCE-001
