**Top 3 Risks (by score):**

1. **TECH-001 (R1)** — Upstream-failure-mode coverage incomplete for DashScope-specific shapes (429 throttle body, native 401 `InvalidApiKey`); BR-1.4 mapping table row drift could leak unhandled errors as `500_internal_error` or malformed envelope. Score: **16** (P=4 × I=4) — mitigated by quintuple-layer test defence (INT-003 + INT-004 + INT-006 + CHAOS-001..007 — seven fault modes including Qwen-specific 429 throttle).
2. **TECH-008 (R8 — NEW)** — Multi-model-id-per-service dispatch leaks state across model ids: a `qwen-max` request returns `qwen-plus` response (model-id swap in `translate.go` body or in adapter response mapping). Score: **15** (P=3 × I=5 — silent data corruption with downstream billing implications) — mitigated by triple-layer (UNIT-002/003 translate forward, INT-002 upstream-receive, INT-009 parallel non-cross-contamination, CONTRACT-002/004 SDK-observed response.model).
3. **TECH-009 (R9 — NEW)** — `NewRegistry` endpoint-dedup refactor (Architect M2 ~7 LoC) breaks Story-4.1 single-endpoint `deepseek-v3` path — the dedup logic accidentally aliases `deepseek-v3` to qwen-max/qwen-plus handle if endpoint-keying logic is flawed. Score: **12** (P=3 × I=4 — Story-4.1 regression breaks two ratified ACs) — mitigated by UNIT-012 (deepseek-v3 distinct handle) + INT-001 (gateway routes `deepseek-v3` to `adapter-deepseek` unchanged) + UNIT-013 (qwen-max == qwen-plus pointer identity, anchors the M2 fix).

**Overall Assessment:**

- **Zero Critical** risks. All 9 risks have explicit P0 or P1 test gates designed in `4.2-test-design-20260519.md`.
- The 3 High risks (TECH-001 + TECH-008 + TECH-009) drive the Comprehensive test-design budget — together they account for **23 of the 34 P0 scenarios** (chaos suite + multi-model-id triple-coverage + M2 endpoint-dedup regression guard).
- 4 immediate pre-Dev actions required (listed in §Risk Mitigation Roadmap below — 3 INHERITED from Story-4.1 risk profile + 1 NEW for the M2 refactor).
- All 3 High risks must have GREEN P0 test coverage before Dev marks `Status = Review` (QA-aligned gate criteria).

**Recommendation: Conditional Proceed** — Dev MAY begin implementation after acknowledging the 4 Immediate Action items in §Risk Mitigation Roadmap. The chaos suite (CHAOS-001..007) MUST be wired into the nightly CI job during T4.3 — if the chaos suite is deferred to a follow-up Story, the Story 4.2 gate FAILS on the High-risk surface for R1 (DashScope 429 throttle path unverified).

| **Acceptance Criterion** | All seven CHAOS scenarios pass in nightly CI; INT-003/004/006 all P0; slog `upstream_error_kind` enum is closed (only `upstream_5xx`/`upstream_4xx_auth`/`upstream_timeout`/`rate_limit_throttle`/`tls`/`dns`/`connect_refused` permitted — no other values). |

### TECH-008 (R8 — NEW) — Multi-model-id-per-service dispatch leaks state across model ids

| Attribute | Value |
|-----------|-------|
| **Category** | TECH |
| **Score** | P=3 (medium — new pattern, no prior production telemetry; goroutine-state-sharing bugs are subtle) × I=5 (critical — silent data corruption; billing-svc reads `usage` + `model` from `usage.recorded` Kafka topic in Epic 7; if model swaps mid-flight, billing attributes Qwen-Max cost to a Qwen-Plus call OR vice versa) = **15** |
| **Source** | Story 4.2 NEW pattern (BR-1.10 single-service-multi-model-id); Architect Round 1 OQ-4.2-2 ratification (cascades to Stories 4.3 Kimi + 4.5 Doubao) |
| **Failure Mode** | (a) `translate.go` hardcodes a model id instead of forwarding `req.Model` verbatim; (b) adapter-side state (e.g., a shared `latestModel` variable) crosses goroutine boundaries under parallel `qwen-max` + `qwen-plus` dispatch; (c) Connect-RPC server-stream payload mutation reuses a chunk struct across model ids and a goroutine sees a stale `model` field |
| **Mitigation** | Triple-layered: UNIT-002 + UNIT-003 (translate.go body field `model` verbatim per req.Model) + INT-002 (upstream-fake asserts received body's `model` field for BOTH `qwen-max` AND `qwen-plus`) + INT-008 (streaming variant) + INT-009 (parallel `qwen-max` + `qwen-plus` non-cross-contamination — race detector enabled `go test -race`) + CONTRACT-002/004 (SDK-observed `response.model` matches `request.model`). |
| **Owner** | Dev (T1.2 + T1.4 + T2.6 implementation) → QA (review + race-detector enforcement) |
| **Acceptance Criterion** | UNIT-002/003 + INT-002/008/009 all P0 and green; race detector clean for INT-009 (`go test -race ./apps/adapters/qwen/tests/...`); CONTRACT-002/004 green when `HE_API_TEST_GATEWAY_URL` is set. |

|-----------|-------|
