# Test Design: 6.1 — 路由器核心（策略接口 + 决策引擎）

2026-06-03 | Turing (QA) | Level: **Comprehensive** (Decision 8B: complexity 4/8 ≥ 3 + first-realisation-of-locked-contract + Epic-6 inheritance)

> Story type: **Backend API + Library lift** (Go / Connect-RPC service skeleton + shared `packages/models-catalogue/` package). Blind-spot high-priority categories applied: **BOUNDARY, ERROR, CONCURRENCY, DATA, RESOURCE** (+ FLOW medium). All Architect Round-1 rulings Q-A…Q-K folded into the assertions below.
>
> **6.1 boundary reminder for the implementer/QA**: server-side only — NO gateway wiring, NO real scoring, NO PG migration, NO `context.WithTimeout` enforcement (Q-E 100ms is a documented lifetime contract value; enforcement lands gateway-side in 6.2). The three named strategies are **intentionally indistinguishable** stubs (Q-G).

**Shift-left posture**: the headline criterion `单测覆盖 3 种策略边界` is satisfied almost entirely at the **unit** level (strategy stubs + engine dispatch are pure functions over an in-memory catalogue — no I/O). Integration is reserved for the three genuine boundaries that unit cannot prove: Connect-RPC over-the-wire conformance, health-probe/boot lifecycle, and the cross-package `BuildPublicModelsSnapshot` byte-identity (4.7-INT-001).

## Blind Spot Scenarios `[BLIND-SPOT]`

| ID | Category | Lvl | Pri | Scenario | Ref |
|----|----------|-----|-----|----------|-----|
| 6.1-BLIND-BOUNDARY-001 | BOUNDARY | U | P2 | `requested_model` = **whitespace-only** string (`"   "`) → treated as empty → `InvalidArgument` (not silently accepted) | BOUNDARY-001 |
| 6.1-BLIND-BOUNDARY-002 | BOUNDARY | U | P1 | `strategy` enum **just beyond range** (value `5`, `99`) → not in registry → `ErrUnknownStrategy` → `InvalidArgument` | BOUNDARY-004 |
| 6.1-BLIND-BOUNDARY-003 | BOUNDARY | U | P2 | `ab_models` populated in a 6.1 request → **ignored** (A/B is Story 6.4); single-select still returns; `is_ab_test=false`, `ab_selected_models=[]` | BOUNDARY-001 |
| 6.1-BLIND-BOUNDARY-004 | BOUNDARY | U | P2 | `he_request_id` **empty** → no validation error; slog handles empty value gracefully (field is optional) | BOUNDARY-001 |
| 6.1-BLIND-ERROR-001 | ERROR | U | P1 | Shared models-catalogue load yields a **nil/empty registry** → boot **fail-fast** (maps to the AC1 empty-catalogue exit path, exercised via the dependency seam) | ERROR-002 |
| 6.1-BLIND-ERROR-002 | ERROR | U | P2 | Registry entry **malformed** (missing `ID`) → `init()` panic / boot fail with a structured message — never a silent half-loaded catalogue | ERROR-003 |
| 6.1-BLIND-CONCURRENCY-001 | CONCURRENCY | U | P1 | **N concurrent** `Engine.Decide` calls → deterministic identical results; **no data race** on the read-only catalogue (`go test -race`) | CONCURRENCY-002 |
| 6.1-BLIND-CONCURRENCY-002 | CONCURRENCY | I | P1 | **Concurrent** `SelectModel` RPCs read the boot-loaded snapshot read-only → no data race, no torn read (`-race`) | CONCURRENCY-004 |
| 6.1-BLIND-DATA-001 | DATA | U | P0 | **Reverse 1:1** — a capability entry with **no matching model** also violates the invariant (no orphan in either direction; complements UNIT-042) | DATA-004 |
| 6.1-BLIND-DATA-002 | DATA | I | P0 | api-gateway **and** routing-svc read the **identical** snapshot from the single SoT — cross-package data consistency (the lift cannot introduce drift between the two consumers) | DATA-002 |
| 6.1-BLIND-RESOURCE-001 | RESOURCE | I | P1 | **SIGTERM** → graceful shutdown releases the HTTP listener **and** flushes/shuts down the TracerProvider (Story 1.5 signal-handling reuse) | RESOURCE-001 |
| 6.1-BLIND-RESOURCE-002 | RESOURCE | U | P2 | `TracerProvider.Shutdown` is called on the exit path (defer) — no leaked span-exporter goroutine after server stop | RESOURCE-004 |
| 6.1-BLIND-FLOW-001 | FLOW | I | P1 | **Boot-sequence ordering** — the engine + catalogue are fully constructed *before* `/ready` flips to 200, so any `SelectModel` accepted after readiness is guaranteed a constructed engine (no half-initialised dispatch) | FLOW-003 |

**Minimum blind-spot coverage check**
- ✅ BOUNDARY per input field: `requested_model` (BOUNDARY-001), `strategy` (BOUNDARY-002), `ab_models` (BOUNDARY-003), `he_request_id` (BOUNDARY-004) — plus catalogue-as-array empty (UNIT-017) and single (UNIT-019).
- ✅ ERROR per external dependency: the only 6.1 "dependency" is the boot-loaded shared catalogue (ERROR-001, ERROR-002). No network/DB/Kafka deps exist in 6.1 (stateless, BR1-1).
- ✅ CONCURRENCY: stateless service serving concurrent reads (CONCURRENCY-001 engine-level, CONCURRENCY-002 RPC-level), both `-race`.
- ✅ DATA: the cross-package lift is the integrity surface (DATA-001 invariant, DATA-002 cross-consumer parity).
- ✅ RESOURCE: graceful shutdown + tracer cleanup (RESOURCE-001, RESOURCE-002).
- ✅ FLOW per multi-step process: the boot→ready→serve sequence (FLOW-001).

## Risk Coverage

No standalone risk-profile was produced for 6.1 (`security_sensitive: false`; comprehensive level reached via complexity + first-realisation rules, not risk). The implicit risks and their mitigating scenarios:

| Implicit risk | Mitigated by |
|---------------|--------------|
| **Cascade-locked contract churn** (Strategy interface / proto reshaped after 6.2-6.5 bind) | UNIT-022 (interface signature lock), INT-010/011 (proto shape over the wire), UNIT-030/035 (`adapter_endpoint` reserved Q-K), UNIT-036 (`strategy_used` Q-I) |
| **proto3 zero-value mis-dispatch** (omitted `strategy` → UNSPECIFIED errors/mis-routes) | UNIT-015, UNIT-036 (Q-D) |
| **Lift regression** (`/public/models` output drifts; 4.7 invariant lost) | UNIT-040/041/042, INT-020 (4.7-INT-001 byte-identity), BLIND-DATA-001/002 |
| **Stub mistaken for real logic** in 6.2 | UNIT-013 (intentional indistinguishability) — 6.2 QA proves replacement by asserting the three diverge |
| **Served-empty state** (catalogue empty at runtime instead of boot-fail) | UNIT-001/003, INT-003, BLIND-ERROR-001 (BR1-2) |
| **Data race** on the shared snapshot under concurrent load | BLIND-CONCURRENCY-001/002 (`-race`) |
