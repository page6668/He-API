# Test Design: 9.6 — ASR API（兼容 Whisper）+ Doubao

2026-06-15 | Turing (QA) | Level: **Comprehensive** (security_sensitive=true)

> Designed against the **Architect-ratified contract** (`## Architect Review Results`, Wright, score 9.5/10) — the 7 OQ rulings are binding. Key amendments folded into the scenarios below: **ceil-to-second** billing (`ceil(duration_seconds) × price_per_minute_audio_usd/60 × (1+markup)`); **token columns stay NOT NULL** (doubao-asr row carries 0/0); **`ComputeCost` signature extends** to take duration; **`whisper-1` alias DEFERRED**; **`srt`/`vtt` → explicit 400**; **`prompt` cap = 2048**; **magic-byte sniff via stdlib `http.DetectContentType`**; **transcript NOT safety-scanned**.

## Test-Skeleton Note (Go monorepo)

This story spans 5 Go modules (`packages/proto`, `apps/api-gateway`, `apps/adapters/doubao`, `apps/billing-svc`, `packages/models-catalogue`) — the single-file TS skeleton in the test-design template does not fit. The skeleton's intent (every designed scenario gets a test, none silently dropped) is instead served by: (a) this document's stable scenario IDs, and (b) the **Test Specs tables backfilled into the Story Tasks** (Output 4.5) keyed to T1–T7. Dev writes the per-package `*_test.go` test-first per task; QA `*review 9.6` verifies every scenario ID above has a corresponding test.
