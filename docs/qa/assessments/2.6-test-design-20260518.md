### Story-level Scenario-ID convention

- `2.6-UNIT-{NNN}` — Go (testify) or TypeScript (Vitest) unit; pure-logic / no external I/O
- `2.6-INT-{NNN}` — Go testcontainers integration (PG + Redis + Kafka + LocalStack-OSS) OR api-gateway↔notification-svc↔analytics-svc full-stack
- `2.6-E2E-{NNN}` — Playwright browser flow (console + api-gateway + notification-svc + analytics-svc + Kafka + Mailpit + LocalStack-OSS)
- `2.6-BLIND-{CATEGORY}-{NNN}` — blind-spot scenario tagged `[BLIND-SPOT]` per `blind-spot-categories.yaml`. Categories applied: **BOUNDARY, ERROR, FLOW, CONCURRENCY, DATA, RESOURCE** (full-stack applicability per the framework's `applicability.fullstack` row); `security_sensitive=true` elevates CONCURRENCY / DATA / RESOURCE scenarios touching credentials or PII allow-lists to **P0** (contrast Story 2.5).

### Architect R-1..R-5 ruling impact on test design

- **R-1** (TS-CONS-013: Kafka-topics Terraform module CREATE — was incorrectly labeled EXTEND in R1): `2.6-INT-031` smoke-tests `kafka-topics.sh --describe --topic gdpr.export.requested` after `terraform apply` against staging.
- **R-2** (TS-CONS-014: `EmailTemplate.EMAIL_TEMPLATE_GDPR_EXPORT_READY = 6` proto enum — NOT a string `template_id`): `2.6-INT-040` asserts the outgoing `SendEmailRequest.template` field is the proto-enum integer `6`, not a string. `2.6-UNIT-080` asserts the template loader maps enum → file-slug `gdpr_export_ready` (decoupling per Ruling R-2 Action #2).
- **R-3** (TS-CONS-015-shared-bucket-prefix: shared OSS bucket + per-user prefix): `2.6-UNIT-060`, `2.6-INT-020`, `2.6-INT-027` assert object key pattern `gdpr-exports/{user_id}/{export_id}.zip` against a SHARED bucket `he-api-gdpr-exports` (NOT per-user bucket).
- **R-4** (TS-CONS-016-failed-excluded: 24h idempotency window EXCLUDES `failed`): `2.6-INT-006` asserts that a row with `status='failed'` does NOT block a new request inside the 24h window — the user can retry immediately.
- **R-5** (TS-CONS-017-CH-explicit-WHERE: `dumpRequestLogs` uses explicit `WHERE ts >= NOW() - INTERVAL 90 DAY` not TTL-dependent): `2.6-UNIT-073` asserts the SQL string contains the explicit WHERE clause; `2.6-INT-022` asserts the 91-day-old row is NOT dumped even when CH TTL is permissive.

### Low-1 (front-end-spec §3.5 narrative drift) impact

Story BR-1.1 / BR-6.3 enumerate **6** categories (users / api_keys / request_logs / orders / balances / safety_logs); front-end-spec §3.5 still narrates 4. Test design follows the **Story's 6-category dialog** (security.md §8.3 is the authority). `2.6-UNIT-001` + `2.6-E2E-001` assert all 6 category labels render in the dialog.
