### Why "Comprehensive"

Decision 8B locks **Comprehensive** because:

- Rule 1 (Simple) fails: `complexity_indicators = 3 > 0`.
- Rule 2 (Standard) fails: `complexity_indicators = 3 > 2`.
- Rule 3 (Comprehensive) matches: `3 ≥ 3` → unit + integration + e2e mandated; risk profile required.
- Rule 4 (via `security_sensitive`) NOT triggered: `security_sensitive = false`.

Although Story 4.4 is the **LEAST architecturally-novel** adapter in Epic 4 (single model id; full template REUSE from Story 4.1/4.2/4.3 verbatim), every NEW vendor onboarding introduces a NEW upstream-failure surface and a NEW live-exercise gate. These MUST be exercised before production traffic. Comprehensive adds the **chaos suite** (Toxiproxy 6 REUSE Story-4.1/4.2/4.3 + 1 Zhipu-flavoured 429 per T4.1.g), **contract suite** (`openai==1.40.*` skeleton-only per T2.6), and an **opt-in e2e live suite** (`HE_API_GLM_LIVE=1` per T4.2 — separate gate from `HE_API_DEEPSEEK_LIVE` + `HE_API_QWEN_LIVE` + `HE_API_KIMI_LIVE` so vendor suites run independently).
