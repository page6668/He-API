### Story-level Scenario-ID convention

- `2.3-UNIT-{NNN}` — auth-svc / api-gateway / console unit (Go or Vitest)
- `2.3-INT-{NNN}` — auth-svc + Redis / PG / provider stub / Kafka integration (Go testcontainers)
- `2.3-E2E-{NNN}` — Playwright browser flow (console + api-gateway + auth-svc + mock provider stubs)
- `2.3-SEC-{NNN}` — explicit security attack/abuse-path scenarios (level=integration or e2e per check)
- `2.3-BLIND-{CATEGORY}-{NNN}` — blind-spot scenario tagged `[BLIND-SPOT]` per `blind-spot-categories.yaml`

Dev MUST embed `// Scenario: {scenario_id}` (Go) or `// Scenario: {scenario_id}` (TS/JS) in each test function — QA `*review 2.3` greps these comments for AC traceability per Story 2.3 `## QA Test Design Metadata` contract.

Full-stack (Go gRPC auth-svc + Go HTTP api-gateway + Next.js console). High-priority blind-spot categories per `blind-spot-categories.yaml` `applicability.fullstack`: **BOUNDARY, ERROR, FLOW, CONCURRENCY, DATA, RESOURCE** (all 6 applied).
