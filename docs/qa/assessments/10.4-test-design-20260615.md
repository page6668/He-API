# Test Design: 10.4 — Go SDK (`github.com/he-api/sdk-go`, drop-in OpenAI)

2026-06-15 | Turing (QA) | Level: **Comprehensive** (Epic-10 directive)

## Overview

Total: **53** | Unit: 14 (26%) | Integration: 38 (72%) | E2E: 1 (2%, live-gated)
Priority: **P0: 21**, P1: 26, P2: 6
Blind Spot Scenarios: **12**

**Story shape (drives every scenario):** `github.com/he-api/sdk-go` is a *pure-consumer* library — it touches **no backend/proto/DB**. Because **Go has no class inheritance** and `openai-go` is a functional-options design, the ratified drop-in form (**R-OQ-10.4-1**) is **constructor wrapping**: `func NewClient(opts ...option.RequestOption) openai.Client` pre-pends `WithBaseURL(DEFAULT_BASE_URL)` + `WithAPIKey(env HE_API_KEY)` and **returns the upstream `openai.Client` itself**. "Interface identity" is therefore tested as **same-type identity** — *the value returned IS the upstream client* — not "inheritance fidelity" (10.3) and not a re-implemented HTTP client. Every hermetic test injects a stub transport via **`option.WithHTTPClient(&http.Client{Transport: stubRoundTripper})`** (R-OQ-10.4-3); SSE streaming tests may use an `httptest.Server`. **No real gateway** in CI. The single live E2E is gated on `HE_API_TEST_GATEWAY_URL` (skip-if-unset).

**Key fact (Architect, ratified):** `openai-go` is **GA `/v3`** (not beta) — import path carries the major suffix `github.com/openai/openai-go/v3`, requires Go 1.22+. Pin discipline is "major-in-import-path" (like 10.3 npm 4.x↔6.x), **not** "beta churn". The SDK's own module path has **no `/vN` suffix** (v0/v1).

**Drop-in oracle (REUSE — there is no Go-native oracle):** `apps/api-gateway/tests/_protocol_invariants.py` shape assertions (`assert_chat_completion_shape`, `assert_chat_completion_chunk_shape`, `assert_embedding_shape`, `assert_error_envelope_shape`, `assert_model_entry_shape`, `REQUEST_ID_RE = ^req_[0-9a-f]{12}$`). Dev MUST build an **equivalent Go shape-assertion helper** so the wrapper is proven shape-faithful in the same terms the gateway's own contract suite uses. The hermetic fixtures must emit bodies that satisfy these shapes.

## Risk Coverage

No separate risk-profile was run (Comprehensive level, but `security_sensitive=false`, pure consumer). Implicit risk mapping:

- **Upstream-breakage risk** (openai-go major/minor bump silently changing parse shapes) → `10.4-UNIT-014` pin-drift guard + every INT shape assertion.
- **Credential cross-wiring risk** (sending an OpenAI key to the He gateway, or routing `HE_API_KEY` to OpenAI) → `10.4-UNIT-012`, `10.4-INT-011`, `BLIND-BOUNDARY-002`.
- **False-billing risk** (treating `X-He-Cost-Usd` as authoritative) → `10.4-INT-016` (OQ5 guard).
- **Orphan-module risk** (module built/tested by no CI lane, or linted by none) → `10.4-INT-003/004/009`.
- **Path-resolution risk** (`go get` path ≠ epic AC, or missing `/v3` on dependency) → `10.4-UNIT-002/003`, `10.4-INT-005`.
- **Streaming-leak risk** (SSE connection not released) → `BLIND-RESOURCE-001`, `BLIND-ERROR-005`.
