### Test-Level Interpretation for CI/CD Stories

CI/CD workflow stories invert the usual test-level pyramid: the "production code" is itself a set of declarative YAML manifests, so the most actionable tests are static assertions on workflow files (parsed as YAML / matched as text). Per the test-levels framework these are classified as **Unit** (pure config validation, no external system involvement). The remaining **Integration** and **E2E** scenarios are inherently workflow-runtime tests — they require a real PR or `main` merge to validate, and are tracked via Dev T6 evidence (PR/Run links in `docs/dev/logs/1.2-dev-log.md`).

| Level | Coverage Strategy |
|-------|-------------------|
| Unit | Vitest tests parsing `.github/workflows/*.yml`, `.golangci.yml`, `Dockerfile`; assert structure / required keys / regression guards. Runnable locally via `pnpm test`. |
| Integration | PR-driven scenarios (draft PR + intentional failures). Evidence = PR Run links in dev-log T6. Not auto-runnable. |
| E2E | Merge-to-`main` scenarios (workflow_run chain end-to-end). Evidence = `main` branch Action Run links in dev-log T6. Not auto-runnable. |

## Execution Order

1. **P0 Unit (15)** — fast, deterministic, runnable in <10s via `pnpm test`; gate `lint+test` job before E2E
2. **P0 Integration (3)** — Dev-driven PR runs (1.2-INT-001/002/003) with intentional failures
3. **P0 E2E (3)** — Dev-driven merge run + step-summary verification (1.2-E2E-001/002/003)
4. **P0 Blind-Spot (10)** — interleaved with above; most are observation-based (no extra runs needed) or Story 1.3+ follow-ups
5. **P1 (11)** — P1 Unit (4) + P1 INT (2) + P1 BLIND-SPOT (5); within same PR runs
6. **P2 (3)** — best-effort observation; document in dev-log T6 if unobservable in this Story
