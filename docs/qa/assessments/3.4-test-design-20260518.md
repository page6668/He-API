### Why "Comprehensive" (not Standard or Simple)

Decision 8B locks Comprehensive on `complexity_indicators = 4` (api_changes + new_patterns + performance + core_docs). Three indicators drive depth:

1. **api_changes** — FIRST SSE wire contract in the project. The chunk-shape types (`chatChunk`/`chatChunkChoice`/`chatChunkDelta` with `omitempty` discipline per AR1-R2) become the template Epic 4 streaming adapters inherit. Byte-exact assertion at the Writer (3.4-UNIT-001/003) AND SDK (3.4-E2E-001) levels is the load-bearing guard.
2. **new_patterns** — FIRST `apps/api-gateway/internal/streaming/` occupant (the slot has been reserved at `source-tree.md §6 line 12` since Epic 1); FIRST `http.ResponseController` consumer (Go 1.20+ flush-through-wrapped-writer pattern that survives `obs.WrapHTTPHandler` middleware); FIRST SSE Writer abstraction. 3.4-UNIT-005 (middleware-wrapper survival) + 3.4-UNIT-006 (`ErrFlushUnsupported` sentinel) are the precedent guards future stories inherit.
3. **performance** — AC2 TTFB ≤ 300ms is the epic AC. Two-mode P50/P95/P99 measurement (in-process recorder via `httptest.NewRecorder` at 3.4-INT-001 vs loopback TCP via `httptest.NewServer` at 3.4-INT-002) is novel — must prove the recorder isn't masking latency (delta < 20ms guard at INT-002) AND a `time.Sleep` regression is caught earlier than the budget (P50 < 5ms floor at INT-003).

### Risk Coverage

No `risk-profile` was generated for Story 3.4 (not required at Standard/Comprehensive — risk-profile is the next-step deepening for `securitySensitive=true` per `core-config.yaml.qa.testDesignThresholds.comprehensive`, which Story 3.4 is NOT). The risk surface is enumerated implicitly through ACs:

| Implicit Risk | Mitigating Scenarios |
|---------------|----------------------|
| **R1 — SSE wire framing breaks OpenAI SDK iterator** (off-by-one LF, missing `data: ` prefix, malformed `[DONE]`) | 3.4-UNIT-001, 003, 004, 008 (byte-exact Writer assertions) + 3.4-E2E-001..004 (SDK iterator end-to-end) |
| **R2 — Story 3.3 non-streaming path regresses** (dispatch fork accidentally swallows non-streaming requests) | 3.4-INT-005, 006 (stream-false / stream-missing route to JSON) + 3.4-INT-007 (golden-file byte-equality) |
| **R3 — TTFB SLA breach** | 3.4-INT-001 (in-process P95), 002 (loopback P95 + delta), 003 (P50 sleep-regression catch) |
| **R4 — Goroutine / FD leak under client-disconnect churn** | 3.4-UNIT-021 (no spawn) + 3.4-INT-013 (goleak.VerifyNone after 10 successes) + 3.4-BLIND-CONCURRENCY-001 (concurrent + mid-cancel) + 3.4-BLIND-RESOURCE-001 (FD baseline after 100) |
| **R5 — Import-cycle (C1) re-emerges via future edits** | Verify-grep invariants encoded in T2.5 (`go list -deps ./...streaming \| grep handlers` must return empty); not a test, but a build-time gate any test runner picks up |
| **R6 — PII leak via chunk-delta logging** | 3.4-INT-009 (sentinel substring in `messages[].content`, assert absent from slog buffer) — inherits Story 3.3 BR-1.8 / UNIT-016 pattern |
| **R7 — Architect ruling AR1-R4 (return-value TTFB) regresses to Writer hook** | 3.4-UNIT-022 second sub-case (ordering invariant: `firstFlushAt` set AFTER bootstrap WriteEvent but BEFORE first content chunk) + zero-value sentinel for pre-first-flush cancellation |

### AC1 — SSE Happy Path: Chunked Delivery, Event Framing, `[DONE]` Terminator

#### AC1.A — Writer Wire-Format Primitives (Unit)

| ID | Lvl | Pri | Test | Why |
|----|-----|-----|------|-----|
| 3.4-UNIT-001 | U | P0 | `Writer.WriteEvent("", json)` → `"data: {json}\n\n"` byte-exact | **Load-bearing wire-format** — BR-1.2; OpenAI SDK iterator hard-depends on exact framing |
| 3.4-UNIT-002 | U | P0 | `Writer.WriteEvent("error", json)` → `"event: error\ndata: {json}\n\n"` byte-exact | BR-4.4 interface guarantee — future Stories MAY use named-event variant for SSE-encoded errors (Epic 4) |
| 3.4-UNIT-003 | U | P0 | `Writer.WriteDone()` → `"data: [DONE]\n\n"` byte-exact | **Load-bearing** — BR-4.5 + AR1-R3; OpenAI SDK iterator terminates ONLY on this exact byte sequence |
| 3.4-UNIT-004 | U | P0 | First `WriteEvent` call sets BR-1.1 headers (`Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-cache, no-transform`, `Connection: keep-alive`, `X-Accel-Buffering: no`) | AC1 GIVEN/THEN headers — proxy-buffering defence + cache-disable + connection persistence |
| 3.4-UNIT-005 | U | P0 | `Flush()` via `http.ResponseController` succeeds even when ResponseWriter is wrapped by a non-Flusher middleware | **Load-bearing for production** — BR-1.10; guards against `obs.WrapHTTPHandler` middleware regression |
| 3.4-UNIT-006 | U | P0 | `Flush()` returns `errors.Is(err, streaming.ErrFlushUnsupported)` on a non-Flushable writer | BR-1.10 defensive contract — caller-detectable failure |
| 3.4-UNIT-007 | U | P1 | `Writer.Close()` returns nil + no underlying-writer mutation | BR-4.4 no-op surface (no per-stream resource holders this Story; defence for future Writer impls) |
| 3.4-UNIT-008 | U | P0 | Two `WriteEvent` calls → headers written exactly once (second call does not re-`Header().Set()`) | Guards against future regression that would call `Header().Set()` inside the per-chunk loop |
| 3.4-BLIND-ERROR-001 | U | P2 | `Writer.Close()` returning non-nil → handler logs at WARN level (`event=sse_writer_close_failed`); no panic | **[BLIND-SPOT ERROR-005]** — defensive for future Writer implementations that hold per-stream resources |

#### AC1.C — Word-Boundary Splitter (Unit)

| ID | Lvl | Pri | Test | Why |
|----|-----|-----|------|-----|
| 3.4-UNIT-018 | U | P0 | Table-driven `splitContentIntoChunks(s, targetN)`: (a) canonical MockContent + targetN=8 → exact 8-element slice byte-for-byte; (b) empty string → empty slice; (c) single word → single-element slice; (d) leading/trailing whitespace → trimmed; (e) multiple consecutive spaces → collapse-on-join | **AR1-R1 contract** — BR-4.3 word-boundary via `unicode.IsSpace`; the canonical-input fixture is the regression bottleneck future edits cannot bypass |

### AC2 — TTFB Performance Budget: In-Process P95 ≤ 300ms

| ID | Lvl | Pri | Test | Why |
|----|-----|-----|------|-----|
| 3.4-INT-001 | I | P0 | 100-iter `httptest.NewRecorder` measurement; assert P95 ≤ 300ms | **Load-bearing AC2** — the epic SLA; in-process measurement isolates gateway contribution |
| 3.4-INT-002 | I | P0 | 100-iter `httptest.NewServer` (loopback TCP) measurement; assert P95 ≤ 300ms AND `(loopback_p95 - recorder_p95) < 20ms` | **Load-bearing two-mode** — proves the in-process recorder isn't masking a latency contribution; guards against "passed in-process, regressed on the wire" failure mode |
| 3.4-INT-003 | I | P1 | 10-iter measurement; assert P50 < 5ms | **Sleep-regression catch** — catches a future `time.Sleep` in the chunker BEFORE it breaches the 300ms budget; cheap (10 iters) and tight (5ms ceiling = 60× tighter than P95 budget) |

**Note**: All three tests share the `measureTTFB(t, n)` helper (T2.5.1) and emit `t.Logf("ttfb_ms p50=%d p95=%d p99=%d", ...)` per BR-2.4 + T2.5.5 so the Dev Log captures concrete numbers for the review trail.

## Execution Order

Per `test-priorities-matrix.md` — fail fast on critical issues, defer edge cases:

1. **P0 Unit** (20 SM-enumerated): `go test ./apps/api-gateway/internal/streaming/...`
   - Wire-format primitives (UNIT-001..006, 008) — sub-second; first signal of byte-format regression
   - Chunker shape + ordering (UNIT-009..017) — sub-second
   - Splitter (UNIT-018..019) — sub-second
   - Cancellation guard (UNIT-020, 021) — sub-second
2. **P0 Integration** (11 SM-enumerated): `go test ./apps/api-gateway/internal/handlers/... -run 'TestChatCompletionsStream'`
   - Dispatch fork + Story-3.3 preservation (INT-004..007) — ~5s
   - Structured logging (INT-008, 009) — ~2s
   - Cancellation + leak (INT-011..013) — ~5s
   - TTFB (INT-001, 002) — ~30s (100 iters × two modes); also tests `-race` clean per BR-2.4
3. **P0 E2E** (3 SM-enumerated): `pytest apps/api-gateway/tests/openai_sdk_streaming_contract_test.py -k "happy_path or concat or finish_reason"` — requires `HE_API_TEST_GATEWAY_URL`; ~5s wall-clock; guarded skip if env var unset
4. **P1** (13 — 2 unit + 5 int + 2 E2E + 4 blind-spot): runs same harness as above
   - UNIT-007 (Close no-op), UNIT-022 (firstFlushAt ordering)
   - INT-003 (P50 sleep-regression), INT-010 (retired marker), INT-014 (no-panic on flush error), INT-015/016 (bearer auth pair)
   - E2E-004 ([DONE] cleanly), E2E-005 (SDK pin)
   - BLIND-BOUNDARY-001/002 (splitter edges), BLIND-ERROR-002 (auth 503), BLIND-CONCURRENCY-001 (concurrent + cancel)
5. **P2** (4 blind-spot): runs at end of CI cycle / on-demand
   - BLIND-BOUNDARY-003 (string `stream`), BLIND-ERROR-001 (Close failure), BLIND-RESOURCE-001 (FD baseline), BLIND-FLOW-001 (duplicate submission `id` differs)

**Timing budget**: full P0+P1+P2 suite expected ≤ 90s wall-clock on a developer M-series MacBook (TTFB tests dominate at ~30s; goleak tests add ~5s; rest is sub-second). E2E suite gated on `HE_API_TEST_GATEWAY_URL` — adds ~5s when run, skips silently otherwise.

## Principles Applied

- **Shift left**: Unit (49%) > Integration (41%) > E2E (10%); cheapest signal wins
- **Risk-based**: P0/P1/P2 align with risk severity and load-bearing assertions
- **Efficient**: No duplicate coverage — explicit skip list above documents what was considered + rejected
- **Maintainable**: All scenarios have stable IDs (`3.4-{LEVEL}-{NNN}` or `3.4-BLIND-{CATEGORY}-{NNN}`); long-term grep-friendly
- **Fast feedback**: Full suite ≤ 90s wall-clock on dev machine; P0 unit subset is < 5s (sub-second per package)
