# Test Design: 8.2 — 入参过滤（命中拦截 + 错误码）

2026-06-10 | Turing (QA) | Level: **Comprehensive** (security focus) | Risk: **HIGH**

Source story: `docs/stories/8.2-input-content-safety-filter.md`
Architect Round 1: PASS (9/10) — OQ-8.2-1..7 all ratified; carry-forwards folded below.

## Overview

Total: **41** | Unit: 36 (88%) | Integration: 3 (7%) | Bench: 2 (5%)
Priority: **P0: 28, P1: 10, P2: 3**
Blind-Spot Scenarios: 14
HARD gates (no weakening): **8.2-UNIT-013** (exhaustive no-false-negative), **8.2-UNIT-014** (corpus-truth window). All perf scenarios are SOFT gates (`t.Log` on fail).

The defining risk is the **no-false-negative invariant**: a stored term that appears in request content but is NOT detected = a missed filter = a 备案 (生成式 AI 服务备案) compliance breach — the gravest defect class, inherited from 8.1's security posture.

> **Go adaptation:** project is Go (api-gateway handler + `safety-lexicon` library). Tests are `go test` / `httptest` / `testify`, run under `-race`. "E2E" for a headless gateway is `httptest` handler-level integration (INT-001/002) — there is no browser surface. The skeleton's forced-failure convention is adapted to `t.Skip("TODO[<id>]…")` (QA `*review` verifies zero `TODO[` skips remain) so the scaffold does not red the shared CI lane before Dev begins.
