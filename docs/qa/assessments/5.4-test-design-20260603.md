### Story-level Scenario-ID convention

- `5.4-UNIT-{NNN}` — Go unit test (testify + table-driven). In-process only. Mocks: `miniredis/v2` for Redis, `httptest`/in-process gRPC stub for notification-svc & auth-svc, `pgxmock`/testcontainers-go PG for the auth-svc repository handler. Pure functions (`evaluateThresholds`, `resolveDisplayName`) are mock-free.
- `5.4-INT-{NNN}` — Go integration test (build-tag `integration`). Requires real Postgres 16 (testcontainers-go) AND/OR Redis 7.2 (standalone OR **3-node cluster** for INT-029) AND/OR Kafka (KRaft). Reuses Story-5.1/5.2 testcontainers harness.
- `5.4-E2E-{NNN}` — Real-binary pytest in `apps/api-gateway/tests/5_4_e2e_test.py` (pytest 8.* + httpx 0.27.* + OpenAI SDK fixture — Story-3.3/5.1/5.2 toolchain REUSED); spawns gateway + auth-svc + notification-svc + mock SendGrid + testcontainers PG/Redis/Kafka; budget ≤ 90s wall-clock.
- `5.4-CHAOS-{NNN}` — Resilience with `toxiproxy` (notification-svc / PG / Redis fault injection); build-tag `chaos` (NOT in default CI; nightly gated per Story-4.x/5.1/5.2 precedent).
- `5.4-BLIND-{CATEGORY}-{NNN}` — blind-spot scenarios tagged `[BLIND-SPOT]`. Categories per `blind-spot-categories.yaml`. These are NOT a separate test count — each maps onto one of the UNIT/INT/E2E/CHAOS cells above and is cross-referenced in §Blind-Spot Coverage.

Dev MUST embed `// Scenario: {scenario_id}` Go comments atop each Go test function (and `# Scenario: {scenario_id}` for pytest) — `*review 5.4` greps these for AC traceability per Story 2.x/3.x/4.x/5.1/5.2 precedent.
