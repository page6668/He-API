### Source of Truth & Scope Locks (Architect Round-1, BINDING)

This test design is the **binding scenario contract for Dev**. The following Architect rulings (2026-06-10) supersede the SM defaults where noted and are encoded as test assertions:

- **Q-PLAN-CATALOG → code catalogue** `packages/plan-catalogue/` (NO `plan_entitlements` PG table) → migration is **`0012_create_feature_flags.sql`** (feature_flags-only). Tested: catalogue panic-at-construction 1:1 invariant (UNIT-003).
- **Q-ENTITLEMENT-ENFORCE → fail-safe-LOW, TTL ≤ 60s + immediate sentinel invalidation, NO sync PG/billing call on the hot path.** Tested: UNIT-016/018/019, INT-016..023.
- **Q-BETA-GATE → `min(plan, sandbox)`, NO tier exemption (Enterprise capped too).** Unavailable-direction is split: **booting pod, no Redis AND no PG → beta OFF** (UNIT-028); **running pod loses Redis → holds last-known** (UNIT-029) — *two distinct directions, both tested.*
- **Q-ADMIN-BETA → Unleash console is the operator SoT. The in-app `POST /v1/admin/feature-flags/{key}` endpoint + the `admin-forbidden` code are DROPPED from 7.8.** Consequence: the "non-admin beta-flip rejection" P0 lane asserts the **absence of any He-API write surface** for `beta_mode` (INT-027), NOT a He-API 403.
- **Q-DISCOUNT → OUT.** Tiers grant limits + included-credit + features only; the 7.1 per-token markup is UNCHANGED (E2E-002 proves the coexistence).
- **Medium-1 → DROP `400_invalid_plan`; REUSE the 7.3-ratified `400_invalid_payment_request`** for unknown/empty plan. Tested: INT-004, UNIT-012, BLIND-BOUNDARY-001.
- **Medium-2 → singular `/v1/billing/subscription` ratified as a singleton sub-resource** (distinct from 7.3's plural `…/subscriptions` create-rail). Dev must add the §5.1.3 disambiguation note (verified at `*review`).
