## 6. QA 对 Architect 修订项的二次背书

QA 已对照 SM Story 文本 + 工作树状态二次核验 Architect Round 1 的 7 项发现，全部背书并作为后续 *test-design 阶段的输入。

| Architect Issue | QA 二次审视 | 立场 |
|---|---|---|
| **C1**: GitOps 自动 commit 无限循环 | `deploy-staging.yml on: push: branches:[main]` + `paths-ignore` 未排除 `infra/helm/**` + bot push values-staging.yaml → re-trigger 循环。Architect 方案 1（`${{ secrets.GITHUB_TOKEN }}` + `permissions: contents: write`）正确利用 GitHub "GITHUB_TOKEN created events do not trigger workflows" 文档化行为。 | **强烈同意 Critical**。test-design 必须新增故障注入用例：制造 main push 后验证不出现二次 deploy-staging run。 |
| **M1**: `wait-for-build` 轮询反模式 | 同意改用 `workflow_run` 触发器。需要 `build-images.yml` 把 image SHA 作为 artifact 输出供下游消费，test-design 加 verify 项。 | 同意 High |
| **M2**: step-level `if: secrets.X != ''` 不可靠 | 同意 env-mapping 模式（`env: HAS_ACR: ${{ ... && 'true' \|\| 'false' }}` + `if: env.HAS_ACR == 'true'`）。test-design 抽 2 条用例覆盖 has/no ACR 两条路径。 | 同意 High |
| **M3**: `golangci-lint ./packages/...` 无 Go module | 经核验 `go.work` 仅 `use ./apps/api-gateway`；`./packages/` 当前无 Go 源文件，会触发 "no Go files" 报错。作用域应改 `./apps/...`，README 本地 reproduce 命令同步。 | 同意 High |
| **m1**: `:staging-latest` mutable tag | 与 GitOps 不可变性原则冲突；仅保留 `:${git_sha}` 与 `:staging-<short-sha>`。 | 同意 Medium |
| **m2**: CGO_ENABLED 差异（`go test -race` 默认 CGO=1，distroless 静态 CGO=0） | 经典分支行为坑；CI 显式 `CGO_ENABLED=1 go test -race`，Dockerfile 显式 `CGO_ENABLED=0 go build`，dev log 注释。 | 同意 Medium |
| **m3**: `expectTypeOf<Empty>` 类型不存在 | 已核验 `packages/shared-types/src/index.ts` 未导出 `Empty`。采纳 Architect 给出的运行时占位方案（`expect(types).toBeDefined()`）。 | 同意 Medium |
