## Non-Blocking Observations

### obs-1 — Pre-existing flake in handlers package (Story 3.4 origin)

`TestChatCompletionsStream_ClientDisconnect_ConnectionClose` failed ~3/5 times in
`-count=1` mode without `-race`; passes consistently under `-race`. The test
polls the slog buffer for `client_disconnected=true` within a 1s deadline after
`srv.CloseClientConnections()` — TCP-FIN propagation timing on the test runner is
non-deterministic. This test was last modified in Story 3.4 and is **untouched
by Story 4.3** (BR-2.1/BR-2.2 explicitly REUSE Story-4.1 streaming handler +
AdapterChunker verbatim). The `qwen-max` model id in the request body is a
Story-3.4 default fixture; the test outcome is timing-independent of the model
field. Recommendation: open a follow-up to harden the assertion (e.g., poll
the `Flush()` → `Hijack()` boundary directly).

### obs-2 — Empirical curl --http2 verification deferred

T6.6 of the Tasks/Subtasks records that `curl --http2 -v
https://api.moonshot.cn/v1/chat/completions` was deferred to first live
deployment because the dev workstation lacks `KIMI_UPSTREAM_API_KEY`.
Compensating control: the `ForceAttemptHTTP2: true` policy + ALPN fallback is
verified by `TestClient_ALPN_NegotiatesHTTP11_WhenServerOffersOnlyHTTP11` and
`TestClient_ALPN_NegotiatesHTTP2_WhenServerOffersH2` against httptest in CI,
so the fallback branch is exercised regardless of upstream posture.

### obs-3 — SDK contract + live e2e skeletons env-gated

Per Story-4.1/4.2 deferred-live-execution posture. No new follow-up story
opened; inherits the already-tracked Epic-4 live-execution lane.
