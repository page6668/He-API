### AC2: 与 OpenAI 官方 Node/TS SDK 接口一致——改 import 即 drop-in 迁移

**Scenario**
```gherkin
GIVEN 一个原本用官方 `openai` npm SDK 的脚本：`import OpenAI from "openai"; const client = new OpenAI();`
WHEN 开发者改为 `import { Client } from "@he-api/sdk"; const client = new Client();`（导出名以 OQ-10.3-4 裁定为准），且设置 `HE_API_KEY`
THEN 客户端默认把请求发往 He-API 网关（默认 `baseURL` 指向 He-API，OQ-10.3-3；可经构造参数 / `HE_API_BASE_URL` 覆盖），凭据取自 `HE_API_KEY`（而非 `OPENAI_API_KEY`）
  AND `client.chat.completions.create(...)`（非流 + `stream:true` 异步迭代 `for await` + `stream_options.include_usage` 尾包）、`client.embeddings.create(...)`、`client.models.list()` 等调用面与 `openai` npm SDK **签名/返回类型一致**（响应是 openai-node 同型对象，TS 类型一致）
  AND 错误以 openai-node 的异常体系抛出（`OpenAI.APIError` 子类 `BadRequestError`/`AuthenticationError`/`RateLimitError`…），且 He-API 自定义错误码（`error.code`）与 `he_request_id` 可读
  AND He-API 扩展（路由策略 `X-He-Routing-Strategy`、A/B `X-He-AB-Models`、响应头 `X-He-Request-Id`/`X-He-Selected-Model`/`X-He-Cost-Usd`、自定义端点 `/v1/balance`·`/v1/usage`）通过 SDK 可达——**MVP 扩展面取舍由 OQ-10.3-4 钉死**
  AND 浏览器 vs Node 运行时定位明确（openai-node 默认 Node；浏览器需显式 opt-in——OQ-10.3-5）
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-10.3.6 | **「接口一致」= 继承而非追赶（沿用 10.2-OQ-1 范式，待 OQ-10.3-1 裁定）**：`@he-api/sdk` 的 `Client` 应**继承/组合官方 `openai` npm SDK 的 `OpenAI` 类**——drop-in 等价性、SSE 流（`for await`）、TS 类型、重试/超时全部**继承**，而非重写一套 fetch 客户端逐一追平（违 KISS）。 |
| BR-10.3.7 | **默认 baseURL + 凭据来源**：未显式传 `baseURL` 时默认指向 He-API 网关（生产域名 OQ-10.3-3；`/v1` 后缀遵循 openai-node「baseURL 后接路径」约定）；可经构造参数或 `HE_API_BASE_URL` 覆盖。凭据：未显式传 `apiKey` 时读 `HE_API_KEY`（**不读** `OPENAI_API_KEY`，避免与真 OpenAI 凭据串台）。 |
| BR-10.3.8 | **OpenAI 类型/异常透传**：re-export（或继承暴露）openai-node 的请求/响应类型与异常类，使既有以 `openai` 类型注解 / `instanceof OpenAI.APIError` 编写的代码改 import 后仍类型通过/运行。He-API 错误信封（5 字段，rest-api-spec §5.1.2）经 openai-node 异常的 `.code` / `.request_id` / body 可读。 |
| BR-10.3.9 | **`openai` 依赖 pin 策略 + drop-in 漂移防护**：网关合约测试侧 pin `openai` Python `==1.40.*`（注记其 12 月两次破坏性响应解析变更）；TS 侧选 openai-node 的 pin 区间（兼容上限 vs 紧 pin）+ 升级流程 = OQ-10.3-1 子项；须有测试在 pin 漂移/上游破坏时**早失败**。 |
| BR-10.3.10 | **He 扩展呈现（MVP 面待 OQ-10.3-4 钉死）**：路由策略 / A/B 经 per-request `headers`（openai-node `{ headers: {...} }` 选项原生支持）或便捷参数；He 响应头经 openai-node `.withResponse()` / `.asResponse()`（暴露 raw `Response`）读取；`/v1/balance`·`/v1/usage` 非-OpenAI 端点经 openai-node 的 `client.get(...)` escape-hatch 或薄便捷方法。**不**修改网关/proto/DB——纯消费侧。 |
| BR-10.3.11 | **多模态/音频自动继承**：视觉（9.5）、ASR（9.6 `/v1/audio/transcriptions`）、TTS（9.7 `/v1/audio/speech`）因网关 OpenAI 兼容 + SDK 继承 openai-node，**无需额外代码**即随 `client.audio.*` / 多模态 messages 可用；本 Story 仅需文档/冒烟覆盖，不为其新增实现（cut-line 归 OQ-10.3-4）。 |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| `apiKey`（构造） | string | 否（回落 env） | 显式 > `HE_API_KEY` env；二者皆缺 → 沿用 openai-node 缺 key 行为 | openai-node 原生 key-missing 错误 |
| `baseURL`（构造） | string | 否 | 显式 > `HE_API_BASE_URL` env > He-API 默认（OQ-10.3-3） | — |
| `headers`（路由/AB，per-request） | object | 否 | `X-He-Routing-Strategy ∈ {quality,cost,latency}`；`X-He-AB-Models` = 2 个不同具体 id（网关侧已校验，SDK 不重复实现） | 由网关返回 `400_invalid_request`，经 openai-node 异常透出 |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| 网关返回 He 自定义码（如 `402_quota_exhausted`） | 402 | openai-node 异常体系（`.code`/`.request_id` 可读） | SDK 透传，不吞码 |
| 未知 model id | 400 | `OpenAI.BadRequestError`，`.code == "400_invalid_request"` | 与既有 Python 合约测试行为一致 |
| 上游 5xx / 超时 | 502/504 | openai-node `APIError` 子类 | 透传 |

**Examples**
- Input: `import { Client } from "@he-api/sdk"; const c = new Client(); await c.chat.completions.create({ model:"qwen-max", messages:[{role:"user",content:"Hi"}] })` → Expected: 返回 openai-node 同型 `ChatCompletion`，请求落 He-API 网关。
- Input: `await c.chat.completions.create({ model:"he-router-cost", messages:[...] }, { headers:{ "X-He-Routing-Strategy":"cost" } })` → Expected: 网关按成本路由；`X-He-Selected-Model` 可经 `.withResponse()` 读到。
- Input: 流式 `const stream = await c.chat.completions.create({ ..., stream:true }); for await (const chunk of stream) {...}` → Expected: openai-node 同型 chunk 迭代，含 `[DONE]` 终止。
- Input: drop-in 等价性：把官方 `new OpenAI({baseURL, apiKey})` 换成 `new Client()`（默认 baseURL 指网关）→ Expected: 同型响应/流/错误。

## Dev Notes

> **核心原则**：He-API 网关**已是 OpenAI 线协议兼容**，且 **Story 10.2（Python SDK）已被 Architect 裁定（Wright, 2026-06-15, 9.8/10）确认「接口一致靠包装/继承官方 SDK（subclass）而非重写」**（OQ-10.2-1 RATIFIED）。本 Story 在 TS 侧**沿用该已批准范式**——包装/继承官方 `openai` npm SDK（openai-node）。Dev 不应需要读架构文档即可实现——关键事实已抄录于下。

### Technical Constraints
- **网关已 OpenAI 兼容（drop-in 前提，已核验）**：`/v1/chat/completions`（非流 + SSE `data:…\n\n` + `data: [DONE]\n\n`）、`/v1/embeddings`、`/v1/audio/{transcriptions,speech}`（9.6/9.7）、多模态 content（9.5）、`/v1/models`（capabilities 7 字段）、错误信封（OpenAI 5 字段 + `he_request_id`）。[→ docs/architecture/rest-api-spec.md#511-对外-apiopenai-兼容]
- **10.2 已立的范式（直接沿用）**：Story 10.2（`docs/stories/10.2-python-sdk-drop-in-openai-replacement.md`）= 仓库首个 SDK，Architect 裁定 **wrap/inherit 官方 SDK（subclass）** + 默认 base_url/key-from-env + 扩展面 cut-line + 分层测试（hermetic mock 必跑 + live 可选）。本 Story 是其 TS 镜像；**OQ-10.3-1 应继承 10.2-OQ-1 的裁定方向**，Architect 仅需确认 TS 生态特有差异（模块格式、浏览器运行时）。
- **PRD 产品原则**：「客户改 `base_url` 即可零代码迁移」[→ docs/prd/epics.md:53] + FR-11.1「至少 3 个官方 SDK（Python/Node/Go），每个 drop-in 一致」[→ docs/prd/requirements.md:99]。
- **drop-in oracle**：`apps/api-gateway/tests/openai_sdk_*_test.py` + `apps/api-gateway/tests/_protocol_invariants.py`（chat/chunk/embedding/error/model 形状断言 + `REQUEST_ID_RE=^req_[0-9a-f]{12}$`）证网关 OpenAI 兼容；TS 侧 hermetic 测试对位这些形状断言。
- **He 响应头读法**：openai-node 经 `.withResponse()`（返回 `{ data, response }`）或 `.asResponse()` 暴露 raw `Response`，读 `x-he-selected-model`/`x-he-request-id`/`x-he-cost-usd`（注：OQ5——`x-he-cost-usd` 网关侧**故意缺省**；[[project_cost_source_oq5_usage_ledger]]）。
- **TS 工具链现状（已核验）**：仓库 monorepo = pnpm（`pnpm-workspace.yaml` 纳 `packages/*`）+ turbo（`turbo.json` tasks `build`/`lint`/`typecheck`/`test`，`test` dependsOn `^build`）。范式包 `@he-api/shared-types`：`"type":"module"`、`main`/`types`/`exports` 指 `dist/`、`build: tsc -p tsconfig.json`、`lint: tsc --noEmit`、`test: vitest run`、devDeps `typescript ^5.4.5`/`vitest ^2.1.9`。root `tsconfig.base.json`：ES2022/ESNext/`moduleResolution:bundler`/`strict`/`declaration:true`。CI `pnpm test`（vitest via turbo，`.github/workflows/test.yml:29`）——**新包有 `test` script 即自动覆盖，无需新建 CI lane**（区别于 10.2 Python 需 bespoke lane）。
- **首个可发布 npm 包（关键差异）**：仓库现有 `@he-api/*` 包**全部** `"private": true`/`"version":"0.0.0"`（内部占位，从不发布）；无 npm publish / changesets / release workflow。本包是**首个真正可发布**的——须 `private` 非 true、`version` 真实、scoped 包加 `publishConfig.access:"public"`。发布管线归属见 OQ-10.3-2。
- **无 `openai` npm 依赖**：当前仓库 0 处依赖 openai-node（本 Story 引入）。openai-node 现状为 v4.x（发双 ESM+CJS）；pin 区间 + 模块格式对齐见 OQ-10.3-1/-3。
