### AC1: 调用日志读接口 — `GET /v1/me/usage/logs` (JWT-cookie, per-user IDOR-fenced, paginated + multi-dim filter)

**Scenario**
```gherkin
GIVEN
  - Story 9.1 shipped the ClickHouse `he_api.request_logs` MergeTree (ORDER BY (user_id, ts, he_request_id), 90d TTL) populated by analytics-svc
  - The gateway is started with HE_API_CLICKHOUSE_DSN set (else the route is simply not mounted — 404, graceful degradation, parity with /v1/me/usage/summary)
  - A user authenticates via the JWT cookie (he_access); their user_id is the verified JWT `sub`
WHEN
  - The console calls GET /v1/me/usage/logs?limit=50&offset=0&model=qwen-max&status=success&is_streaming=false&api_key_id=<uuid>&start=<rfc3339>&end=<rfc3339>
THEN
  - The gateway returns 200 with { items: LogEntry[], total_count, limit, offset, has_more }
  - EVERY row carries WHERE user_id = $JWT.sub — a user can NEVER see another user's logs (IDOR fence BR-RD-1)
  - Rows are ordered most-recent-first: ORDER BY ts DESC, he_request_id DESC; the queryable window is capped to the 1000 most-recent matching rows ("最近 1000 条")
  - Each LogEntry exposes ONLY non-PII observability fields (BR-RD-9); client_ip / client_country / user_agent / error_message / cost_usd are NEVER returned
  - Applied filters (model, status class, is_streaming, api_key_id, time range) narrow the set; unknown param or invalid value → 400_invalid_request
  - ClickHouse unreachable → 503_clickhouse_unavailable (canonical openaierr envelope); missing/expired JWT → 401_unauthenticated
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-RD-1 | **IDOR fence**: user_id is taken ONLY from `middleware.UserIDFromContext` (verified JWT `sub`). A `user_id` query param (or any unrecognized param) is a strict 400_invalid_request — never trusted. Every SELECT carries `WHERE user_id = ?`. [→ analyticsquery/handler.go:101-117] |
| BR-RD-2 | **Recent-window cap**: the endpoint exposes at most the **1000** most-recent matching rows. Server enforces `offset + limit ≤ 1000`; `offset ≥ 1000` → 400. `total_count = min(matching_count, 1000)`; `has_more = (offset + len(items) < total_count)`. |
| BR-RD-3 | **Pagination params**: `limit` ∈ [1,100] default 50; `offset` ∈ [0,999] default 0. Non-integer / out-of-range → 400_invalid_request with `param` set to the offending field. |
| BR-RD-4 | **Ordering**: `ORDER BY ts DESC, he_request_id DESC` (stable tie-break) so pages are deterministic under equal-`ts` rows. |
| BR-RD-5 | **Filter dimensions** (all optional, AND-combined): `model` (exact), `status` ∈ {success, client_error, server_error}, `is_streaming` ∈ {true,false}, `api_key_id` (UUID — and STILL fenced to the caller's own keys via user_id), `start`/`end` (RFC3339; `end > start`; range within the 90d TTL — older bounds simply return fewer rows). |
| BR-RD-6 | **Status class mapping**: success → `status_code < 400`; client_error → `status_code BETWEEN 400 AND 499`; server_error → `status_code >= 500`. Unknown value → 400. |
| BR-RD-7 | **Timezone**: `start`/`end` are interpreted as the explicit RFC3339 offsets the client sends; if omitted, no time bound is applied (the recent-window cap governs). The user-tz resolver is NOT needed here (absolute timestamps), unlike /summary. [→ analyticsquery/tz.go] |
| BR-RD-8 | **Conditional mount**: route wired only when `HE_API_CLICKHOUSE_DSN` is set, wrapped by `jwtVerifier.RequireJWT`, sibling to `GET /v1/me/usage/summary`. [→ cmd/server/main.go:410-438] |
| BR-RD-9 | **PII exclusion (non-negotiable)**: response projects ONLY {he_request_id, ts, model, upstream_model, status_code, is_streaming, prompt_tokens, completion_tokens, total_tokens, latency_ms_total, ttfb_ms, api_key_id, error_code}. `client_ip`/`client_country`/`user_agent` are ops-only (BR-ING-5 of 9.1); `error_message` is not ingested; `cost_usd` in request_logs is NON-AUTHORITATIVE (always "0", H-1-R) so it is excluded — per-request 消费 is out of scope ([[project_cost_source_oq5_usage_ledger]]). |
| BR-RD-10 | **No new store**: reuses the 9.1 `analyticsquery` ClickHouse connection (`OpenStore`) and the existing `request_logs` table. No migration, no new table, no new Kafka topic. |

**Data Validation**
| Field (query param) | Type | Required | Rules | Error Message |
|---------------------|------|----------|-------|---------------|
| limit | int | no (def 50) | 1 ≤ limit ≤ 100 | "limit must be an integer in [1,100]" → 400, param=limit |
| offset | int | no (def 0) | 0 ≤ offset ≤ 999 AND offset+limit ≤ 1000 | "offset must be in [0,999] and offset+limit ≤ 1000" → 400, param=offset |
| model | string | no | non-empty, ≤128 chars | "model filter invalid" → 400, param=model |
| status | enum | no | success \| client_error \| server_error | "status must be one of success/client_error/server_error" → 400, param=status |
| is_streaming | bool | no | "true" \| "false" | "is_streaming must be true or false" → 400, param=is_streaming |
| api_key_id | uuid | no | RFC4122 UUID | "api_key_id must be a UUID" → 400, param=api_key_id |
| start, end | rfc3339 | no | parseable RFC3339; if both set, end > start | "start/end must be RFC3339 and end > start" → 400, param=start\|end |
| (any other param) | — | — | unknown param rejected | "unrecognized query parameter" → 400_invalid_request |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| Missing/expired JWT cookie | 401_unauthenticated | (canonical) | console redirects to /signin?return_to=/logs |
| Invalid/unknown query param | 400_invalid_request | per Data Validation row | console shows inline filter validation; no query fired |
| ClickHouse unreachable / query error | 503_clickhouse_unavailable | (canonical) | console renders inline retry on the table card |
| Route not mounted (DSN unset) | — (404) | (none) | graceful degradation; console hides the page / shows unavailable state |

**Examples**
- **Input**: `GET /v1/me/usage/logs?limit=2&status=server_error` (user A) → **Expected**: `{ items: [{he_request_id:"req_…", ts:"…Z", model:"qwen-max", status_code:503, error_code:"503_clickhouse_unavailable", total_tokens:0, …}, {…}], total_count: 2, limit:2, offset:0, has_more:false }` — only user A's failed rows, newest first, no `client_ip`/`cost_usd`.
- **Input**: user B requests `?api_key_id=<a-key-belonging-to-user-A>` → **Expected**: `{ items: [], total_count: 0, … }` (the user_id fence yields zero — never user A's rows). IDOR-safe.
- **Input**: `?offset=1000` → **Expected**: 400_invalid_request, param=offset.

### AC2: 控制台调用日志页 — filterable, paginated log table (states + i18n ×10 + a11y)

**Scenario**
```gherkin
GIVEN
  - AC1's GET /v1/me/usage/logs is live, and the user is authenticated in the console
WHEN
  - The user navigates to /{locale}/logs (the "调用日志 / Request Logs" page)
THEN
  - A table renders the most-recent calls (columns: Time, Model, Status, Streaming, Tokens, Latency, API Key, Request ID) via an SSR fetch through a 'use server' action (cookie passthrough, cache: no-store)
  - A filter bar offers: Model (free text), Status (All/Success/Client error/Server error), Streaming (All/Yes/No), API Key (select of the user's keys), Time range (start/end); applying re-queries /logs and resets to offset 0
  - Pagination controls (Prev / Next, page indicator) walk the ≤1000-row window using limit/offset, honoring has_more
  - Loading → table skeleton; empty (total_count=0) → EmptyState ("No requests match these filters"); 503 → inline retry banner on the table card (filters stay intact); 401 → redirect to /signin
  - The table is accessible: semantic <table> with <th scope>, the filter bar is a labeled <form>, status is conveyed by text+icon (not color alone), pagination buttons have aria-labels and disabled states
  - All visible strings are i18n keys present in all 10 locales (ar de en es fr ja ko pt ru zh-CN); under ar the layout mirrors RTL while timestamps/IDs/numbers stay LTR
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-UI-1 | Page lives at `app/[locale]/(console)/logs/page.tsx`; data fetched in a `_actions/get-usage-logs.ts` Server Action (mirrors 9.1 `get-usage-summary.ts`: `'use server'`, cookie passthrough, `cache: 'no-store'`, discriminated-union result ok/unauthorized/error). |
| BR-UI-2 | Response parsed through a Zod `UsageLogsPageSchema` (mirrors `me-usage.ts` `UsageSummarySchema` safety net); malformed shape → generic error state, never a crash. |
| BR-UI-3 | Filters/pagination are reflected in the URL query (`/logs?model=…&status=…&offset=…`) so the view is shareable/back-button-safe; the page is a Server Component reading `searchParams`. |
| BR-UI-4 | `cost`/`消费` column is intentionally ABSENT (per-request cost is not authoritative — BR-RD-9). The table is volume/latency/status oriented. |
| BR-UI-5 | i18n: a NEW `logs` namespace (`messages/{locale}/logs.json`) OR extend `dashboard.json` — author as a dedicated `logs.json` across all 10 locales (next-intl, `getTranslations({namespace:'logs'})`); no hardcoded English. |
| BR-UI-6 | Status cell shows label+icon (success/client/server) — never color-only (WCAG 1.4.1); latency/tokens via `Intl.NumberFormat` (locale-aware). |
| BR-UI-7 | RTL (ar): document `dir="rtl"`; column order mirrors but timestamp, request_id, model id, and numeric cells render LTR (code-direction precedent, 5.5 Q-RTL1). |
| BR-UI-8 | Nav: add a "调用日志 / Request Logs" entry to the console sidebar with `aria-current` on the active route (mirrors 9.1 dashboard nav). Exact sitemap slot deferred to UX (see SM Open Questions Q-NAV). |

**Data Validation**
| UI input | Rule | Behavior on invalid |
|----------|------|---------------------|
| Time range (start/end) | end > start; both RFC3339 | inline field error; query not fired |
| Limit selector | one of {25,50,100} | constrained to enum (select), cannot be invalid |
| Model free-text | ≤128 chars | trim; empty = no filter |

**Error Handling**
| Scenario | Behavior |
|----------|----------|
| 401 from action | redirect to /signin?return_to=/logs |
| 503 from action | inline retry banner on the table card; filter bar + last good rows retained where possible |
| Empty result | EmptyState with reset-filters CTA |
| Malformed payload (Zod fail) | generic error state + Retry; logged |

**Examples**
- **Input**: user opens `/en/logs`, sets Status=Server error, clicks Next → **Expected**: table shows page 2 of server-error rows, URL `/en/logs?status=server_error&offset=50`, Prev enabled, Next disabled when `has_more=false`.
- **Input**: `/ar/logs` → **Expected**: RTL-mirrored layout, Arabic headers, but the Request-ID / timestamp / token columns remain LTR and correctly aligned.

### Database Design (WHY, not SQL)
- Querying `request_logs` directly (not the hourly_agg MV): the log viewer needs per-request rows, not aggregates. The MergeTree `ORDER BY (user_id, ts, …)` makes `WHERE user_id=? ORDER BY ts DESC` a primary-key range scan — efficient for the recent-window cap.
- "最近 1000 条" is enforced server-side as `offset+limit ≤ 1000` + `total_count = min(count, 1000)`, so the user can page through at most the 1000 newest matching rows without unbounded deep-pagination cost.

### Data Models (contracts, not impl)
- **Go** `LogEntry`: `{ HeRequestID string; Ts time.Time; Model string; UpstreamModel string; StatusCode int; IsStreaming bool; PromptTokens, CompletionTokens, TotalTokens int64; LatencyMsTotal int64; TtfbMs int64; ApiKeyID string; ErrorCode string }`. Response: `{ items []LogEntry; total_count int; limit int; offset int; has_more bool }`.
- **TS/Zod** `LogEntrySchema` mirrors the Go JSON exactly; `UsageLogsPageSchema = { items: LogEntry[], total_count: number, limit, offset, has_more }`.
