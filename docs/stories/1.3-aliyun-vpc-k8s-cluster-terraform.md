### AC1: K8s 集群可访问

**字面要求**: K8s 集群可访问

**展开（SM 解释，待 Architect Round 1 仲裁集群 API server 暴露策略后定稿）**:

- 通过 `terraform apply -chdir=infra/terraform/envs/staging` 成功创建以下阿里云资源：
  - 1 个 VPC（CIDR `10.20.0.0/16`，cn-shanghai region；prod env 使用 `10.30.0.0/16` 避免与 staging 路由冲突）`[Source: docs/architecture/infrastructure-deployment.md#7.1]`
  - 3 个 vSwitch（多 AZ：`cn-shanghai-f/g/h`，CIDR `10.20.{1,2,3}.0/24`），用于 ACK worker node 跨 AZ 分布
  - 1 个 NAT Gateway + EIP（worker node 拉镜像与访问外部 API 的统一出口；按量计费保证最小成本）
  - 1 个 ACK 标准托管版集群（K8s 1.29+）`[Source: docs/architecture/tech-stack.md#2.1; #7.2]`：
    - worker node 池：3 节点 ecs.c7.large（2C4G，按量计费可手动改包年包月），跨 3 AZ 分布
    - **集群 API server 暴露策略 = Path A2** `[Source: Architect Round 1 Q3 Ruling, Confidence M]`：
      - `cluster_endpoint_public_access_enabled = true`（变量名 `api_server_public_access_enabled`，默认 `true`）
      - `cluster_endpoint_public_access_allowed_cidrs = [...]`（变量名 `api_server_public_access_allowed_cidrs`，默认 `[]` — module 内 precondition 强制 `enabled=true` 时 `length(allowed_cidrs) > 0`）
      - 白名单来源（运维填入 `terraform.tfvars`）：
        - **GitHub Actions hosted runner egress CIDR**（来源：`curl https://api.github.com/meta | jq .actions`；运维每周由 cron 刷新；Story 1.7+ 引入 self-hosted runner 后此条删除）
        - **团队 operator 工作站 IP**（≤ 5 个 `/32`）
        - **公司 office NAT 出口**（如有）
      - `cluster_endpoint_private_access_enabled = true`（内网 always-on，供 1.4 ArgoCD 落地后 in-cluster controller 同步）
      - **拒绝路径 A**（强制 VPN）：本项目阶段无 VPN 基础设施，部署 VPN gateway 单独一周工作量；GHA hosted runner egress 本就是动态公开 CIDR，"白名单 GHA runner IP"等同于 A2 + 周期刷新
      - **拒绝路径 B**（公网无 ACL + 仅靠 client cert）：攻击面 = 全球公网 `:6443`；client cert 一旦泄漏即灾难（无 IP 边界 = 无回旋）
    - kubeconfig 写入 ACK 集群的 KMS-encrypted output；运维通过 `aliyun cs DescribeClusterUserKubeconfig` 拉取
  - 1 个 **ACR Enterprise Edition Basic 实例**（`payment_type = "Subscription"`, `period = 1` 月 ≈ ¥100/月）+ 1 个 namespace `he-api` + 1 个 repo `api-gateway`；endpoint 形如 `<instance_name>-registry.cn-shanghai.cr.aliyuncs.com`（独立 endpoint，不同于 Personal 共享 endpoint）；Story 1.2 的 `secrets.ACR_REGISTRY` 取此 EE 实例的 endpoint；ACR 子账号 + 临时 token 政策由 RAM 配置 `[Source: Architect Round 1 H-1 Fix A: Personal 被标 legacy，EE Basic 提供独立 endpoint + 镜像扫描 + 签名能力（Story 9 安全合规必需）；+¥100/月在 ¥1500 阈值内]`
- 通过 `kubectl get nodes` 输出 3 个 Ready 节点，节点角色 = `<none>`，跨 3 AZ 各 1 节点（`kubectl get nodes -L topology.kubernetes.io/zone` 可见）
- 通过 `kubectl get ns` 输出至少 `kube-system / he-api-staging / monitoring`（后两者由 `infra/k8s-base/namespace.yaml` 创建；`monitoring` 占位，1.4 装 Prometheus/Grafana）`[Source: docs/architecture/infrastructure-deployment.md#7.2]`
- 通过 `kubectl auth can-i --as=system:serviceaccount:he-api-staging:default get secrets -n he-api-staging` 输出 **`no`**（验证 NetworkPolicy + RBAC 最小权限基线 — 默认 ServiceAccount 不能直接读 Secret，必须通过 Workload Identity 链或显式 RoleBinding）
- **可验证标志**：操作员（拥有 ACK ReadOnly RAM 权限）在 30 秒内 `kubectl get nodes` 返回 3 行 Ready，screenshot/console 输出附 dev-log。

### AC2: Helm chart 可部署

**字面要求**: Helm chart 可部署

**展开（SM 解释）**:

- `infra/helm/api-gateway/` 目录交付完整 Helm chart 骨架：
  - `Chart.yaml`（apiVersion: v2, type: application, version: 0.1.0, appVersion: "0.1.0", `kubeVersion: ">=1.29.0-0"`）
  - `values.yaml`：默认值（`image.repository = he-api/api-gateway`、`image.tag = "0.1.0"`、`replicaCount = 1`、`service.type = ClusterIP`、`service.port = 8080`、`resources.requests = { cpu: 100m, memory: 128Mi }`、`resources.limits = { cpu: 500m, memory: 256Mi }`、`ingress.enabled = false`、`networkPolicy.enabled = true`）
  - `values-staging.yaml`：**关键**——必须存在且非空（关闭 Story 1.2 deploy-staging.yml 的 `HAS_HELM_VALUES` step probe fallback 分支）；遵循 **Architect Round 1 Q1 裁定 = 最小可部署 + 显式安全基线 override**，**仅包含以下字段**（多一字段都会引入 1.4/1.5/1.6 revise 时的 merge 冲突）：
    - `image.repository = ${ACR_REGISTRY}/he-api/api-gateway`（Story 1.2 deploy-staging.yml yq 占位写入）
    - `image.tag = "0.1.0"`（占位 SHA，由 Story 1.2 workflow `yq` 自动改写为 `${{ github.sha }}`）
    - `image.pullPolicy = IfNotPresent`（不用 `Always` — 避免每次重启都拉镜像；cost + latency 双优）
    - `service.type = ClusterIP`（staging 阶段不直接公网暴露；公网入口待 Story 1.4 ingress-nginx 接入）
    - `service.port = 8080`
    - `networkPolicy.enabled = true`（**必须显式 override**，即使 `values.yaml` 默认已 true；防止 `values.yaml` 默认变更时 staging 安全基线静默退化）
    - `serviceAccount.create = true`（显式启用，配合 T7 RBAC RoleBinding）
    - `serviceAccount.name = ""`（空字符串触发 `_helpers.tpl` 的默认命名 = `api-gateway`）
  - **values-staging.yaml 禁止字段（Story 1.3 阶段）** `[Source: Architect Round 1 Q1]`：
    - `ingress.*` — 由 Story 1.4 ingress-nginx 接入后，由 SM 在 Story 1.4 revise 时补充
    - `autoscaling.*` (HPA) — 由 Story 1.4 配合 metrics-server + Prometheus 接入后补充
    - `resources.requests/limits` 显式 override — 沿用 `values.yaml` 默认；Story 1.5 业务进入后调整
    - `env` / `envFrom` 中含明文凭证 — 永远禁止；走 Story 1.7+ Vault 接入
  - `templates/`：`_helpers.tpl`、`deployment.yaml`（含 readinessProbe `GET /healthz` + livenessProbe + resources + serviceAccountName + nodeSelector 占位）、`service.yaml`、`networkpolicy.yaml`（default deny ingress + allow from `kube-system/ingress-nginx`）、`serviceaccount.yaml`、`NOTES.txt`
- 通过 `helm lint infra/helm/api-gateway/` 退出码 0、无 ERROR 级警告
- 通过 `helm install api-gateway infra/helm/api-gateway/ --dry-run --debug -n he-api-staging -f infra/helm/api-gateway/values-staging.yaml` 渲染出可被 K8s API server 接受的 manifest（`--dry-run=server` 真实通过 K8s admission webhook 校验，不持久化）
- 通过 `helm install api-gateway infra/helm/api-gateway/ --debug -n he-api-staging -f infra/helm/api-gateway/values-staging.yaml` **真实** 安装到 staging 集群：
  - `kubectl rollout status deploy/api-gateway -n he-api-staging --timeout=60s` 等待 1 个 pod Ready（pod 拉的是占位 image `he-api/api-gateway:0.1.0`，若 ACR 还没真实镜像，**预期** Pod 进 `ImagePullBackOff` — 这是本 Story 阶段的预期行为，因为真实 image 在 Story 1.5 业务代码进入 + Story 1.2 build-images.yml 真实推 ACR 后才有；T6 验证脚本对该状态做 expected-failure 断言）
  - 紧接 `helm uninstall api-gateway -n he-api-staging` 清理（本 Story 阶段不长驻 staging pod 以节省 ACK 配额）
- `helm upgrade --install api-gateway ... --dry-run=server -f values-staging.yaml` 通过 server-side 校验（验证 `values-staging.yaml` 的全部字段被 Helm chart template 消费、无 unused/missing-required key）
- **可验证标志**：上述 4 条 `helm` 命令在 dev-log 中均有完整 stdout 记录，`kubectl describe pod -l app=api-gateway -n he-api-staging` 输出附 dev-log（确认 `ImagePullBackOff` 来自 image 不存在而非 RBAC/NetworkPolicy 阻挡）。

### 技术约束

- **Terraform 版本**: 1.7+，provider `aliyun/alicloud` 1.220+（最低支持 Aliyun Service Mesh 2.x + ACK 1.29） `[Source: docs/architecture/tech-stack.md#2.1]`
- **K8s 版本**: 1.29+（ACK 标准托管版） `[Source: docs/architecture/tech-stack.md#2.1; #7.2]`
- **Helm 版本**: 3.14+（chart apiVersion v2） `[Source: docs/architecture/tech-stack.md#2.1]`
- **云区域**: 主 cn-shanghai，灾备 cn-shenzhen（本 Story 仅交付 cn-shanghai；DR replication 由 Story 1.7+ 单独实施） `[Source: docs/architecture/infrastructure-deployment.md#7.1]`
- **VPC CIDR 规划**: staging `10.20.0.0/16` / prod `10.30.0.0/16`；vSwitch CIDR `10.{20,30}.{1,2,3}.0/24` 跨 AZ；service CIDR `172.16.0.0/16`；pod CIDR `172.20.0.0/16`。**禁止重叠** `[Source: docs/architecture/infrastructure-deployment.md#7.1; 默认规划]`
- **Terraform state 后端**: OSS bucket + KMS encryption + TableStore lock；**禁止** 使用 local state 或 git-stored state；state 文件包含敏感 output（kubeconfig），必须加密 `[Source: docs/architecture/security.md#8.1 存储分层]`
- **RAM 最小权限**: `tfstate-operator` 子账号 6 个 RAM policy（见 T10 README）；**禁止** 使用 Admin policy 或 root 账号执行 `terraform apply` `[Source: docs/architecture/security.md#8.1]`
- **secrets 处理**: 与 Story 1.2 一致——所有 secrets/vars 引用必须使用 `${{ secrets.* }}` 或 `${{ vars.* }}`，禁止 echo 完整 secret 值；Terraform output 中含 sensitive 字段必须标注 `sensitive = true`；ACR password 等动态密钥不通过 Terraform 持久化
- **K8s RBAC 基线**: 每个 `he-api-*` namespace 内 `default` ServiceAccount 仅获 `Role/api-gateway-runtime`（只读 ConfigMap + 自身 Pod），**禁止** 直读 Secret；Secret 访问走 Workload Identity 或显式 RoleBinding `[Source: docs/architecture/security.md#8.1]`
- **NetworkPolicy 基线**: 每个 `he-api-*` namespace 设置 `default-deny-ingress`；跨 namespace 通信默认 deny；ingress-nginx 显式 allow `[Source: docs/architecture/infrastructure-deployment.md#7.2]`
- **ACK 集群 API server 暴露策略 = Path A2**（Architect Round 1 Q3 Ruling，Confidence M）：`api_server_public_access_enabled = true`（默认）+ `api_server_public_access_allowed_cidrs = []`（必填，module precondition 强制非空）；白名单 = GHA hosted runner egress CIDR（来自 `api.github.com/meta`，运维周刷新）+ operator 工作站 `/32` ≤ 5 个 + 公司 office NAT 出口（如有）；内网 endpoint always-on；**拒绝** Path A（强制 VPN，无基础设施）/ Path B（公网无 ACL，攻击面=全球公网:6443）
- **镜像 tag 策略**（与 Story 1.2 m1 修复一致）: ACR 仅接受 immutable tag（`:${git_sha}`），**不**接受 `:staging-latest`；Helm `values-staging.yaml` 中 `image.tag` 由 Story 1.2 deploy-staging.yml workflow 写入真实 SHA
- **成本控制**: staging 预算 ≤ ¥1000/月；触达 ¥1500/月须运维 + Tech Lead 联合审批；prod 留待 Story 1.7+ 上线评审；本 Story 阶段**不交付** ECS 包年包月（按量计费便于回滚）
- **本 Story 不引入**: ArgoCD（Story 1.4）/ 任何可观测组件（Story 1.4）/ 任何业务数据库（RDS/Redis/ClickHouse/Kafka 全部留 Story 1.6）/ 任何业务 Go 代码（Story 1.5）

#### Q2: Terraform State Backend 选型

**Ruling**: **OSS + TableStore（Aliyun 原生）**。
**Confidence**: H

**Why**:
1. 项目唯一主云为阿里云（`docs/architecture/infrastructure-deployment.md §7.1`），腾讯云仅做 DR DNS 切换；DR 不共享 Terraform state（DR 由代码重建）→ 无跨云可移植性需求
2. TableStore 是 alicloud provider 官方文档化的 OSS backend 分布式锁机制，社区案例丰富，故障模式可观测
3. OSS+S3-compat lock 插件（如 `tflocks`）是社区维护，长期维护风险高；且 KMS encryption 在 S3-compat 接口下行为不一致
4. 运维成本：TableStore 按量计费 ≈ ¥1/月；S3-compat 锁额外多一个 ZooKeeper/Redis 依赖，运维成本提升不值

**T0 修订要求**：保持 `infra/terraform/backend.tf` 使用 `terraform { backend "oss" { ... tablestore_endpoint = ...; tablestore_table = "terraform-lock"; encrypt = true } }`。

#### Q3: ACK 集群 API server 暴露策略

**Ruling**: **Path A2（公网 EIP + ACL CIDR 白名单 + 强 RBAC）— 拒绝原始 Path A（强制 VPN）与 Path B（无 ACL 全开放）**。
**Confidence**: M (实操考虑)

**详细参数**：
- `cluster_endpoint_public_access_enabled = true`（变量名 `api_server_public_access`，默认 `true`）
- `cluster_endpoint_public_access_allowed_cidrs = [...]`（变量名 `api_server_public_access_allowed_cidrs`，默认 `[]` 强制必填）
- 白名单来源（运维填入 `terraform.tfvars`）：
  - GitHub Actions hosted runner egress CIDR（来源：`curl https://api.github.com/meta | jq .actions`；运维每周由 cron 刷新；Story 1.7+ 引入 self-hosted runner 后此条删除）
  - 团队 operator 工作站 IP（≤ 5 个 /32）
  - 公司 office NAT 出口（如有）
- `cluster_endpoint_private_access_enabled = true`（内网 always-on，供 1.4 ArgoCD 落地后用 in-cluster controller 同步）

**Why Path A2 vs Path A**：
- Path A 强制 VPN，但本项目当前阶段无 VPN 基础设施（部署 VPN gateway 是单独一周工作量，且 staging 阶段团队规模可能仅 2-3 人）
- GHA hosted runner egress IP 是动态公开的 CIDR 列表（不固定，但 `api.github.com/meta` 每周稳定）— Path A 中"白名单 GHA runner IP"实际等同于 Path A2 + 周期刷新；既然如此不如把"VPN 网段"也走 ACL 不强制 VPN

**Why Path A2 vs Path B**：
- Path B（公网无 ACL + 仅靠 client cert + RBAC）的攻击面是"全球公网 :6443"，client cert 一旦泄漏即灾难（无 IP 边界 = 无回旋）
- ACK API server 不需要从全球可达；ACL 白名单是 K8s 多家云厂商（EKS / AKS / GKE）的最佳实践默认值

**T2 修订要求**：将变量名 `api_server_public_access`（boolean）拆为：
```hcl
variable "api_server_public_access_enabled" { type = bool default = true }
variable "api_server_public_access_allowed_cidrs" { type = list(string) default = [] }
# Module 内部 precondition: enabled=true 时 length(allowed_cidrs) > 0
```
对应 `alicloud_cs_managed_kubernetes` 资源使用 `cluster_endpoint_public_access` + `cluster_endpoint_public_access_acl_cidrs`（确认 alicloud provider v1.220+ 字段名）。

**T1 修订要求**：删除 `vpn_allowed_cidrs[]` 变量（不再用 VPN 走 VPC 安全组）；VPC 安全组仅保留 VPC 内部连通规则，公网 API server 访问由 ACK 集群 endpoint ACL 接管（不同层）。
