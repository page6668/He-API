### AC3: Token-usage accuracy — adapter-reported `usage` (POST-identity-Normaliser) matches upstream-reported `usage` within < 1% delta for `glm-4`

**Scenario**
```gherkin
GIVEN the same setup as AC1/AC2 (gateway built, adapter deployed, `glm-4` resolves to `adapter-glm`)
AND a fixture set of ~10 representative prompts spanning short (< 100 chars), medium (~1KB), and long (~10KB) inputs across both system + user message types
AND Zhipu v4's `usage` JSON shape matches OpenAI per platform docs (`{"prompt_tokens": int, "completion_tokens": int, "total_tokens": int}`) — identity Normaliser per OQ-4.4-3 cascade from Story-4.2 OQ-4.2-3
WHEN the test issues `POST /v1/chat/completions` with `model=glm-4` for each fixture prompt across BOTH `stream=false` and `stream=true` paths
THEN
  - the adapter-reported `usage` (post-identity-Normaliser) matches the upstream-reported `usage` (from Zhipu's raw response JSON) within < 1% delta for ALL THREE fields (`prompt_tokens`, `completion_tokens`, `total_tokens`) — REUSE Story-4.1/4.2/4.3 oracle invariant (BR-3.1)
  - `usage.total_tokens == usage.prompt_tokens + usage.completion_tokens` (strict equality per BR-3.3 — enforced by `packages/adapter-usage.ValidateInvariants(prompt, completion, total)`)
  - `usage.prompt_tokens > 0` (non-empty prompt always tokenises)
  - `usage.completion_tokens >= 0` (zero-length completion is possible for content-filter trigger; total still == prompt + 0)
  - the gateway forwards `usage` VERBATIM in the OpenAI response (no re-tokenisation, no Tiktoken fallback — BR-3.1 oracle invariant REUSED from Story-4.1/4.2/4.3)
WHEN upstream returns `usage` with `total != prompt + completion` (constraint violation)
THEN
  - `Normaliser.Normalise` returns `ErrUsageConstraintViolation` (REUSE `packages/adapter-usage.ValidateInvariants` from Story-4.2 M1 lift)
  - the gateway maps to 502 + `502_upstream_unavailable` (BR-1.4); the adapter slog record carries `validation_failure=usage_constraint_violation` + `upstream_raw_usage=<sanitised JSON>` (PII-safe — the raw usage shape is metadata, NOT request content)
WHEN upstream returns `usage` field MISSING entirely from terminal chunk (non-streaming) OR from the stream-options-opted tail chunk (streaming)
THEN
  - the adapter returns a 502 envelope per BR-1.4; the adapter slog record carries `validation_failure=missing_usage` (AC3 enforcement — usage is NON-OPTIONAL by contract per Story-4.1/4.2/4.3 BR-3.4 REUSE)
  - OQ-4.4-5 ratification: if Zhipu's v4 endpoint DOES NOT honour `stream_options.include_usage=true` opt-in (i.e., the tail chunk lacks `usage`), this clause STILL fires — the adapter does NOT compensate by emitting a fake `usage` value; instead the upstream is treated as non-conformant and the request fails (operator action: file ticket with Zhipu support; meanwhile the user gets a clear 502 instead of a fabricated count)
```

type NormalisedUsage = adapterusage.NormalisedUsage
var ErrUsageConstraintViolation = adapterusage.ErrUsageConstraintViolation

type Normaliser interface {
    Normalise(raw upstream.RawUsage) (NormalisedUsage, error)

type glmNormaliser struct{}

func (glmNormaliser) Normalise(raw upstream.RawUsage) (NormalisedUsage, error) {
