### Testing Requirements

> Test focus areas specific to this Story (edge cases, performance, complex validation).

- **Determinism (BR-1.10)**: every contract-test cell MUST be deterministic. ZERO retries at the workflow level. ZERO `time.sleep` calls in test bodies (use pytest fixtures with `tmp_path` / `monkeypatch` instead). Force-mutating one assertion in `_protocol_invariants.py` MUST trip ALL 20 matrix cells + 6 per-vendor contract files in T7.4 sanity check — if a mutation only trips a subset, the shared library wiring is incomplete.
- **Cross-vendor independence**: the 20 matrix cells MUST NOT share state. Specifically: each cell creates a FRESH `OpenAI` client via the `openai_client` conftest fixture (the fixture is function-scoped); chat-completion requests MUST be parametrised per-cell (no global request fixture). Otherwise, vendor A's response leakage could mask vendor B's regression.
- **Streaming-specific (BR-2.3)**: the matrix's streaming cells assert on `is_terminal` flag — the LAST non-DONE chunk in the SDK iterator is `chunks[-1]` (the SDK consumes `data: [DONE]` internally). MUST assert `chunks[-1].usage is not None` AND the usage triple satisfies `total == prompt + completion` AND `finish_reason == "stop"`. A cell that fails to find a terminal chunk indicates the adapter's `AdapterChunker` (Story 4.1 introduction) is not emitting the tail-usage chunk before `data: [DONE]`.
- **Error envelope discipline (BR-2.5)**: the matrix's three error scenarios (401 / 400 / 405) MUST verify `error.he_request_id` shape via `REQUEST_ID_RE = re.compile(r"^req_[0-9a-f]{12}$")`. A failing match indicates the Story 3.6 `middleware/requestid` middleware is NOT wrapping the error path — possible regression of the outermost-wrap invariant.
- **Adapter-fake fidelity (BR-1.1)**: each fake-upstream binary's response MUST be checkable by the production `apps/adapters/{vendor}/internal/upstream` parsing logic without modification. Verify locally by running `go test ./apps/adapters/{vendor}/...` against the fake-upstream (the existing per-vendor `tests/adapter_test.go` from Stories 4.1-4.6 already exercises this — Story 4.8 just confirms it still passes after the fake-upstream binaries land).
- **Workflow wall-clock budget (BR-1.9)**: T7.2 measures the wall-clock time. If the job exceeds 12 minutes, profile via `time` wrappers around each step group; common culprits are slow `go build` (use Go module cache via `actions/setup-go@v5 cache: true` — already enabled) and slow pytest collection (acceptable for ~30 test cases — investigate if > 30s).
- **Live-lane idempotency (BR-1.6)**: the live-lane workflow MUST be safely re-runnable (manual trigger should be cost-free in terms of state — the live tests are READ-only against vendor APIs; no upstream mutation). Specifically: contract tests MUST NOT spawn any persistent state at the vendor side. (The vendor APIs are stateless chat-completion endpoints — confirmed by Stories 4.1-4.6 OQ rulings.)
