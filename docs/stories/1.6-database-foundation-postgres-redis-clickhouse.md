## Acceptance Criteria

### AC1: 三数据库实例已通过 Terraform 在 staging 中 provisioned 并可达

**Scenario**
```gherkin
GIVEN Story 1.3 已建立 ACK cluster + VPC + Terraform state 后端 (OSS) 且 Story 1.4 OTel/Prom/Loki 栈已就绪
WHEN 运维在 `infra/terraform/envs/staging/` 执行 `terraform init && terraform plan && terraform apply`
THEN
  - PostgreSQL 16 实例（RDS，多 AZ）provisioned 且 status = Running
  - Redis 7.2 兼容 (Tair) 集群版实例 provisioned 且 status = Running
  - ClickHouse 24+ 实例 provisioned 且 status = Running
  - 三实例均位于 1.3 既定 VPC 私网（NO public endpoint）
  - 三实例均启用 TLS in transit + KMS 静态加密
  - 三实例的 connection endpoints 通过 `terraform output` 可读
  - 从 staging cluster 内任一 pod 跑 `scripts/db-doctor.sh` 在 5 分钟内退出码 = 0
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-1.1 | 三 DB 必须**全部**部署在 VPC 私网；任何 public IP / public endpoint 暴露均判 FAIL（合规 §9.1 "数据不出境"） |
| BR-1.2 | TLS in transit 必须**强制**（`require_ssl = true` for PG；`tls_enabled = true` for Tair/CH） |
| BR-1.3 | 静态加密必须使用 KMS 托管密钥（不接受默认加密） |
| BR-1.4 | 实例规格使用 SM 推荐 default（PG: `pg.n2.medium.2c`，Tair: `redis.shard.small.ce`，CH: 2c8g）— 仅为 staging baseline；prod 规格在 Story 9.x 单独定义 |
| BR-1.5 | Terraform module 必须**幂等**：第二次 `apply` 在无配置变化时报 `No changes` |
| BR-1.6 | Terraform module 必须输出 endpoint + port + 应用 user 名（**不**输出密码；密码由 K8s Secret 注入 — Vault deferred per M-1 ruling） |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| 任一 DB 实例 provisioning 失败 | TF-DB-001 | "Terraform apply 失败：<resource>" | 回滚 + 写入 dev-log + halt T1 |
| Public endpoint 检测到暴露 | SEC-DB-001 | "DB <name> exposed to public — VPC config error" | 立即 destroy + escalate to Architect |
| Doctor 脚本超时 (>5min) | DOC-DB-001 | "DB doctor wall-clock > 5min" | 写入 dev-log + dump 三 DB 健康状态 + FAIL AC1 |

### Technical Constraints

- **PostgreSQL 版本**：必须 `16+`（架构 §2.1 锁定；避开 17 [→ tech-stack.md#22-版本选择原则]）
- **Redis 版本**：必须 `7.2+`（Tair 7.0 兼容 Redis 7.2 ACL 模型 [→ tech-stack.md§2.1]）
- **ClickHouse 版本**：必须 `24+`（架构 §2.1 + §4.2 OLAP schema 依赖 `Decimal64` + `quantile()` 函数）
- **网络边界**：三 DB **必须**位于 1.3 既定 VPC 私网（`vpc-he-api-staging`），无 public IP；任何 0.0.0.0/0 入站规则均判 FAIL [→ infrastructure-deployment.md#71-云架构 + 9-合规架构compliance-architecture.md#91-数据不出境的架构强制]
- **TLS / KMS**：传输强制 TLS 1.2+；静态加密用阿里云 KMS（与 1.3 既定 KMS key 同源）
- **Migration 边界**：本 Story baseline migration **零应用表**；任何 `CREATE TABLE foo (...)` 业务表语句违反 BR-3.6，应推迟到 Epic 2 Story 2.x
- **Doctor 5min SLO**：`scripts/db-doctor.sh` wall-clock ≤ 300s（AC1 验收硬指标）
- **凭据**（Q3 / M-1 ruling: K8s Secret ONLY for 1.6；Vault deferred）：admin 凭据存于 K8s Secret `he-api-db-admin-creds` in `he-api-ops` namespace（ops-only RBAC，ACK KMS envelope-encrypted）；应用凭据存于 K8s Secret `he-api-db-creds` in `he-api-staging` namespace（app ServiceAccount RBAC，ACK KMS envelope-encrypted）。两层通过 **namespace + RBAC 分离**（NOT 通过工具分离）。Vault 仍是架构 §2.1 锁定 target state，但在 future 专属 Story 通过 ExternalSecret CR 替换 Secret data source（application contract 不变 → zero-touch 迁移）。**严禁** plaintext 写入 git / terraform state / 日志 [→ security.md#82-api-key-生命周期 类比执行]

### Database Design

本 Story **不**设计任何业务表。baseline migration 仅做：

**PostgreSQL** (`migrations/postgres/0001_baseline.sql`，**Q1 ruling: Atlas versioned mode**):
```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;     -- 提供 gen_random_uuid() per §4.1
CREATE SCHEMA IF NOT EXISTS he_api;
CREATE ROLE he_api LOGIN PASSWORD :'app_password';  -- :app_password injected via psql -v from K8s Secret (M-1 ruling: NO Vault)
GRANT USAGE, CREATE ON SCHEMA he_api TO he_api;
ALTER DEFAULT PRIVILEGES IN SCHEMA he_api GRANT ALL ON TABLES TO he_api;
```

**Invocation** (M-1 ruling: K8s Secret-sourced password, not Vault):
```bash
# Read application password from K8s Secret (NOT Vault)
APP_PWD=$(kubectl get secret he-api-db-creds -n he-api-staging -o jsonpath='{.data.app_password}' | base64 -d)
psql -v app_password="$APP_PWD" -f migrations/postgres/0001_baseline.sql
# In CI / `db-migrate.sh up`, the same env-var resolution applies via Atlas's variable substitution
```

**ClickHouse** (`migrations/clickhouse/001_baseline.up.sql`，**Q2 ruling: golang-migrate**):
```sql
CREATE DATABASE IF NOT EXISTS he_api;
CREATE USER IF NOT EXISTS he_api IDENTIFIED WITH plaintext_password BY {app_password:String};
GRANT SELECT, INSERT ON he_api.* TO he_api;
```

`migrations/clickhouse/001_baseline.down.sql` (m-2 ruling: empty stub required by golang-migrate paired up/down convention):
```sql
-- intentionally empty; baseline migration is one-way per BR-3.3 (rollback via destroy-and-re-provision, not migration)
```

**Redis** (ACL 通过 `redis-cli` 命令，非 migration 文件，记录在 `docs/architecture/database-bootstrap.md` runbook):
```bash
# App password sourced from K8s Secret he-api-db-creds in he-api-staging namespace
APP_PWD=$(kubectl get secret he-api-db-creds -n he-api-staging -o jsonpath='{.data.app_password}' | base64 -d)
redis-cli -h "$REDIS_HOST" --tls -a "$ADMIN_PWD" ACL SETUSER he-api on ">$APP_PWD" "~he-api:*" "&*" "+@read" "+@write" "+@stream" "-@dangerous"
```
