### AC1: 全 UI 在 10 种语言下完整本地化且可切换

**Scenario**
```gherkin
GIVEN 控制台已部署，支持的 10 个 locale = [en, zh-CN, ja, ko, es, fr, de, pt, ru, ar]
  AND 每个 locale 目录下存在 6 个 namespace JSON（common / auth / account / dashboard / logs / models）
WHEN 用户经 LocaleSwitch 切换到任意一个 locale（或 middleware 按 cookie / Accept-Language 协商出该 locale）
THEN 控制台**全部**已落地页面（marketing / auth / console 三个 route group）渲染**该语言的真实译文**，无英文回退、无裸 key、无 `[en-pending]` 占位
  AND 任何 namespace 的任一 key 不再出现 `MISSING_MESSAGE` 或 next-intl key-fallback
  AND 日期 / 时间 / 数字 / 货币经 `Intl.DateTimeFormat` / `Intl.NumberFormat` 按 locale 格式化
  AND 缺失翻译回退顺序为 user locale → 同语言变体（zh-TW→zh-CN, pt-BR→pt）→ en（en/zh-CN 已 100% 完整，回退仅对未来变体生效）
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-10.1.1 | **Namespace 接线（linchpin）**：`apps/console/i18n/request.ts` 当前**仅**向 `NextIntlClientProvider` 提供 `{ common }`，但代码库已广泛使用 `getTranslations('account'\|'dashboard'\|'logs'\|'models')` 与 `useTranslations('auth')`（见 Dev Notes 清单）。必须把 **`messages/{locale}/` 下全部 namespace** 接入 request config，使全部页面在 SSR/CSR 下都拿到译文。接线方式须对「未来新增 namespace」鲁棒（推荐按目录动态装载，避免再次漏接）。 |
| BR-10.1.2 | **占位翻译落地**：8 个非 en/zh-CN locale 仍带 `[en-pending]` 前缀占位串（每 locale 215 条：`account` 104 / `logs` 58 / `models` 35 / `dashboard` 18；`auth` 与 `common` 已全量翻译）。全部 8×215 = 1720 条须替换为**真实译文**，`[en-pending]` 前缀在仓库中归零（`grep -rl 'en-pending' messages/` 返回空）。 |
| BR-10.1.3 | **Key 集完整 + 不破坏 codegen 门禁**：`scripts/check-i18n-keys.ts`（key-set parity + ICU plural 分支）对 10 locale 全 PASS；`packages/i18n-keys/src/` codegen 漂移门禁（`git diff --exit-code` after `scripts/gen-i18n-keys.ts`）保持 GREEN。翻译落地**只改 value，不得改 key 集**——en 为 key SoT，其余 locale key 集必须与 en 逐一对齐。 |
| BR-10.1.4 | **运行时切换无重载**：切 locale 后页面内容立即刷新（`LocaleSwitch` 现有 Server Action `setLocale` + `usePathname` 重写路径），不触发整页 reload；`he_locale` cookie 持久化选择。 |
| BR-10.1.5 | **长文本不破坏布局**：长词 locale（de 尤甚）在 `lg`（1024px 设计基线）下导航 / 按钮 / 表头 / 卡片不溢出、不截断、不重叠（front-end-spec §6.2 测试要点）。 |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| 译文 value | string | 是 | 非空；不含 `[en-pending]` 前缀；ICU 占位符 `{name}` / plural 分支与 en 同构 | check-i18n-keys：`locale {x} namespace {n} key {k} still placeholder / plural-branch mismatch` |
| key 集 | set | 是 | 每 locale 每 namespace 的 key 集 == en 对应集合 | check-i18n-keys：`key set drift in {locale}/{namespace}` |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| 某 namespace 未接入 request config，页面用到其 key | （运行时） | next-intl `MISSING_MESSAGE` / 渲染裸 key | 视为 AC1 失败——BR-10.1.1 必须接入全 namespace |
| 某 locale 残留占位串 | （CI） | check-i18n-keys 非零退出 | 视为 AC1 失败——补齐真实译文 |
| 未知 / 不支持 locale 路由 | 404 | `notFound()`（现有 `isLocale` 守卫，不回归） | 维持现状，本 Story 不放宽 |

**Examples**
- Input: 用户在 `/en/dashboard` 点 LocaleSwitch 选「日本語」→ Expected: 跳 `/ja/dashboard`，dashboard / 导航 / account 菜单全部呈日文真实译文，数字按 `ja` 千分位格式化。
- Input: `grep -rl 'en-pending' apps/console/messages/` → Expected: 空输出（占位归零）。
- Input: CI 跑 `pnpm --filter @he-api/console check-i18n-keys` → Expected: 10 locale 全 PASS。

### AC2: 阿拉伯文（ar）RTL 布局正确

**Scenario**
```gherkin
GIVEN 用户切换到 ar（العربية）locale，文档根 `<html lang="ar" dir="rtl">`（现有 isRtlLocale 已置 dir）
WHEN 渲染 marketing / auth / console 任意已落地页面
THEN 整体布局按 RTL 镜像：行内起止、内边距 / 外边距、表格列序、下拉 / 菜单锚点、导航方向均正确镜像
  AND 方向性图标（返回箭头 / chevron / 展开收起）在 RTL 下镜像翻转
  AND **LTR 孤岛保留**：时间戳、Request ID、API Key、数字 / 跑分 cell、代码块、格式码（JSON / CSV）在 RTL 文档内仍以 `dir="ltr"` 左到右呈现（front-end-spec Story 9.2/9.3 实现说明）
  AND 不引入仅靠物理方向（pl-/pr-/ml-/mr-/text-left/text-right/left-/right-）而在 RTL 下错位的布局
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-10.1.6 | **逻辑属性迁移**：审计并改造 `components/` + `app/` 内 RTL-不安全的物理方向 Tailwind class（现状约 49 处：`text-left`×7 / `text-right`×6 / `mr-1`×4 / `pl-*` / `ml-auto` / `right-*` 等），改用逻辑属性（`ps-/pe-`、`ms-/me-`、`text-start/text-end`、`start-/end-`）。现已有约 36 处逻辑属性用法可作范式。`border-red` / `rounded-lg` 这类**非方向**类不在范围内（grep 噪声，勿误改）。 |
| BR-10.1.7 | **方向性图标镜像**：返回 / chevron / 展开等方向图标在 RTL 下镜像（CSS `[dir=rtl] .icon{transform:scaleX(-1)}` 或等价逻辑），非方向图标（logo / 状态图标）不翻转。 |
| BR-10.1.8 | **LTR 孤岛**：时间戳 / ID / API Key / 数字 / 跑分 / 代码 / 格式码（JSON·CSV）以 `dir="ltr"` 包裹，在 ar 文档内保持 LTR（避免 `12:34` / `req_abc123` 被 RTL 重排）。推荐单一可复用原语（见 Deliverable Bindings）。 |
| BR-10.1.9 | **dir 不回归**：`<html dir>` 由现有 `isRtlLocale(locale)` 决定（ar/fa/he/ur 集合），本 Story 不改协商逻辑，仅保证下游布局在 `dir=rtl` 下正确。 |

**UI Interaction**
| Trigger | Behavior |
|---------|----------|
| 切到 ar | `<html dir="rtl">`；导航 / LocaleSwitch 下拉锚点右对齐镜像；正文右起 |
| ar 下查看 Logs 表 | 列标题镜像；但 Time / Request ID / Tokens / Latency cell 保持 LTR（BR-10.1.8） |
| ar 下点「返回」 | 箭头指向镜像方向（指右），语义不变 |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| RTL 下因物理 class 出现错位 / 截断 / 反向 | （视觉回归） | Playwright RTL 快照 diff vs en 基线失败 | 改逻辑属性（BR-10.1.6） |
| 数字 / ID 在 ar 下被 RTL 重排 | （视觉回归） | LTR 孤岛缺失 | 加 `dir="ltr"` 包裹（BR-10.1.8） |

**Examples**
- Input: 访问 `/ar/dashboard` → Expected: `<html dir="rtl">`，整体右到左镜像，余额数字与图表数值仍 LTR 可读。
- Input: 访问 `/ar/logs` → Expected: 表头镜像、Time/Request ID/Tokens cell 保持 LTR；分页 Prev/Next 镜像。
- Input: Playwright `2.1-E2E-005`（现 `test.skip`）→ Expected: 实装并通过——`html dir="rtl"` + RTL 快照相对 en 基线呈逻辑属性镜像。

- **OQ-10.1-1 → (a) static namespace SoT.** Create `apps/console/i18n/namespaces.ts` exporting the canonical ordered namespace array; `request.ts` loads via `Promise.all(NAMESPACES.map(ns => import(\`../messages/${locale}/${ns}.json\`)))`. **Rationale**: the `${locale}/${ns}` dynamic-segment `import()` is statically analyzable by the Next/webpack bundler → one chunk per file, so **only the requested locale's namespaces ship in that locale's chunk** (directly satisfies T4.2 / 250KB budget). Directory/glob dynamic import is NOT statically analyzable (risks bundling all locales or runtime fs, unavailable on the edge/SSR path). The static array is the single SoT shared by `request.ts` + `check-i18n-keys.ts` + `gen-i18n-keys.ts` (kills the re-miss class of bug). **Keep the `LtrText`/`namespaces.ts` Deliverable Bindings** — do not inline.
