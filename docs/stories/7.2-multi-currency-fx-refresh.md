### AC1: 多币种展示 — USD 默认 / RMB 可切换（display-only conversion，不改 USD 记账 SoT）

**Scenario**
```gherkin
GIVEN
  - the 7.1 money-read surface ships GET /v1/balance → {"current_usd","currency":"USD","updated_at"} and GET /v1/usage → {"period","total_cost_usd","total_requests","total_tokens","by_model"}
  - USD (balances.current_usd + usage_ledger.cost_usd) is the SINGLE authoritative accounting SoT (7.1 BR-A-2 / reconciliation invariant)
  - a latest USD→CNY rate is available in he_api.fx_rates (AC2)
WHEN
  - a client calls GET /v1/balance (no currency selector) — the USD default path
  - OR a client calls GET /v1/balance?currency=rmb — the RMB display path (Q-PREF: stateless query param, SM DEFAULT)
  - OR a client calls GET /v1/usage?currency=rmb
THEN
  - **USD default (no selector / currency=usd)** → 200 with the EXACT 7.1 byte shape PRESERVED, additively carrying `fx_rate:"1.00000000"`, `current_display` == `current_usd`, `fx_as_of:"<RFC3339>"`; `currency:"USD"` (the existing 7.1 seam) — zero regression for existing clients (BR-B-7)
  - **RMB path (currency=rmb)** → 200 {"current_usd":"12.3400","currency":"RMB","current_display":"<USD×rate, HALF-UP 2dp string-decimal>","fx_rate":"<rate string>","fx_as_of":"<RFC3339 of the rate's fetched_at>","updated_at":"<RFC3339>"} — `current_usd` is ALWAYS present (the authoritative truth is never hidden, BR-B-3); `current_display` is the converted presentation value
  - **GET /v1/usage?currency=rmb** → the same additive treatment on `total_cost_usd` (adds `total_cost_display`, `fx_rate`, `fx_as_of`); per-model `by_model[]` cost stays USD unless a display variant is requested (Q-APISHAPE — SM DEFAULT: convert the top-line only for MVP)
  - **SoT invariant**: the deduction path, usage_ledger writes, the 402 pre-flight gate, and the SUM(usage_ledger.cost_usd) vs balances.current_usd reconciliation are BYTE-FOR-BYTE UNCHANGED from 7.1 — conversion is read-side display ONLY (BR-B-1)
  - **Unknown currency** (e.g. ?currency=eur / ?currency=xyz) → 400 `400_unsupported_currency` (§5.1.2 NEW — Architect to ratify code name); MVP supports exactly {usd, rmb} (BR-B-5)
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-B-1 | **Conversion is display-only.** USD stays the single accounting SoT; no story-7.2 code path writes `balances.current_usd`, `balances.current_rmb`, or `usage_ledger`. The 7.1 reconciliation invariant is preserved verbatim. (Q-SOT SM DEFAULT.) |
| BR-B-2 | The currency selector is the stateless `?currency=usd\|rmb` query param; absent ⇒ `usd`; case-insensitive; whitespace-trimmed. No persisted preference in MVP (Q-PREF). |
| BR-B-3 | `current_usd` (and `total_cost_usd`) — the authoritative USD value — is ALWAYS present on every response regardless of selected currency; the converted `*_display` field is ADDITIVE, never a replacement. |
| BR-B-4 | All money fields (USD and converted) serialize as **string-decimals** (`"12.3400"`) — Q-Spec-4 / 7.1 BR-A-3 cascade-lock; a JSON-number money field is a contract violation. `fx_rate` is a string-decimal too. |
| BR-B-5 | MVP supported display currencies = {USD, CNY/RMB} exactly (epic scope). Any other value → `400_unsupported_currency`. No silent fallback to USD on a bad value (fail loud, BR — wrong-currency display is a money defect). |
| BR-B-6 | Conversion uses `shopspring/decimal`, HALF-UP, display rounded to 2 dp; the rate read at NUMERIC(18,8). NEVER float64 (Architect 7.1 M-1 cascade, Q-ROUND). |

### AC2: 汇率刷新 — fx_rates 表 + 每日 UTC 00:00 自动刷新（外部源 + stale-serve 回退）

**Scenario**
```gherkin
GIVEN
  - a NEW he_api.fx_rates table (effective-dated rate rows; model_pricing effective_at precedent) seeded by migration 0009 with one bootstrap USD→CNY row (so day-0 reads work before the first cron)
  - a pluggable FxProvider (Q-FXSRC) that returns a USD-base rate, with an FX_MANUAL_USD_CNY override for dev/air-gapped/CI
  - a K8s CronJob scheduled at `0 0 * * *` UTC (Q-CRON; precedent: Story 5.4 monthly-cost-reset CronJob)
WHEN
  - the daily cron fires at 00:00 UTC and calls FxProvider for USD→CNY
THEN
  - **success** → INSERT a NEW fx_rates row {base='USD', quote='CNY', rate=<fetched>, source=<provider id>, fetched_at=NOW()} (append-only; the latest MAX(fetched_at) row becomes the active rate for AC1 conversion); emit `fx_refresh.completed` metric + slog
  - **provider failure** (timeout / non-2xx / malformed / rate ≤ 0) → STALE-SERVE: do NOT insert any row; the previous latest row remains active; emit `fx_refresh.failed` metric + slog + alert; the cron exits non-fatally so it retries next day (BR-C-3)
  - **idempotency**: re-running the cron within the same UTC day inserts at most one *effective* refresh per provider success; a duplicate same-rate fetch is acceptable (append-only audit) — reads always take MAX(fetched_at) so duplicates are harmless (BR-C-4)
  - **conversion read** (AC1) always reads the latest fx_rates row; NEVER calls the provider on the request hot path (BR-C-5)
  - **migration safety**: 0009 is additive (CREATE TABLE + seed), REVERSIBLE (atlas dynamic down drops fx_rates), NON-DESTRUCTIVE; `atlas.sum` row added (BR-C-6)
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-C-1 | `he_api.fx_rates` is APPEND-ONLY and effective-dated; the active rate is the `MAX(fetched_at)` row per (base, quote) pair (model_pricing `effective_at` precedent). Historical rows are retained (audit trail). |
| BR-C-2 | The refresh is a single-shot K8s CronJob at `0 0 * * *` UTC invoking a billing-svc subcommand — NOT a long-lived in-process timer (Q-CRON, 5.4 precedent). |
| BR-C-3 | **Stale-serve on failure**: provider timeout/error/malformed/non-positive rate ⇒ NO row inserted, last-known row stays active, alert emitted, cron exits non-fatally. A stale rate is served; a *wrong* (zero/null) rate is NEVER persisted or served (BR — money-display safety). |
| BR-C-4 | The cron is idempotent at the day granularity: a re-run that succeeds appends another (harmless) row; reads always take the latest. No UPDATE-in-place (avoids losing the audit trail + avoids a lost-update race). |
| BR-C-5 | The provider is NEVER called on the GET /v1/balance / /v1/usage hot path — conversion reads PG (or a boot+refresh in-proc snapshot, Q-FXCACHE). Provider latency/outage NEVER affects a user read. |
| BR-C-6 | Migration 0009 is ADDITIVE (CREATE TABLE + idempotent bootstrap seed `ON CONFLICT DO NOTHING`), REVERSIBLE (atlas dynamic down), NON-DESTRUCTIVE; `balances.current_rmb` is NOT altered (Q-RMBCOL SM DEFAULT: stays reserved). |
| BR-C-7 | The FX-provider base-URL/credential is a NEW secret — env-injected, NEVER logged (slog redaction), registered in docs/dev/secrets. The fetched rate value MAY be logged (it is public market data). |
| BR-C-8 | MVP fetches exactly USD→CNY. The FxProvider seam + fx_rates (base,quote) key are general enough to add pairs later without schema change. |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| provider `rate` | decimal | Yes | finite, `> 0`, parses as NUMERIC(18,8) | (cron-internal) reject → stale-serve (BR-C-3), no user-facing error |
| `FX_MANUAL_USD_CNY` (env override) | string-decimal | No | if set, `> 0`; bypasses the provider (dev/CI) | fail-fast boot error if set but unparseable |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| Provider timeout / non-2xx / malformed / rate ≤ 0 | (cron) | — | stale-serve: no insert, keep last row, `fx_refresh.failed` metric + alert, exit 0 (retry next day) — BR-C-3 |
| Provider returns same rate as last row | (cron) | — | append a new row (harmless, append-only) OR skip if identical (Q — SM DEFAULT: append; reads take latest) |
| Cold start: cron has never succeeded | (read) | — | the migration bootstrap seed row serves until the first successful refresh (BR-C-6) |

**Examples**

### Database Design (WHY, not full SQL)
- **`fx_rates` is append-only + effective-dated** (not an UPDATE-in-place single row): preserves a historical audit trail of rates (small table), avoids a lost-update race on concurrent cron runs, and lets `fx_as_of` expose staleness. Active rate = `MAX(fetched_at)` per pair — identical read shape to `model_pricing` latest-`effective_at` (6.2). [→ data-models.md §4.1]
- **Bootstrap seed row** in 0009 so day-0 / cold-start reads convert before the first cron fires (BR-C-6); `source='bootstrap'` distinguishes it from provider rows.
- **`balances.current_rmb` is NOT touched** — Q-RMBCOL DEFAULT is compute-on-read (single SoT, no staleness); the column stays at its 7.1 reserved DEFAULT 0. (If the Architect OVERRULES to a stored mirror, the cron would additionally UPDATE it — a scope increase to flag.)
