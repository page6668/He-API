## Epic Context
**Epic**: 10 - 多语言控制台、文档、SDK 与 Beta 上线
完整多语言体验 + 3 个 SDK（Python / TypeScript / Go）+ 文档站 + 上线检查表 + Beta 切换。Epic DoD 第 2 行「3 个 SDK 可用」由 10.2（Python）+ 10.3（TS）+ **本 Story（Go，3 个之末）** 共同关闭。本 Story **沿用 10.2/10.3 立的 SDK 工程范式**（drop-in 包装官方 SDK / 打包 / 发布 / 分层测试），把它落到 Go + Go modules 生态——但 **Go 无类继承**，且**本仓库本身即 Go**（网关 + 全后端服务），故 Go SDK 与前两个 SDK 有两处实质差异（实现形态、模块路径/发布拓扑），见下。

**Story Deliverables**:
- 一个可被 `go get` 的 Go module（epic AC: `go get github.com/he-api/sdk-go`），落位 `packages/sdk-go/`（source-tree.md:82 已预留），含包源 + `go.mod` + `*_test.go` + `README.md`，纳入仓库 `go.work`（AC1）
- 与 OpenAI 官方 Go SDK（`github.com/openai/openai-go`）**接口一致** 的客户端：默认 baseURL 指向 He-API 网关、从 `HE_API_KEY` 取凭据，chat / streaming / embeddings / models 等调用面与 `openai-go` 一致（drop-in，改 import + 构造即可迁移）（AC2）

## Acceptance Criteria

> **Note**: Epic-10 YAML 为 10.4 提供单条 legacy AC（`go get github.com/he-api/sdk-go 可用`）。下列 Enhanced AC 由 SM 依据该原文 + PRD FR-11.1（「至少 3 个官方 SDK（Python/Node/**Go**），每个与 OpenAI 官方 SDK 接口一致（drop-in）」`docs/prd/requirements.md:99`）+ 已核验仓库现状展开，**不新增** epic 未要求的范围。AC1 = 可 `go get` 的 module；AC2 = drop-in 接口一致（FR-11.1 对 Go 的落地）。
>
> **核心设计支点（与 10.2/10.3 同源，已核验）**：He-API 网关**本身已是 OpenAI 线协议兼容**（`docs/architecture/rest-api-spec.md §5.1`），且 PRD 明确「客户改 `base_url` 即可零代码迁移」（`docs/prd/epics.md:53`）。Story 10.2（Python）/ 10.3（TS）已为「接口一致靠包装官方 SDK 而非重写」立下范式（OQ-10.2-1 / OQ-10.3-1 RATIFIED = subclass）。
>
> **⚠️ Go 两处实质差异（本 Story 的真正待裁点，不是前两 SDK 的镜像继承）**：
> 1. **Go 无类继承**——10.2/10.3 的「`Client extends/subclass OpenAI`、仅重写构造器」范式**无法逐字平移**。`openai-go` 是 **functional-options** 设计（`openai.NewClient(opts ...option.RequestOption)`，服务以结构体字段挂载 `client.Chat.Completions.New(ctx, ...)`），没有可「重写」的构造器。Go 惯用的 drop-in 应靠**构造器包装 + 预置默认 `option.RequestOption`**（注入默认 baseURL + `HE_API_KEY`）实现，而非类型继承。这是 OQ-10.4-1（LINCHPIN），SM 强烈倾向「构造器包装/预置 options」。
> 2. **模块路径 = 导入路径 = VCS URL（无 PyPI/npm 式名称中介）**——epic AC 字面 `go get github.com/he-api/sdk-go`（**独立仓库**路径），但本 monorepo 既有约定是 `github.com/he-api/he-api/packages/*`（如网关 `github.com/he-api/he-api/apps/api-gateway`）。二者冲突，且 Go 的发布即「在 module path 对应的 VCS 上打 `vX.Y.Z` tag」（无独立 registry）。归属 + 发布拓扑见 OQ-10.4-2（需 PO 协同）。
>
> **本仓库即 Go（与前两 SDK 的另一关键差异）**：网关 + 全后端服务皆 Go（`go.work` 含 21 个 module，Go 1.25.0），故本 Story **非绿地**——必须遵循仓库既有 Go 工具链（golangci-lint + gofumpt + `go test -race`），而非像 10.2/10.3 那样新引入打包/测试体系。

### AC2: 与 OpenAI 官方 Go SDK 接口一致——改 import + 构造即 drop-in 迁移

**Scenario**
```gherkin
GIVEN 一个原本用官方 `openai-go` 的脚本：`import "github.com/openai/openai-go"; client := openai.NewClient(option.WithAPIKey(...))`
WHEN 开发者改为 `import heapi "<module-path>"; client := heapi.NewClient()`（符号名以 OQ-10.4-4 裁定为准），并设置 `HE_API_KEY`
THEN 客户端默认把请求发往 He-API 网关（默认 baseURL 指向 He-API，OQ-10.4-3；可经构造 option / `HE_API_BASE_URL` 覆盖），凭据取自 `HE_API_KEY`（而非 `OPENAI_API_KEY`）
  AND `client.Chat.Completions.New(ctx, ...)`（非流 + streaming `ssestream` 迭代 `stream.Next()/.Current()` + `stream_options.include_usage` 尾包）、`client.Embeddings.New(...)`、`client.Models.List(...)` 等调用面与 `openai-go` **签名/返回类型一致**（响应是 openai-go 同型对象）
  AND 错误以 openai-go 的错误体系返回（`*openai.Error` / `apierror`），且 He-API 自定义错误码（`error.code` 如 `402_quota_exhausted`）与 `he_request_id` 可读
  AND He-API 扩展（路由策略 `X-He-Routing-Strategy`、A/B `X-He-AB-Models`、响应头 `X-He-Request-Id`/`X-He-Selected-Model`、自定义端点 `/v1/balance`·`/v1/usage`）通过 SDK 可达——**MVP 扩展面取舍由 OQ-10.4-4 钉死**
  AND **无独立 async 客户端**（Go 以 `context.Context` + goroutine 为并发模型，openai-go 本身即 context-based——区别于 Python 10.2 的 `AsyncClient` delta，Go 不需要）
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-10.4.6 | **「接口一致」= 包装而非追赶（Go 形态 = 构造器预置 options，待 OQ-10.4-1 裁定）**：因 Go 无类继承，`openai-go` 又是 functional-options 设计，drop-in 应靠 **`heapi.NewClient(opts ...option.RequestOption)` 预置默认 `option.WithBaseURL(DEFAULT)` + `option.WithAPIKey(HE_API_KEY-from-env)` 再调 `openai.NewClient(...)`** 实现——chat/embeddings/models/streaming/重试/超时全部**由 openai-go 提供**，不重写一套 `net/http` 客户端（违 KISS）。这是 10.2/10.3「继承等价性」在 Go 的等价表达，**非类型继承**。备选（结构体嵌入 `type Client struct{ *openai.Client }`）由 OQ-10.4-1 一并裁。 |
| BR-10.4.7 | **默认 baseURL + 凭据来源**：未显式传 baseURL option 时默认指向 He-API 网关（生产域名同 10.2/10.3-R-OQ-3 = `https://api.he-api.com/v1`，待 OQ-10.4-3 确认）；可经构造 option（`option.WithBaseURL`）或 `HE_API_BASE_URL` env 覆盖。凭据：未显式传时读 `HE_API_KEY`（**不读** `OPENAI_API_KEY`，避免与真 OpenAI 凭据串台）。优先级：显式 option > env > 默认。 |
| BR-10.4.8 | **OpenAI 类型/错误透传**：直接复用 openai-go 的请求/响应类型与错误类型（包装方案下消费者直接拿到 `openai.*` 类型），使既有以 openai-go 类型 / `errors.As(err, &apierr)` 编写的代码改 import 后仍编译/运行。He-API 错误信封（5 字段 `code/message/type/param/he_request_id`，rest-api-spec §5.1.2）经 openai-go 错误的字段 / 原始响应可读。 |
| BR-10.4.9 | **`openai-go` 依赖 pin 策略 + drop-in 漂移防护**：网关合约测试侧 pin Python `openai==1.40.*`（注记其破坏性响应解析变更教训）。Go 侧选 `openai-go` 的 pin 区间（`openai-go` 仍 beta，更需谨慎）+ 升级流程 = OQ-10.4-1 子项；须有测试在 pin 漂移/上游破坏时**早失败**（对位 Python `test_sdk_pin_guard_openai`、TS pin-drift guard）。 |
| BR-10.4.10 | **He 扩展呈现（MVP 面待 OQ-10.4-4 钉死）**：路由策略 / A/B 经 per-request `option.WithHeader(...)`（openai-go functional option 原生支持）注入 `X-He-Routing-Strategy` / `X-He-AB-Models`；He 响应头经 openai-go 的 `option.WithResponseInto(&raw)`（或中间件）读取 `X-He-Request-Id`/`X-He-Selected-Model`；`/v1/balance`·`/v1/usage` 非-OpenAI 端点经 openai-go 的 `client.Get(ctx, path, ...)` escape-hatch 或薄便捷方法。**不**修改网关/proto/DB——纯消费侧。 |
| BR-10.4.11 | **多模态/音频自动继承**：视觉（9.5）、ASR（9.6 `/v1/audio/transcriptions`）、TTS（9.7 `/v1/audio/speech`）因网关 OpenAI 兼容 + SDK 复用 openai-go，**无需额外代码**即随 `client.Audio.*` / 多模态 messages 可用；本 Story 仅需文档/冒烟覆盖，不为其新增实现（cut-line 归 OQ-10.4-4）。 |
| BR-10.4.12 | **`X-He-Cost-Usd` 例外（OQ5，已核验）**：网关在 OQ5 下 `X-He-Cost-Usd` **故意缺省/非权威**（合约测试 `openai_sdk_deepseek_contract_test.py` 断言其 `is None`，[[project_cost_source_oq5_usage_ledger]]）——SDK/测试**不得**假定其存在或据其计费。成本须经 `/v1/usage`·`/v1/balance` 单独读取。 |

### Technical Constraints
- **网关已 OpenAI 兼容（drop-in 前提，已核验）**：`/v1/chat/completions`（非流 + SSE `data:…\n\n` + `data: [DONE]\n\n`）、`/v1/embeddings`、`/v1/audio/{transcriptions,speech}`（9.6/9.7）、多模态 content（9.5）、`/v1/models`（capabilities 字段）、错误信封（OpenAI 5 字段 `code/message/type/param/he_request_id` + 请求 id 格式 `req_<12 hex>`，正则 `^req_[0-9a-f]{12}$`）。[→ docs/architecture/rest-api-spec.md §5.1「对外 API（OpenAI 兼容）」，错误信封 line 183-189]
- **10.2/10.3 已立的范式（沿用其精神，非逐字平移）**：两个先行 SDK 均 Architect 裁定 **wrap/subclass 官方 SDK** + 默认 baseURL/key-from-env + 扩展面 cut-line + 分层测试（hermetic mock 必跑 + live 可选）。**⚠️ Go 关键差异**：Go 无类继承——`openai-go` 是 functional-options（`openai.NewClient(opts ...option.RequestOption)`，服务挂结构体字段 `client.Chat.Completions.New(ctx,...)`），没有可重写的构造器。Go drop-in = **`NewClient` 预置默认 options 再调 `openai.NewClient`**（SM 倾向），备选结构体嵌入；OQ-10.4-1 钉死。
- **PRD 产品原则**：「客户改 `base_url` 即可零代码迁移」[→ docs/prd/epics.md:53] + FR-11.1「至少 3 个官方 SDK（Python/Node/**Go**），每个 drop-in 一致」[→ docs/prd/requirements.md:99]。
