### Technical Constraints

- **HTTP/2 negotiation policy** (Story-4.2 OQ-4.2-5 cascade default REUSE): `&http.Transport{ForceAttemptHTTP2: true}` — ALPN-negotiates HTTP/2 if upstream supports it, falls back to HTTP/1.1 cleanly. Architect Round 1 OQ-4.5-6 should empirically verify Volcengine's `ark.cn-beijing.volces.com` H2 support via `curl --http2 -v https://ark.cn-beijing.volces.com/api/v3/chat/completions`. [→ [Story 4.2 Dev Notes / OQ-4.2-5 ratification](4.2-qwen-tongyi-qianwen-adapter.md), [Story 4.4 BR-1.7](4.4-glm-zhipu-adapter.md)]
- **Auth scheme** (Story-4.5-specific OQ-4.5-1): Volcengine historically used an HMAC-SHA256-signed-request auth scheme at legacy Maas endpoints (`maas-api.ml-platform-cn-beijing.volces.com`). The Ark v3 OpenAI-compat endpoint uses plain `Authorization: Bearer <api_key>`. Architect Round 1 MUST confirm via `curl -H "Authorization: Bearer <key>" -d ... https://ark.cn-beijing.volces.com/api/v3/...` exploration that plain Bearer works (NOT HMAC-signed). If HMAC-signed is required, the adapter MUST implement the signing step BEFORE upstream calls — adds substantial non-trivial complexity (parallel to Story-4.4 OQ-4.4-1 Zhipu-legacy-JWT concern); Architect to document the path in their Round 1 ruling.
- **Endpoint-id translate** (Story-4.5-specific OQ-4.5-3 — first non-identity transform in any Epic-4 adapter): Volcengine Ark uses opaque `ep-20240xxx-xxxx`-shaped endpoint IDs as the upstream `model` body field, NOT the consumer-facing friendly names (`doubao-pro` / `doubao-lite`). The adapter implements a bidirectional `model` field rewrite: (a) outbound — `req.Model` → `endpoint_map.Lookup(req.Model)` BEFORE the upstream HTTPS call; (b) inbound — `response.Model` (Volcengine's echo of the endpoint id) → `req.Model` BEFORE returning to gateway. Both directions are implemented in `apps/adapters/doubao/internal/upstream/translate.go`. The lookup map is loaded at process startup from env vars `DOUBAO_PRO_ENDPOINT_ID` + `DOUBAO_LITE_ENDPOINT_ID` (per OQ-4.5-3 SM lean); env-var source is ConfigMap (per OQ-4.5-4 SM lean — ratification pending). If an env var is unset/empty, `endpoint_map.Lookup` returns `("", ErrUnsupportedModel)` and the adapter fails fast with `connect.CodeFailedPrecondition` per BR-1.12 (the upstream HTTPS call is NEVER initiated — no leaked empty-string `model` to Volcengine). This is the precedent for Story 4.6 (Ernie) which faces a similar but DIFFERENT translate concern.
- **Cold-start budget**: ≤ 2s (Story-4.1 M5 inheritance). Helm chart readiness probe gates the rollout — REUSE Story-4.4 `infra/helm/adapter-glm/templates/deployment.yaml` readiness probe definitions. [→ [Story 4.1 M5 ratification](4.1-deepseek-adapter-streaming-non-streaming.md)]
- **Namespace**: `he-api-adapters` (Story-4.1 M4 inheritance — shared across all six Epic-4 adapters). [→ [Story 4.1 M4 ratification](4.1-deepseek-adapter-streaming-non-streaming.md)]
- **Default timeout**: 60s configurable via `DOUBAO_UPSTREAM_TIMEOUT_SECONDS` env var (BR-1.8 REUSE Story-4.1/4.2/4.3/4.4 default). Propagated via `req.Context()` so client disconnect mid-stream cancels the upstream call within 200ms.
- **Vault path**: `kv/data/he-api/upstream/doubao/` per Story-4.1 OQ3 cascade. Manual rotation — Volcengine API keys do not support auto-rotation per current platform docs.

Live exercises against `ark.cn-beijing.volces.com` from non-mainland-China CI runners will likely exceed this due to cross-region network latency; QA captures p50/p95/p99 per-environment separately. #### Endpoint-id static lookup map (NEW for Story 4.5)

```go
// Imported at apps/adapters/doubao/internal/upstream/endpoint_map.go
package upstream

import (
    "errors"
    "os"
)

var ErrUnsupportedModel = errors.New("endpoint id not configured for model")

// endpointIDByModel is loaded at process startup from env vars per OQ-4.5-3
// SM lean. OQ-4.5-4 ratifies env-var source = ConfigMap (mounted via
// envFrom: configMapRef on the adapter Deployment).
var endpointIDByModel = map[string]string{
    "doubao-pro":  os.Getenv("DOUBAO_PRO_ENDPOINT_ID"),
    "doubao-lite": os.Getenv("DOUBAO_LITE_ENDPOINT_ID"),
}

// Lookup returns the Volcengine endpoint id for a friendly model id, OR
// ("", ErrUnsupportedModel) if the env var is unset/empty (BR-1.12
// fail-fast).
func Lookup(modelID string) (string, error) {
    epID, ok := endpointIDByModel[modelID]
    if !ok || epID == "" {
        return "", ErrUnsupportedModel
    }
    return epID, nil
}

// ReverseLookup is the symmetric helper for BR-1.11 inbound back-translate.
// Prefer reading req.Model from the Service per-request context for the
// canonical back-translate path; ReverseLookup exists as a defensive
// fallback for cases where the request context is not threadable.
func ReverseLookup(endpointID string) (string, error) {
    for friendlyID, epID := range endpointIDByModel {
        if epID == endpointID && epID != "" {
            return friendlyID, nil
        }
    }
    return "", ErrUnsupportedModel
}
```

#### Medium Issues (2)

- **m-1: `endpoint_map.go` package-init env-var snapshot is brittle for tests**
  (`apps/adapters/doubao/internal/upstream/endpoint_map.go`, Dev Notes Data Models §
  "Endpoint-id static lookup map").
  - Issue: the pseudocode `var endpointIDByModel = map[string]string{"doubao-pro":
    os.Getenv("DOUBAO_PRO_ENDPOINT_ID"), ...}` evaluates `os.Getenv` at package-import
    time. Tests using `t.Setenv` AFTER the test binary has imported the package will NOT
    mutate the map, breaking `4.5-UNIT-001..005` env-var-unset coverage (4.5-UNIT-004
    specifically requires verifying the env-var-empty branch).
  - Fix: refactor to lazy/explicit loading. Two acceptable shapes:
    ```go
    // Option A — constructor returns a snapshot map.
    func LoadEndpointMap() map[string]string {
        return map[string]string{
            "doubao-pro":  os.Getenv("DOUBAO_PRO_ENDPOINT_ID"),
            "doubao-lite": os.Getenv("DOUBAO_LITE_ENDPOINT_ID"),
        }
    }
    // cmd/server/main.go calls LoadEndpointMap() once at startup,
    // passes the result into NewService(... , endpointMap).

    // Option B — Lookup reads env vars on each call (acceptable: ~10ns/call,
    // negligible vs the HTTPS round-trip).
    func Lookup(modelID string) (string, error) {
        switch modelID {
        case "doubao-pro":  if v := os.Getenv("DOUBAO_PRO_ENDPOINT_ID");  v != "" { return v, nil }
        case "doubao-lite": if v := os.Getenv("DOUBAO_LITE_ENDPOINT_ID"); v != "" { return v, nil }
        }
        return "", ErrUnsupportedModel
    }
    ```
    Option A is preferred (DI-friendly, snapshot-stable per-process), but Option B is
    acceptable. Either way, the Story 4.5 pseudocode (lines 910-913 + 643-647) needs
    revision and `4.5-UNIT-004` MUST be able to test the env-var-empty branch without
    `TestMain` gymnastics.

- **m-2: SM-leaned `ReverseLookup` defensive-fallback is fragile under endpoint-id rotation**
  (Dev Notes Data Models § "Endpoint-id static lookup map", lines 926-937).
  - Issue: `ReverseLookup(endpointID string) (string, error)` searches the map for an
    endpoint id and returns the friendly id. SM admits it exists "as a defensive fallback
    for cases where the request context is not threadable" but ALSO admits "prefer reading
    `req.Model` from the Service per-request context (cheaper + avoids drift)." The
    fallback has a real failure mode: if an operator rotates `DOUBAO_PRO_ENDPOINT_ID` from
    `ep-A` to `ep-B` and the adapter is mid-flight with a request that left at `ep-A`,
    `ReverseLookup("ep-A")` after rotation returns `ErrUnsupportedModel` — silently
    breaking the per-chunk back-translate.
  - Fix: drop `ReverseLookup` from the initial Story 4.5 implementation; the per-request
    closure pattern (BR-1.11 + ratified OQ-4.5-3) covers all current use cases AND is
    rotation-safe. Defer reintroduction to a future Story IF a concrete use case
    materialises (YAGNI). T1.2 + Dev Notes pseudocode block (lines 926-937) revised.
