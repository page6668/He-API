### AC1: 用量趋势读接口 — `GET /v1/me/usage/series`（JWT-cookie，per-user 隔离）

**Scenario**
```gherkin
GIVEN
  - An authenticated console user (JWT-cookie session) with ≥1 day of usage history in he_api.request_logs / request_logs_hourly_agg (realised by Story 9.1)
WHEN
  - The console requests GET /v1/me/usage/series?range=30d&group_by=day (default), or with group_by=model | status
THEN
  - The endpoint returns { range, group_by, series: [{ bucket, key, requests, total_tokens, cost_usd }] } scoped to ONLY the caller's rows (WHERE user_id = $JWT.sub)
  - group_by=day  → one bucket per calendar day (request_logs_hourly_agg rolled up to day), key=null
  - group_by=model → buckets keyed by model (one logical line per model)
  - group_by=status → buckets keyed by status class (2xx success vs 4xx/5xx error)
  - Period buckets honour the user's timezone (Q-TZ parity with /summary); range bounded ≤ 90d
  - cost_usd is rendered for parity with /summary BUT is NON-AUTHORITATIVE on the volume store — see BR-CH-SERIES-2 (cost provenance carried forward from 9.1 H-1-R)
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-CH-SERIES-1 | `/series` lives in the SAME `apps/api-gateway/internal/analyticsquery` package + read-only ClickHouse pool that 9.1 stood up for `/summary`. REUSE the pool — do NOT open a second CH path. `[Source: 9.1 §File-Locations; rest-api-spec.md §5.1.3]` |
| BR-CH-SERIES-2 | Series points are bucketed by day (`request_logs_hourly_agg` rolled up) for By Day / By Model; By Status reads `request_logs` status classes. The volume metrics (requests/total_tokens) come from ClickHouse. **`cost_usd` series, IF surfaced, follows 9.1's H-1-R per-metric SoT split — the authoritative 消费 SoT is PG `usage_ledger`, NOT `request_logs.cost_usd` (always 0). SM default for 9.1b: the trend primary series is `requests` (the P-4 default); a cost series is OUT unless it reads `usage_ledger` per period-bucket. → Architect Q-SERIES-COST.** `[Source: 9.1 H-1-R ruling; project memory cost-SoT]` |
| BR-CH-SERIES-3 | Per-user IDOR isolation is the highest-stakes rule: every `/series` query filters `user_id=$JWT.sub`; cross-user reads impossible (BR-RD-1 parity, extended to the new endpoint). |
| BR-CH-SERIES-4 | USD-only display (no `?currency` — BR-RD-7 cascade from 9.1). |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| group_by | enum | no | day \| model \| status (default day) | unknown → `400_invalid_request` |
| range | string | no | ≤ 90d (default 30d) | out-of-range / malformed → `400_invalid_request` |

**Error Handling**
| Scenario | Code | Message (en) | Action |
|----------|------|--------------|--------|
| ClickHouse unavailable | 503 | (reuse 9.1's `503_clickhouse_unavailable` envelope — rest-api-spec §5.1.2) | client inline chart-card retry |
| Unknown group_by / out-of-range range | 400 | `400_invalid_request` (strict-reject, /summary parity BR-RD-7) | client fixes the request |

### AC2: 用量趋势图 — `<UsageChart>` (Recharts) 历史聚合可视化 (By Day / By Model / By Status)

> FIRST Recharts realization per front-end-spec §5.2 line 600. Retained verbatim from 9.1's deferred AC4.

**Scenario**
```gherkin
GIVEN
  - User is on /dashboard with ≥1 day of usage history
WHEN
  - The page renders <UsageChart> (FIRST realization per front-end-spec §5.2 line 600), which fetches GET /v1/me/usage/series?range=30d&group_by=day (default)
  - The user toggles By Model / By Status / By Day (P-4 "Toggle by Model / By Status / By Day")
THEN
  - A Recharts line chart renders the last-30-day series; By Day = one line of daily request_count; By Model = one line per model; By Status = success vs error lines
  - The toggle re-queries /series?group_by=... (client-side fetch via the typed client OR a Server Action — Architect Q-CHART-FETCH; SM default client fetch for the interactive toggle)
  - Empty (no history) → an EmptyState inside the chart card ("No usage in the last 30 days")
  - The chart is accessible: a visually-hidden data <table> mirrors the series for screen readers (Recharts SVG is aria-hidden); the toggle is a labelled control group
  - i18n axis labels + tooltip; RTL-aware (the chart x-axis stays chronological L→R even in RTL — code-block LTR precedent, 5.5 Q-RTL1)
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-CH-1 | `<UsageChart>` is the FIRST Recharts realization (tech-stack §2.1 Recharts 2.x; front-end-spec §5.2 `<UsageChart>` pre-declaration). Recharts (NOT ECharts — ECharts is reserved for Benchmark complex viz per §5 line 47). |
| BR-CH-2 | The chart consumes `GET /v1/me/usage/series` (AC1); the toggle changes `group_by`. Series points are bucketed by day (hourly_agg rolled up) for By Day/Model; By Status reads request_logs status classes. |
| BR-CH-3 | a11y: the SVG is `aria-hidden`; a visually-hidden `<table>` carries the same data (WCAG — non-text content alternative). The toggle is a `role=radiogroup` or labelled `<Tabs>` (Architect Q-A11Y). |
| BR-CH-4 | Loading = chart skeleton; error = inline retry (does NOT take down the whole page — the shipped 9.1 `<UsageStatCards>` band stays rendered). Range is bounded ≤ 90d (BR-RD-7). |
| BR-CH-5 | USD-only display (no currency toggle on the chart cost series, if any — BR-RD-7 cascade). The primary series is request_count (the P-4 default); cost/token series are secondary toggles ONLY if Architect rules a `usage_ledger`-backed cost series in-scope (Q-SERIES-COST). |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| group_by | enum | no | day \| model \| status (BR-RD-7) | unknown → `400_invalid_request` |
| range | string | no | ≤ 90d | out-of-range → `400_invalid_request` |

**Error Handling**
| Scenario | Code | Message (en) | Action |
|----------|------|--------------|--------|
| /series 5xx | 5xx | "Couldn't load the usage trend." | inline chart-card retry (page cards unaffected) |
| Empty history | 200 | "No usage in the last 30 days." | chart EmptyState |

**Examples**
- **Input**: 30 days of data, By Model → 6 lines (qwen-max, deepseek-v3, ...) of daily request counts.
- **Input**: By Status → 2 lines (2xx success vs 4xx/5xx error) — the visual companion to 9.1 AC2's success_rate number.
