### AC3: Locale 协商策略（cookie-first → Accept-Language → en）+ 回退链（zh-TW→zh-CN→en）+ ar RTL

**Scenario**
```gherkin
GIVEN apps/console/middleware.ts 已配置 next-intl middleware（`localePrefix: 'always'`, `localeDetection: true`）
AND apps/console/i18n/config.ts 声明了 fallback map: `{ 'zh-TW': 'zh-CN', 'zh-HK': 'zh-CN' }`（未来变体可扩展）
AND `app/[locale]/layout.tsx` 根据 locale 设置 `<html dir="rtl|ltr">`
WHEN 用户访问 `https://console.he-api.com/` 在以下 3 种情境下
THEN
  情境 A — 首次访问（无 cookie），浏览器 Accept-Language = `fr-FR,fr;q=0.9,en-US;q=0.8`：
    - middleware 检测 Accept-Language 顺序匹配 → 命中 `fr`（French 是 MVP locale）
    - 重定向 302 到 `/fr/`
    - 不写 cookie（仅显式切换时写）

  情境 B — 有 cookie `he_locale=zh-CN`，Accept-Language = `en-US`：
    - middleware 优先读 cookie → `zh-CN`（cookie-first）
    - 重定向 302 到 `/zh-CN/`

  情境 C — 用户在 `/en/` 页面通过 LocaleSwitch 选择 `العربية` (ar)：
    - LocaleSwitch onClick → Server Action `setLocale('ar')` 写 cookie `he_locale=ar; Domain=.he-api.com; Path=/; Max-Age=31536000; SameSite=Lax`
    - Server Action 触发 `redirect('/ar' + currentPath.replace('/en', ''))`
    - 浏览器收到 302 → 跳转 `/ar/`
    - HTML 渲染 `<html lang="ar" dir="rtl">`；布局自动镜像

  情境 D — 用户访问浏览器 Accept-Language = `zh-TW`（未声明的 locale 变体）：
    - middleware 应用 fallback map：zh-TW → zh-CN
    - 重定向 302 到 `/zh-CN/`

  情境 E — 用户访问 Accept-Language = `xh,sw` (Xhosa, Swahili — 均不在 MVP set)：
    - middleware 无匹配 → 兜底 `en`
    - 重定向 302 到 `/en/`
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-3.1 | Locale 检测优先级（高 → 低）：(1) cookie `he_locale`（must be in MVP locales set or fallback map keys）→ (2) Accept-Language header（按 q-value 排序，逐个尝试匹配 MVP locales）→ (3) Accept-Language 变体（如 zh-TW → fallback map → zh-CN）→ (4) `defaultLocale = 'en'` |
| BR-3.2 | Cookie 写入仅在用户**显式切换** locale 时触发；Accept-Language 命中导致的重定向**不写** cookie（避免覆盖用户后续显式选择前的隐含决定） |
| BR-3.3 | Cookie 属性（Architect Q4 SM proposal，待 Round 1 仲裁）：`name=he_locale`, `Domain=.he-api.com` (prod) / `.staging.he-api.com` (staging) / undefined (localhost 自动 host-only), `Path=/`, `Max-Age=31536000` (1 年), `SameSite=Lax`, **非 HttpOnly**（client 侧读 cookie 渲染 LocaleSwitch 当前态需要） |
| BR-3.4 | Fallback map（缺失翻译回退链）：`zh-TW → zh-CN`, `zh-HK → zh-CN`, `pt-BR → pt`, `pt-PT → pt`；不在 fallback map 也不在 MVP set 的 locale 一律回退到 `en`；fallback map 在 `apps/console/i18n/config.ts` 集中声明，next-intl middleware 与 packages/i18n-keys/ codegen 共享 |
| BR-3.5 | RTL 检测规则：`isRtlLocale(locale)` 函数（`apps/console/lib/i18n.ts` 提供）返回 true 当且仅当 locale ∈ `['ar', 'fa', 'he', 'ur']`（本 Story 仅 ar 在 MVP set，其他三个为未来扩展占位）；`app/[locale]/layout.tsx` 设置 `<html dir={isRtlLocale(locale) ? 'rtl' : 'ltr'}>` |
| BR-3.6 | Tailwind RTL 实现策略：使用 logical properties（`ms-*`/`me-*`/`ps-*`/`pe-*`/`text-start`/`text-end`）而非物理方向（`ml-*`/`mr-*`/`pl-*`/`pr-*`/`text-left`/`text-right`）；Tailwind 3.4 logical properties 原生支持；本 Story Demo 页 + LocaleSwitch 必须只用 logical properties（lint 规则 `@he-api/console/no-physical-direction` 由 packages/eslint-config 在后续 Story 引入；本 Story 仅在 PR review 中人工核查） |
| BR-3.7 | 浏览器跳转到不存在的 locale 路径（如直接访问 `/xx/`）必须返回 404（next-intl middleware `localePrefix: 'always'` 默认行为），不重定向 |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| Cookie `he_locale` 值 | string | conditional | 必须 ∈ `locales` 或 fallback map keys；超长（>16 字符）/ 包含非法字符 → 视同未设置，走 Accept-Language 路径 | 无（静默丢弃） |
| `Accept-Language` header | string | conditional | RFC 5646 格式；逐项尝试匹配 locales 与 fallback map | 无（无匹配走 defaultLocale） |
| Server Action `setLocale(newLocale)` 入参 | string (literal union) | YES | 必须 ∈ `locales`；不在则 Server Action 抛错 | "Invalid locale: {value}" (Server Action throws → 客户端 toast) |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| Cookie 值是已删除 / 未声明的 locale（如老用户曾设 `zh-TW`） | E-3.1 | 无（静默 fallback） | middleware 通过 fallback map 解析为 `zh-CN`；**不**主动改写用户 cookie（保持 cookie 原值，等待用户下次显式切换） |
| Server Action `setLocale` 收到非法 locale | E-3.2 | "Invalid locale: {value}" | 抛 Error；客户端 `<LocaleSwitch>` catch 后 toast 错误（toast 文案来自 `common.errors.invalidLocale`） |
| RTL locale 下 Tailwind logical properties 不生效（旧浏览器） | E-3.3 | 视觉上布局未镜像 | front-end-spec §8.1 断点未明确支持 IE/老 Edge；Playwright E2E 仅覆盖 chromium/firefox/webkit 主流版本；不做 polyfill |
| 用户禁用 cookie（隐私浏览模式） | E-3.4 | LocaleSwitch 切换后页面 locale 改变但下次访问回到 Accept-Language 路径 | 文档化此行为；不阻塞 |
| `Domain=.he-api.com` 在 localhost 开发环境被浏览器忽略 | E-3.5 | Cookie 写入失败但开发者侧不感知 | 开发模式下 `setLocale` Server Action 检测 `process.env.NODE_ENV === 'development'` → 省略 Domain（host-only cookie） |

**UI Interaction**
| Trigger | Behavior |
|---------|----------|
| 首次访问 `/` 浏览器 Accept-Language=`ja-JP,ja;q=0.9` | 302 重定向到 `/ja/`；不写 cookie；地址栏显示 `/ja/`；HTML lang=ja |
| 已登录用户从 `/en/dashboard`（未来 Story）切换到 `العربية` | Server Action 写 `he_locale=ar` cookie；redirect 到 `/ar/dashboard`；下次访问 `/` cookie 优先命中 ar |
| 用户在 ar 下访问页面 | 整个 `<html>` 切换 `dir="rtl"`；顶部导航从左到右变为从右到左（logical properties 自动镜像）；LocaleSwitch 下拉菜单的"打开方向"基于 Radix UI 的自动适配（不需要手动处理） |

**Examples**
- **Input**: `curl -i -H "Accept-Language: fr-FR,fr;q=0.9" http://localhost:3000/`
  **Expected**: `HTTP/1.1 302`；`Location: /fr/`；无 `Set-Cookie`
- **Input**: `curl -i -H "Cookie: he_locale=zh-CN" -H "Accept-Language: en-US" http://localhost:3000/`
  **Expected**: `HTTP/1.1 302`；`Location: /zh-CN/`；无 `Set-Cookie`（cookie 已存在）
- **Input**: 用户在 `/en/` 点击 LocaleSwitch 选 `العربية`
  **Expected**: 浏览器 Network 面板看到一个 Server Action POST → 响应 302 `Location: /ar/`；响应 `Set-Cookie: he_locale=ar; Domain=.he-api.com; Path=/; Max-Age=31536000; SameSite=Lax`
- **Input**: `isRtlLocale('ar')` / `isRtlLocale('en')`
  **Expected**: `true` / `false`
- **Input**: `curl -i -H "Accept-Language: zh-TW" http://localhost:3000/`
  **Expected**: `HTTP/1.1 302`；`Location: /zh-CN/`（fallback map 命中）

| BR-4.2 | LocaleSwitch 选项排序：固定按 `locales` 数组顺序（与 BR-2.2 字母序一致）；当前 locale 用 `aria-current="true"` + 视觉上 background highlight；点击当前 locale 不触发 Server Action（noop） |
| BR-4.3 | 切换 locale 必须通过 Next.js Server Action（不允许仅 client-side `router.push`）；Server Action 函数 `setLocale(locale: Locale)` 放在 `apps/console/app/[locale]/_actions/locale.ts`；调用顺序：(1) 校验 locale ∈ locales → (2) `cookies().set('he_locale', locale, {Domain, Path, Max-Age, SameSite})` → (3) `redirect('/' + locale + currentPath.slice(currentLocalePath.length))` |
| BR-4.4 | LocaleSwitch 必须满足 WCAG 2.1 AA 键盘可达性：(a) Tab 可 focus；(b) Enter/Space 打开下拉；(c) Arrow Up/Down 在选项间移动；(d) Enter 选中；(e) Escape 关闭；(f) focus ring 视觉 2px solid indigo-500（front-end-spec §1.3 主色） |
| BR-4.5 | LocaleSwitch 必须配 `aria-label="{common.localeSwitch.label}"` (e.g., en: "Change language", zh-CN: "切换语言")；下拉选项的 `aria-label` = 选项的原生语言名 |
| BR-4.6 | `scripts/check-i18n-keys.ts` 算法：(1) 读 `messages/en/{namespace}.json` 提取 key 集合（递归 flatten 嵌套 object）→ (2) 对每个非 en locale 读相同 namespace 文件 → (3) 对比 key 集合是否严格相等 → (4) 校验 ICU plural 模板的 branch 数（en/zh-CN 等少分支 locale 允许 `=N` + `other`；ar 必须含 `zero one two few many other` 全分支）→ (5) 任一不通过 → 输出详细 diff + exit code 1 |
| BR-4.7 | `scripts/gen-i18n-keys.ts` 算法：(1) 扫描 `messages/en/*.json`（每个文件 = 一个 namespace）→ (2) 对每个 namespace 提取 flattened key 集合 → (3) 输出 `packages/i18n-keys/src/{namespace}.ts` 含 `export type {Namespace}Keys = 'demo.title' \| 'demo.currentLocale' \| ...`（PascalCase namespace + `Keys` 后缀）→ (4) 同时输出 `packages/i18n-keys/src/index.ts` re-export 全部 namespace types |
| BR-4.8 | CI `console / i18n-keys-completeness` job 顺序：(1) `pnpm --filter @he-api/i18n-keys build`（执行 codegen + tsc）→ (2) `git diff --exit-code packages/i18n-keys/src/`（types drift 检测）→ (3) `pnpm exec tsx scripts/check-i18n-keys.ts`（messages 完整性）→ 任一失败即 CI fail |
| BR-4.9 | Bundle size budget 实现：使用 `@next/bundle-analyzer` + `size-limit`（rollup-plugin-size-limit）；`size-limit.json` 声明 `{ "path": "apps/console/.next/static/chunks/pages/[locale]-*.js", "limit": "250 KB", "gzip": true }`；CI 在 build 后执行 `pnpm exec size-limit`，超阈值 exit 1 |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| Server Action `setLocale` 入参 | `Locale` literal union | YES | 必须 ∈ `locales`；TypeScript 编译期保证 + 运行时 `locales.includes(locale)` 双重校验 | "Invalid locale: {value}" (Server Action throws) |
| messages namespace key（codegen 入参） | string | YES | 匹配 `^[a-z][a-zA-Z0-9]*(\.[a-z][a-zA-Z0-9]*)*$`（camelCase + dot-namespace） | codegen 输出 "Invalid key format: {key}" 并 exit 1 |
| size-limit config path glob | string | YES | 解析后必须命中至少 1 个文件 | "No files matched size-limit pattern: {glob}" |

| Scenario | Code | Message | Action |
|----------|------|---------|--------|

> Story-specific constraints unique to 2.1. Do NOT re-state general standards (those live in `docs/architecture/coding-standards.md` + `docs/architecture/tech-stack.md`).

- **TS-CONS-001 [Next.js 版本锁]**: Next.js = `14.2.x` latest minor。**禁止**升级到 15.x（React 19 RC 依赖）；禁止使用 `next@canary`。次要版本升级走单独 dep-bump Story。
  - [Source: docs/architecture/tech-stack.md §2.1 — "Next.js 14.2+ (App Router)"]
- **TS-CONS-002 [next-intl 版本锁]**: next-intl = `3.x` latest。本 Story **不**使用 next-intl v4（API 兼容性变化）。
  - [Source: docs/architecture/tech-stack.md §2.1 — "next-intl 3.x"]
- **TS-CONS-003 [App Router 强制]**: 所有路由必须在 `app/` 目录；**禁止** `pages/` 目录混用。
  - [Source: docs/architecture/tech-stack.md §2.1 — "(App Router)" 限定]
- **TS-CONS-004 [TypeScript strict 不可降级]**: `tsconfig.json` 必须 `strict: true` + `noUncheckedIndexedAccess: true`；**禁止** `// @ts-ignore`（用 `@ts-expect-error` + comment 替代）。
  - [Source: docs/architecture/coding-standards.md §12.2 — "strict mode TS"]
- **TS-CONS-005 [logical CSS properties]**: Tailwind 类名优先使用 logical（`ms-*`/`ps-*`/`text-start`），**避免** 物理方向（`ml-*`/`pl-*`/`text-left`），以便 ar RTL 自动镜像。
  - [Source: docs/front-end-spec.md §6.2 — "RTL 支持：阿拉伯文激活时整个文档 dir=rtl；图标方向自动镜像"]
- **TS-CONS-006 [国旗 emoji 禁用]**: LocaleSwitch 选项**不**含国旗 emoji；仅显示原生语言名。
  - [Source: docs/front-end-spec.md §11 — "D-2: 无国旗图标 — 中性、不引政治情绪"]
- **TS-CONS-007 [shadcn-ui copy not install]**: 本 Story 仅落地 2 个 primitives（button + dropdown-menu）；后续 Story 按需 copy 新 primitives；**禁止** 引入 `shadcn-ui` npm 包作为 runtime 依赖。
  - [Source: docs/front-end-spec.md §1.4 — "shadcn-ui（基于 Radix UI 的 headless 组件，可定制）"]
- **TS-CONS-008 [SSG 优先]**: marketing route group `(marketing)` 必须启用 `generateStaticParams` 预生成 10 locale × 路由组合；console route group `(console)` 占位 layout 默认 `force-dynamic = false`（本 Story 不强制；待 Architect Q1 仲裁）。
  - [Source: docs/front-end-spec.md §13.2 — "SSR/SSG/CSR 在哪些页面采用（推荐：Landing/Docs 用 SSG，Console 用 CSR + 服务端 API）"]
- **TS-CONS-009 [性能预算]**: 首屏 `/[locale]/` First Load JS gzip < **250KB**；LCP < **2.5s** (3G fast 模拟)；CLS < **0.1**；INP < **200ms**。CI 仅 gate bundle size；其他指标 QA Comprehensive test design 阶段在 Lighthouse 中校核。
  - [Source: docs/front-end-spec.md §9.2 — 性能预算表]
- **TS-CONS-010 [a11y AA 基线]**: 所有交互元素 Tab 可达；focus ring 2px solid indigo-500；color contrast ≥ 4.5:1 (text) / 3:1 (large text)；live region `aria-live="polite"`（toast）。
  - [Source: docs/front-end-spec.md §7.1 — WCAG 2.1 AA 目标]

  - [Source: docs/architecture/coding-standards.md §12.2 — "strict mode TS"]
