### AC2: 与 OpenAI 官方 Python SDK 接口一致——改 import 即 drop-in 迁移

**Scenario**
```gherkin
GIVEN 一个原本用官方 `openai` SDK 调 OpenAI 的脚本：`from openai import OpenAI; client = OpenAI()`
WHEN 开发者改为 `from he_api import Client; client = Client()`（导出名以 OQ-10.2-4 裁定为准），且设置 `HE_API_KEY`
THEN 客户端默认把请求发往 He-API 网关（默认 `base_url` 指向 He-API，OQ-10.2-3；可被构造参数 / `HE_API_BASE_URL` 覆盖），凭据取自 `HE_API_KEY`（而非 `OPENAI_API_KEY`）
  AND `client.chat.completions.create(...)`（非流 + `stream=True` 迭代 + `stream_options.include_usage` 尾包）、`client.embeddings.create(...)`、`client.models.list()` 等调用面与 OpenAI SDK **签名/返回类型一致**（响应是 OpenAI 同型对象——chat.completion / chat.completion.chunk / 含 usage 加和不变式）
  AND 同步客户端有对应的 **async** 客户端（对位 `openai.AsyncOpenAI`）
  AND 错误以 OpenAI SDK 的异常体系抛出（`BadRequestError` / `AuthenticationError` / `RateLimitError` …），且 He-API 自定义错误码（`error.code` 如 `400_invalid_request`、`402_quota_exhausted`）与 `he_request_id` 可被读取
  AND He-API 扩展（路由策略 `X-He-Routing-Strategy`、A/B `X-He-AB-Models`、响应头 `X-He-Request-Id`/`X-He-Selected-Model`/`X-He-Cost-Usd`、自定义端点 `/v1/balance`·`/v1/usage`）通过 SDK 可达——**MVP 扩展面的取舍由 OQ-10.2-4 钉死**
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-10.2.6 | **「接口一致」= 继承而非追赶（SM 强烈倾向，待 OQ-10.2-1 裁定）**：`he_api.Client` 应**继承/组合官方 `openai.OpenAI`**——drop-in 等价性、SSE 流式、pydantic 响应模型、重试/超时全部**继承**自 `openai` SDK，而非重写一套 httpx 客户端去逐一追平（重写会把「接口一致」变成永无止境的手工追赶，违反 KISS 与本 Story DoD）。同理 async = 继承 `openai.AsyncOpenAI`。 |
| BR-10.2.7 | **默认 base_url + 凭据来源**：构造时若未显式传 `base_url`，默认指向 He-API 网关（具体生产域名 OQ-10.2-3；`/v1` 后缀遵循 openai SDK「base_url 后接路径」约定）；可经构造参数或 `HE_API_BASE_URL` 覆盖。凭据：未显式传 `api_key` 时读 `HE_API_KEY` 环境变量（**不读** `OPENAI_API_KEY`，避免与真 OpenAI 凭据串台）。 |
| BR-10.2.8 | **OpenAI 类型/异常透传**：SDK 应 re-export（或继承暴露）OpenAI 的请求/响应类型与异常类，使既有以 `openai` 类型注解/`except openai.X` 编写的代码改 import 后仍编译/运行。He-API 错误信封（5 字段 `code/message/type/param/he_request_id`，rest-api-spec §5.1.2）经 openai 异常的 `.code` / `.request_id` / body 可读。 |
| BR-10.2.9 | **`openai` 依赖 pin 策略 + drop-in 漂移防护**：`requirements.txt` 注记 openai SDK「12 个月内两次破坏性响应解析变更」并把网关合约测试 pin 在 `openai==1.40.*`。本 SDK 的 `openai` 依赖 pin 区间（兼容上限 vs 紧 pin）+ 升级流程 = OQ-10.2-1 的子项；须有测试在 pin 漂移/上游破坏时**早失败**。 |
| BR-10.2.10 | **He 扩展呈现（MVP 面待 OQ-10.2-4 钉死）**：路由策略 / A/B 经 `extra_headers`（openai SDK 原生支持 per-request header）或便捷参数；He 响应头经 `.with_raw_response` 读取（既有合约测试已用此法读 `x-he-selected-model`/`x-he-request-id`/`x-he-cost-usd`）；`/v1/balance`·`/v1/usage` 这类非-OpenAI 端点经 openai SDK 的 `client.get(...)`/`.request(...)` escape-hatch 或薄便捷方法。**不**修改网关/proto/DB——纯消费侧。 |
| BR-10.2.11 | **多模态/音频自动继承**：视觉（9.5 多模态 content 入参）、ASR（9.6 `/v1/audio/transcriptions`）、TTS（9.7 `/v1/audio/speech`）因网关 OpenAI 兼容 + SDK 继承 `openai`，**无需额外代码**即随 `client.audio.*` / 多模态 messages 可用；本 Story 仅需文档/冒烟覆盖确认，不为其新增实现（cut-line 归 OQ-10.2-4）。 |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| `api_key`（构造） | string | 否（回落 env） | 显式 > `HE_API_KEY` env；二者皆缺 → 沿用 openai SDK 的缺 key 行为（构造期或首调时报错） | openai SDK 原生 key-missing 错误 |
| `base_url`（构造） | string | 否 | 显式 > `HE_API_BASE_URL` env > He-API 默认（OQ-10.2-3） | — |
| `extra_headers`（路由/AB） | dict | 否 | `X-He-Routing-Strategy ∈ {quality,cost,latency}`；`X-He-AB-Models` = 2 个不同具体 id（网关侧已校验，SDK 不重复实现校验逻辑） | 由网关返回 `400_invalid_request`，经 openai 异常透出 |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| 网关返回 He 自定义错误码（如 `402_quota_exhausted`） | 402 | OpenAI 异常体系（`.code` 可读、`he_request_id` 可读） | SDK 透传，不吞码——测试断言 `.code`/`request_id` 可取 |
| 未知 model id | 400 | `BadRequestError`，`.code == "400_invalid_request"` | 与既有 `openai_sdk_*_contract_test.py` 行为一致 |
| 上游 5xx / 超时 | 502/504 | openai 异常（`APIStatusError` 子类） | 透传 |

**Examples**
- Input: `from he_api import Client; c = Client(); c.chat.completions.create(model="qwen-max", messages=[{"role":"user","content":"Hi"}])` → Expected: 返回 OpenAI 同型 `chat.completion`，请求落在 He-API 网关。
- Input: `c.chat.completions.create(model="he-router-cost", messages=[...], extra_headers={"X-He-Routing-Strategy":"cost"})` → Expected: 网关按成本路由，响应头 `X-He-Selected-Model` 可经 `.with_raw_response` 读到。
- Input: `import asyncio; from he_api import AsyncClient` → Expected: async 客户端对位 `openai.AsyncOpenAI` 可用。
- Input: drop-in 等价性：把任一既有 `apps/api-gateway/tests/openai_sdk_*_test.py` 的 `OpenAI(base_url=..., api_key=...)` 换成 `he_api.Client()`（默认 base_url 指网关）→ Expected: 合约断言全过（同型响应、同型流、同型错误码）。

## Dev Notes

> **核心原则**：He-API 网关**已是 OpenAI 线协议兼容**，且仓库现有 Python 合约测试就是用官方 `openai` SDK 直驱网关。本 Story 的「接口一致」应靠**包装/继承官方 `openai` SDK**实现（继承等价性），而非重写 HTTP 客户端去追平。Dev 不应需要读架构文档即可实现——关键事实已抄录于下。

### Technical Constraints
- **网关已 OpenAI 兼容（drop-in 的前提，已核验）**：`POST /v1/chat/completions`（非流 + SSE，`data: <json>\n\n` 帧 + `data: [DONE]\n\n` 终止符）、`POST /v1/embeddings`、`POST /v1/audio/transcriptions`（Whisper 兼容，9.6）、`POST /v1/audio/speech`（TTS，9.7）、多模态 content 入参（9.5）、`GET /v1/models`（每条 entry 末尾追加 `capabilities` 7 字段）、错误信封（OpenAI 5 字段形 + 末位 `he_request_id`）。[→ docs/architecture/rest-api-spec.md#511-对外-apiopenai-兼容]
- **PRD 产品原则**：「客户改 `base_url` 即可零代码迁移（验证：OpenAI Python SDK 可调通）」。[→ docs/prd/epics.md:53] + FR-11.1「至少 3 个官方 SDK（Python/Node/Go），每个与 OpenAI 官方 SDK 接口一致（drop-in）」[→ docs/prd/requirements.md:99]
- **既有 Python 合约测试 = drop-in 的 oracle**：`apps/api-gateway/tests/openai_sdk_*_test.py`（25+ 文件）用 `OpenAI(base_url=os.environ["HE_API_TEST_GATEWAY_URL"].rstrip("/")+"/v1", api_key=...)` 直驱网关；形状断言集中在 `apps/api-gateway/tests/_protocol_invariants.py`（`REQUEST_ID_RE=^req_[0-9a-f]{12}$`、`assert_chat_completion_shape`、`assert_chat_completion_chunk_shape`、`assert_embedding_shape`、`assert_error_envelope_shape`、`assert_model_entry_shape`）。共享 fixtures 在 `conftest.py`（`gateway_url` / `openai_client` / `httpx_client` / skip-if-unset）。**复用其形状断言做 drop-in 等价性测试。**
- **He 响应头读法（既有范式）**：`raw = client.chat.completions.with_raw_response.create(...)`；`raw.headers.get("x-he-selected-model")` / `x-he-request-id` / `x-he-cost-usd`（注：OQ5——`x-he-cost-usd` 在网关侧**故意缺省**，合约测试断言其 `is None`；[[project_cost_source_oq5_usage_ledger]]）。
- **openai SDK pin 教训**：`apps/api-gateway/tests/requirements.txt` 注明 openai SDK「12 个月内两次破坏性响应解析变更」，故网关合约 pin `openai==1.40.*`（hermetic）。本 SDK 选 pin 区间须权衡 drop-in 现代性 vs 破坏性漂移——OQ-10.2-1 子项；务必有「pin 漂移早失败」的守卫测试。
- **Python 工具链现状**：仓库已有 Python 测试（CI `setup-python@v5` `python-version: '3.12'`，`pip install -r .../requirements.txt`），但**无 ruff/black/setup.cfg/tox**，**无可发布 Python 包**（首例）。无 monorepo 私有打包插件——用标准 PEP 517/621。[→ docs/architecture/tech-stack.md:44]
- **monolith 仓库约定**：`pnpm-workspace.yaml` 仅纳 JS/TS 包；Python 包不入 pnpm graph，独立 `pyproject.toml` 自治。turbo/pnpm 不驱动 Python 构建——CI 用专属 `sdk-python` lane。
