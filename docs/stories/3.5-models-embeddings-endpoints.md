### AC1: GET /v1/models — Static Catalogue in OpenAI ModelList Shape

**Scenario**
```gherkin
GIVEN the api-gateway is built with Story 3.5 wired and Story 3.2's bearer-auth middleware in place
AND a valid `he_api.api_keys` row issued via Story-3.2 `IssueKeyForTest` (plaintext key exported as `HE_API_TEST_API_KEY` — the Story-3.3 BR-3.1 env-var convention)
AND the `openai` Python SDK installed at the Story-3.3-pinned version `openai==1.40.*` (BR-3.2 inheritance — there is NO new pin)
WHEN the test issues a `GET /v1/models` request with header `Authorization: Bearer ${HE_API_TEST_API_KEY}` (no request body)
THEN
  - the response status is 200 OK
  - the response `Content-Type` is `application/json; charset=utf-8` (matches the Story-3.3 `writeChatJSON` discipline)
  - the response body parses as JSON matching the OpenAI ModelList shape: `{"object": "list", "data": [{"id": <string>, "object": "model", "created": <int>, "owned_by": <string>}, ...]}`
  - the SDK call `client.models.list()` returns without raising `openai.APIError` (proving Pydantic-strict shape conformance — same end-to-end guarantee Story 3.3 AC3 established for chat-completions)
  - the SDK iterator yields ≥ 9 `Model` objects (the BR-1.4 canonical catalogue: 6 vendor models + 3 router pseudo-models — exact list in BR-1.4 below)
  - every entry's `object` field equals the literal string `"model"` (NOT `"models"`, NOT empty)
  - every entry's `id` is non-empty and matches `^[a-z0-9][a-z0-9.\-]*$` (lowercase ASCII + digits + `.` + `-` — covers `qwen-max`, `deepseek-v3`, `moonshot-v1-128k`, `glm-4`, `doubao-pro`, `ernie-4.0`, `he-router-cost`, `he-router-quality`, `he-router-latency`)
  - every entry's `created` is a positive integer (Unix seconds; the static catalogue uses the api-gateway process startup timestamp captured ONCE at handler construction — BR-1.6)
  - every entry's `owned_by` is one of: `alibaba` / `deepseek` / `moonshot` / `zhipu` / `bytedance` / `baidu` / `he-api` (the seven canonical owners per BR-1.5)
WHEN the test issues `GET /v1/models` WITHOUT the `Authorization` header (or with `Authorization: Bearer invalid-key`)
THEN
  - the response status is 401 Unauthorized (Story 3.2 BR-2.4 — single 401 envelope for `NOT_FOUND` and `REVOKED` parity)
  - the response body matches the §5.1.2 envelope: `{"error":{"code":"401_invalid_api_key", "message": <string>, "type": "invalid_request_error", "param": null, "he_request_id": null}}`
  - the SDK call raises `openai.AuthenticationError` (Pydantic-strict mapping of 401 → AuthenticationError per OpenAI SDK)
WHEN the test issues `POST /v1/models` (wrong method) with a valid bearer token
THEN
  - the response status is 405 Method Not Allowed (Go 1.22 `http.ServeMux` "POST /v1/models" pattern — the absence of a POST pattern for `/v1/models` makes 405 the stdlib's default; verified by Story 2.2 AC1 BR-1.1 precedent)
  - the response carries `Allow: GET` header (Go 1.22 stdlib behaviour)
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-1.1 | The `/v1/models` route MUST be registered via `mux.Handle("GET /v1/models", bearerAuth.RequireAPIKey(modelsHandler))` in `apps/api-gateway/cmd/server/main.go` — placed in the same `/v1/*` registration block as the Story 3.3 `mux.Handle("POST /v1/chat/completions", bearerAuth.RequireAPIKey(chatCompletions))` line (immediately following it). The per-route wrapping is mandatory per Story 3.2 BR-1.4 ("Concrete implementation: per-route `mux.Handle(...)` — NOT global wrapping of the whole mux"). The Go 1.22 method-prefixed pattern `"GET /v1/models"` is required so a bare `POST /v1/models` cleanly falls through to 405 without invoking the bearer-auth chain (the auth middleware MUST NOT see method-violation traffic). |
| BR-1.2 | The handler MUST be a method on a dedicated `ModelsHandler` struct, constructed via `handlers.NewModelsHandler(logger *slog.Logger, opts ...ModelsHandlerOption)` — mirroring the Story-3.3 `NewChatCompletionsHandler` constructor signature (`logger` first, variadic options second). The constructor MUST accept a `WithNow(f func() time.Time)` option (mirroring Story 3.4's `handlers.WithNow` introduced for SSE TTFB tests) so AC1's `created` timestamps are deterministic under test. Per Architect Round 1 OQ4 ruling on Story 3.3, this option-function pattern is the project's ratified injection pattern (alternative — package-mutable `var ModelsCreated time.Time` — is REJECTED for parallel-test brittleness; precedent `NewAPIKeyAuthenticator` at `apps/api-gateway/internal/middleware/bearer_auth.go:204`). |
| BR-1.3 | The response MUST be emitted via the SHARED helpers `writeChatJSON(w, http.StatusOK, body)` and `writeChatError(w, status, code, message, param)` introduced in Story 3.3 (`apps/api-gateway/internal/handlers/chat_completions.go:335-366`). NO new envelope writer is introduced. | BR-1.5 | The `owned_by` field is a closed-set string mapping to the vendor's slug per `docs/architecture/data-models.md` §4.1 `models.vendor` column (`-- alibaba / deepseek / moonshot / zhipu / bytedance / baidu`). | BR-1.9 | The handler is stateless beyond `h.startedAt` + `h.logger`. No upstream gRPC call is made (the auth-svc `ValidateApiKey` round trip is already done by `bearerAuth.RequireAPIKey` — `/v1/models` does NOT independently re-call auth-svc).
