| A/B 用 `stream=true` | `400_invalid_request` | A/B 非流式 only（6.4 Q-B） | 前端禁用「A/B + 流式」组合 |
| A/B leg 越 scope | `403_model_not_in_scope` | leg 不在 Key scope | 提示选 scope 内模型（6.4 Q-K） |
| A/B 部分失败 | `200` + 失败 leg marker | 一 leg `finish_reason:"he_upstream_error"`+`x_he_error` | 渲染成功 leg + 标注失败 leg（6.4 Q-E） |
| 上游 429 / 余额不足 | `429_*` / `402_*` | 限流 / 余额不足 | 透传网关 envelope 文案，不吞错 |
| SSE 流中断 | （client） | 流式中断 | 优雅收尾 + 可重试（不留半截不可读 UI） |

- **✅ Playground 计费调用鉴权（OQ-10.6-1 裁定 (b)，security-sensitive）**：新增 **`POST /v1/me/playground/chat`**（`rest-api-spec.md §5.1.3` additive，挂既有 `/v1/me/*` JWT-cookie 中间件 [→ rest-api-spec.md:202-205]）。**身份** = JWT-cookie `sub` only（per-user IDOR fence 同 9.1/9.2/9.3），**浏览器绝不持明文 Key**（避开 FR-5.2 落差 + XSS 外泄；`me-keys.ts` 明文从不留存，`PLAINTEXT_RE=/^he-[0-9A-Za-z]{41,43}$/` 仅创建时一次 [→ apps/console/lib/api/me-keys.ts:66-90]）。**计费/scope/限流归属** = 请求体携带**已拥有的 `api_key_id`（UUID，console me-keys 已可列、非明文）**→ 网关校验 ownership（`WHERE user_id=$JWT.sub`）→ 解析为既有 per-key policy → 走**同一内部 chat 管线**（routing 6.2 / adapters / content-safety 8.2-8.3 / `TPMDeduct` / `scope.models` / QPS-RPM-TPM 5.3）——复用全部 per-key 机制，**不新造 per-user 计费路径**。A/B 经同端点（honor `X-He-AB-Models`）；流式 = SSE passthrough 同 §5.1.1；错误复用既有 envelope 码；`Cache-Control: no-store`；**无新 proto / 无 gRPC RPC / 无 migration**（内部转发既有 chat dispatch）。新增 API 资源 + auth 路径 → 入 cumulative-context + §5.1.3（T5.4）。[→ docs/architecture/rest-api-spec.md:8-9 §5.1.1]
- **A/B 契约已接线（Story 6.4，REUSE 不改）**：`X-He-AB-Models: modelA,modelB` 请求头 → 双模型**并行**、返回 ONE `chat.completion`（`choices[]` = leg A 然后 leg B，各带 `x_he_model`，`usage` 累加）；新响应头 `X-He-AB-Models: served-ids`；**`X-He-Selected-Model` 在 A/B 路径不设**；须**恰 2 个不同具体 id**（count≠2 / 重复 / `he-router-*` / unknown → `400_invalid_request`）；**非流式 only**（`stream=true`+头 → 400 before dispatch）；**双计费**（`TPMDeduct == legA.total + legB.total`）；两 leg 须过 Key `scope.models`（越权 → 整请求 `403_model_not_in_scope`）；部分失败 → 200 + 失败 leg marker（`finish_reason:"he_upstream_error"` + `x_he_error` envelope）[→ docs/architecture/rest-api-spec.md:316]。
