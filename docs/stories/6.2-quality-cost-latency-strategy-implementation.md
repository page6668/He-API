### Architect Open Questions (gathered for Architect Round 1)

> SM defaults are stated; the Architect rules IN/DEFER/OVERRULE. **Q-A is the headline fork.**

- **Q-A — Scope of "real" for quality + latency (cross-store data availability)** ⚠️ HEADLINE. The 3 strategies read 3 different stores per [Source: data-models.md#4.1-4.2]: **cost → `model_pricing` (PostgreSQL, seedable now)**; **quality → `benchmark_results` (ClickHouse)**; **latency → `request_logs_hourly_agg` (ClickHouse materialized view)**. Reality check: (i) NO Go service imports a ClickHouse client today (only pgx exists); (ii) the ClickHouse tables are NOT created (`migrations/clickhouse/` holds only `001_baseline`); (iii) `request_logs` (the source of the latency MV) has **no writer until Epic 9** (observability) — and Epic 6's `prerequisite_epics: [3,4]` does **not** include Epic 9, so 6.2 cannot assume that data exists. **SM default = Option A**: 6.2 lands (1) the full gateway↔routing-svc integration + observable decision header (the headline AC); (2) **cost strategy REAL** (model_pricing PG + `0007` migration); (3) quality + latency as **real strategy structures behind a `Scorer` seam that gracefully degrades to a deterministic fallback** (cost ordering, then first-alphabetical) when its backing store is empty/absent — `strategy_used` is echoed truthfully and slog carries `score_source=clickhouse|fallback`. The "real" ClickHouse binding for quality/latency becomes a thin follow-up once Epic 9 populates `request_logs` + a `benchmark_results` seed lands. **Architect alternatives**: (B) bring a ClickHouse client + `002_routing_olap` ClickHouse migration + a `benchmark_results` seed INTO 6.2 (quality goes real now; latency still data-starved until Epic 9) — heavier, couples 6.2 to a new infra dependency; (C) split Story 6.2 into 6.2a (integration + cost real) and 6.2b (quality/latency ClickHouse, Epic-9-gated) — cleanest separation but renumbers 6.3/6.4/6.5; (D) re-home quality/latency signals to PG columns on `models` (e.g. `quality_tier`, `baseline_latency_ms`) to avoid ClickHouse entirely in Epic 6 — contradicts data-models.md §4.2 and needs a doc change.

- **Q-B — request_logs (ClickHouse) routing-decision write**: the `request_logs` columns `routing_strategy` + `selected_by_strategy` pre-exist [Source: data-models.md#4.2:156-157]. SM default = **defer the ClickHouse write to Epic 9** (the request_logs ingestion pipeline is Epic-9 scope); 6.2 makes the decision observable via **slog** (`{strategy, selected_model, requested_model, he_request_id}`) + a **Prometheus counter** `he_routing_decisions_total{strategy,selected_model,score_source}` only. - **Q-C — `he_api.models` + `model_pricing` PG migration** (carried from Story 6.1 Q-C): SM default = **land `migrations/postgres/0007_create_models_and_pricing.sql` here** (both tables pre-defined at [Source: data-models.md#4.1:101-119]) + a pricing seed for the 8 concrete catalogue models, REVERSIBLE + NON-DESTRUCTIVE (the Story-6.1 Architect Q-C condition). SM default = **all `status='active'` models in the boot catalogue** (the `he-router-*` virtual meta-models are EXCLUDED from candidacy — they are routing directives, not routable targets). Architect alternative: restrict candidacy to a curated `routable=true` subset (needs a catalogue/`models` column).

SM default = apply `context.WithTimeout(ctx, 100ms)` at the gateway routingclient call site; routing-svc loads `model_pricing` into a **boot snapshot + periodic refresh every 60s** (stale pricing → slightly-suboptimal routing, never a wrong charge — billing reads pricing independently). ### AC1: Gateway resolves the routing decision and surfaces it on `X-He-Selected-Model` (headline — `决策结果可观测`)

**Scenario**
```gherkin
GIVEN an authenticated POST /v1/chat/completions request
  AND the gateway is wired to routing-svc via a NEW routingclient (Connect-RPC, 100ms deadline)
WHEN the gateway processes the request (stream=false AND stream=true paths)
THEN
- the gateway derives the strategy with precedence: a he-router-{quality,cost,latency} meta-model in the `model` field WINS, else the X-He-Routing-Strategy header, else STRATEGY_DEFAULT (Q-I)
- the gateway calls routing-svc SelectModel{user_id, requested_model, strategy, he_request_id} within context.WithTimeout(100ms) (Q-E)
- the gateway dispatches the adapter via the EXISTING adapterclient.Registry.Resolve(selected_model) using the routing-svc–RETURNED selected_model (NOT req.Model verbatim)
- the response carries X-He-Selected-Model = selected_model (the actual routed model) on every success path — mock, adapter non-stream, adapter stream (Q-L); §5.1.1 "always present"
- a concrete `model` with NO strategy header routes through STRATEGY_DEFAULT and selected_model == req.Model (byte-for-byte today's behaviour — zero regression for the 6-vendor adapter matrix)
- the routing decision is echoed to slog {strategy, requested_model, selected_model, score_source, he_request_id} (non-PII; NEVER user_id) and increments he_routing_decisions_total{strategy,selected_model,score_source} (Q-B, Q-M)
- `score_source` is read from the routing-svc response field `SelectModelResponse.score_source` (additive field 6 — Round-1 High ruling); the gateway never infers it locally (it is a routing-svc-internal fact)
```

**Key implementation decisions (deviations / environment notes):**

1. **Proto regen by hand-edit (env limitation).** `buf` / `protoc` are not installed and large Go binaries built by `go install` on this macOS lack `LC_UUID` (dyld refuses them), so `buf generate` could not run. Verified by a proto round-trip test (descriptor parses at init, field number 6, json `scoreSource`). `buf breaking:FILE` passes by construction (purely additive; fields 1–5 unchanged — identical to the 4/5 precedent). **QA: re-run `buf generate` + `buf breaking` in CI to confirm.**
2. **`SourcedStrategy` optional capability** — to surface per-request `score_source` (quality/latency degradation is per-request) WITHOUT changing the cascade-locked `Strategy.Select` signature (REUSED verbatim per Dev Notes). `Engine.Decide` prefers it; plain strategies report `default`. 6.3/6.4 strategies need only satisfy `Strategy`.
3. **pgx, not otelpgx.** The story mentioned "pgx/otelpgx" but no `otelpgx` exists anywhere in the repo; the real precedent ("mirror auth-svc pgx setup") uses plain `pgxpool`. Followed the actual precedent (KISS, no new uncached dep).
4. **Resilient pricing wiring (BLIND-ERROR-003).** routing-svc boots + serves even when PG is unset/unreachable (cost degrades to first-alphabetical; 60s refresh recovers). Helm `db.enabled` / gateway `routing.endpoint` default OFF so existing deployments are unaffected until explicitly wired.

6. **Docker not running** → testcontainer integration scenarios (6.2-INT-005..014) are authored at unit level with fakes/pgxmock; the over-the-wire proof (`routingclient/client_test.go` httptest) runs without docker. Full testcontainer E2E to be exercised in CI.
